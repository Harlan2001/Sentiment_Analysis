# 数据可视化看板——流量管理功能

**yunjie.xiang | 2026-07-24**

---

## 一、背景与目标

在前期数据看板（新闻、因子、分析、预测等模块）已上线的基础上，本周重点交付了**大模型流量管理**功能。核心诉求是：系统内所有大模型调用（Agent 聊天、新闻分析、AI 策略推荐、策略变动）的 Token 消耗不可见、不可管，领导无法掌握全公司/本部门 AI 资源使用情况，员工也看不到自己的消耗数据。

本次交付围绕三个角色（admin / manager / user），从**系统主动监控**和**用户自助查看**两个维度，建成了一套完整的 Token 流量可视化与权限管控体系。

---

## 二、整体架构

### 2.1 数据层——全链路 Token 采集

新增 `llm_usage_log` 表，统一记录每一次大模型调用的 Token 消耗。四个调用点全部接入：

| 调用来源 | 归属 | 调用方 | 记录方式 |
|---------|------|--------|---------|
| Agent 聊天 | 个人 Token | `chat.py` | 按实际登录用户记录 |
| 新闻分析 | 系统 Token | `generate_report.py` | user_id=0, username="system" |
| AI 策略推荐 | 系统 Token | `strategy_recommendation.py` | 同上 |
| AI 策略变动 | 系统 Token | `change_service.py` | 同上 |

封装了 `TokenLogger` 上下文管理器（`backend/common/llm_logger.py`），支持自动计时、成功/失败分别记录、建表幂等，对业务代码零侵入。

### 2.2 权限模型

三个角色、五种视图，权限矩阵如下：

```
DashboardPage
├── 系统监控
│   ├── 数据看板          [admin + manager]
│   └── Token监控(总览)   [admin only]
├── 用户管理              [admin only]
│   ├── 行为总览
│   ├── 用户画像
│   └── Token消耗（全部用户）
├── 部门概览              [manager only]
│   └── 行为数据 + Token数据（仅本部门）
└── 我的使用              [所有用户]
    └── 仅显示个人 Agent Token 消耗
```

后端通过 `admin_check()` 和 `manager_check()` 两个 FastAPI 依赖实现权限拦截。`manager_check` 对 manager 自动注入部门+公司过滤条件，确保 manager 只能看到本部门数据；admin 传空值，查询全量。

## 三、主要功能模块

### 3.1 系统监控 > Token 监控（admin only）

展示**系统全部大模型调用**的 Token 消耗总览，包括新闻分析、策略生成、策略变动、Agent 聊天四类。

- 4 张概览卡片：今日 Token、本月 Token、今日调用次数（含失败次数）、今日活跃用户
- 按调用来源分布（进度条 + 调用次数）
- 按模型分布（豆包 / DeepSeek / Qwen，百分比）
- 7 天 / 30 天 Token 消耗趋势柱状图

### 3.2 用户管理 > Token 消耗（admin only）

admin 查看**全员 Agent Token 使用情况**：

- 顶部复用系统 Token 概览卡片，提供全局上下文
- 今日 Token 按来源分布（标签式展示）
- Token 趋势 + 模型分布双图
- 用户明细表：支持按用户名搜索、按今日/本月/累计 Token、调用次数、活跃天数排序，50 条/页分页。展示用户名、各维度 Token、角色、部门、最后活跃时间

### 3.3 部门概览（manager only）

manager 登录后默认进入"部门概览"Tab，**不含用户画像**，将行为数据与 Token 数据合并展示：

- 全局汇总：总用户数、今日活跃、Token 消耗、重度用户、流失风险
- 部门行为图表：活跃趋势、时段热力矩阵、页面访问分布、页面停留时长
- Token 趋势 + 模型分布
- 部门 Top 20 用户 Token 排行表

### 3.4 我的使用（所有用户）

每个登录用户可见，**仅显示自己的 Agent 对话 Token 消耗**（系统级的三类调用不纳入个人统计）：

- 5 张个人汇总卡片：今日/本月/累计 Token、今日/累计调用次数
- Token 消耗趋势（7 天 / 30 天柱状图）
- 功能使用分布（30 天各页面访问占比）
- 模型使用偏好（仅统计 chat 来源的模型分布）
- 活跃时段分布（24 小时柱状图）

## 四、技术要点

| 层面 | 要点 |
|------|------|
| **数据库** | `llm_usage_log` 表，含 `call_source` 区分来源、`user_id=0` 标记系统调用；users 表扩展 role / department / company 字段 |
| **后端权限** | `admin_check` 返回 bool；`manager_check` 返回 `{department, company}`，自动注入 SQL 过滤条件 |
| **JWT** | 增加 `role` 字段，登录/状态接口同步返回，前端 AuthContext 全局消费 |
| **前端** | DashboardPage 根据 `isAdmin` / `role === 'manager'` 条件渲染 Tab；TokenOverviewPanel / UserTokenPanel / DeptOverviewPanel / MyUsagePage 四个独立组件，各自拉取对应 API |
| **安全性** | 后端每个 API 均通过 FastAPI Depends 做权限校验，前端仅做 UI 隐藏，不可绕过 |

## 五、交付成果总结

1. **全链路 Token 可见**：四个 LLM 调用点全部接入日志，系统 Token 与个人 Token 清晰分离
2. **三级权限管控**：admin 全量、manager 本部门、user 仅自己，后端强校验
3. **四个可视化面板**：Token 总览、用户 Token 管理、部门概览、我的使用，覆盖所有角色的管理/自查需求
4. **行为+Token 联动**：部门概览将行为数据与 Token 数据合并，为管理者提供一站式视图
5. **即插即用**：`llm_usage_log` 表自动建表，`TokenLogger` 上下文管理器一行代码接入，未来新增 LLM 调用点零成本扩展
