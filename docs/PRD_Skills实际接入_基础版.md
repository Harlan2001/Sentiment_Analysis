# PRD：Skills 实际接入（基础版）

> 文档状态：已实现，待测试数据库与真实模型环境验收
> 适用项目：Sentiment Analysis / BondSense 工作台
> 文档版本：v0.1
> 编写日期：2026-09-08
> 范围说明：本文只定义 Skills，不包含项目制、MCP、自定义记忆、工作流、投资组合等模块

## 1. 背景

当前项目已经具备个人 Skill 的数据库表、基础接口、编辑页面、对话选择入口、模型指令注入和消息使用记录，但系统 Skill 仍来自前端固定数据，系统 Skill 的“启用”实际会创建一条同名个人 Skill；输出格式尚未进入模型上下文；附件数量限制、永久删除清理和专项测试也未形成完整闭环。

本期目标是在保留现有页面结构的基础上，把 Skills 从“可演示”完善为“可真实使用、可校验、可追溯失败”的基础功能。

## 2. 产品目标

用户应能够完成以下两条真实链路：

1. **系统 Skill 链路**：查看系统 Skill → 启用 → 在对话中选择 → 模型按照 Skill 回答 → 停用后不可再用于新消息。
2. **个人 Skill 链路**：创建个人 Skill → 发布 → 在对话中选择 → 模型按照 Skill 回答 → 会话刷新后仍能看到使用记录。

页面上的成功状态必须来自后端真实结果。接口、上传或模型调用失败时，不允许展示模拟成功，也不允许静默退回为普通回答。

## 3. 非目标

本期不开发：

- 附件内容解析和模型上下文注入；
- 用户上传脚本的执行；
- Skill 分享、共同编辑和跨用户复制；
- Skill 版本对比、回滚页面和完整运行审计；
- 自动从对话生成 Skill；
- 自定义输入表单执行引擎；
- 多个 Skill 的复杂编排、优先级拖拽和自动冲突消解；
- 管理后台中的系统 Skill 在线编辑器。

## 4. 名词与状态

### 4.1 Skill 类型

| 类型 | 定义 | 普通用户权限 |
| --- | --- | --- |
| 系统 Skill | 平台维护、所有用户可查看的标准能力 | 只读；只能启用或停用 |
| 个人 Skill | 当前用户创建的能力 | 仅创建者可查看、修改、发布、停用和删除 |

### 4.2 个人 Skill 状态

| 产品名称 | 数据库存储值 | 是否可编辑 | 是否可用于新消息 |
| --- | --- | --- | --- |
| 草稿 | `draft` | 是 | 否 |
| 已发布 | `published` | 是 | 是 |
| 已停用 | `archived` | 是 | 否 |

本期沿用数据库中的 `archived` 表示“已停用”，页面不使用“已归档”这一产品名称。永久删除前必须先停用。

### 4.3 系统 Skill 状态

系统 Skill 同样使用 `draft`、`published`、`archived`。只有平台状态为 `published` 的系统 Skill 才能被用户启用和调用。平台将系统 Skill 停用后，已有用户启用关系可以保留，但该 Skill 不再出现在对话可选列表，也不能用于新消息。

## 5. 当前实现基线

### 5.1 已有真实能力

- `workbench_skills` 保存系统/个人类型、名称、使用场景、分析指令、输出格式、状态和版本号；
- `workbench_skill_versions` 保存个人 Skill 的版本快照；
- 个人 Skill 已有创建、读取、修改、发布、停用和永久删除基础接口；
- 用户只能管理自己的个人 Skill；
- 对话请求支持最多 5 个 `skill_ids`，并拒绝重复 ID；
- 后端会在发送前重新检查个人 Skill 的所有者和发布状态；
- 已选 Skill 的名称与分析指令已能进入模型调用链路；
- `workbench_message_skills` 会保存助手消息使用过的 Skill 名称；
- Skill 附件可以上传到后端磁盘并保存数据库记录。

### 5.2 本期需要替换或补齐的能力

- 系统 Skill 列表由前端常量改为后端数据；
- “添加系统 Skill”由创建个人副本改为保存用户启用关系；
- 对话可选列表合并“已启用且已发布的系统 Skill”和“当前用户已发布的个人 Skill”；
- 输出格式进入本次模型上下文；
- 用户自定义指令不再被提升为平台系统指令；
- 附件数量在后端强制限制，删除时同步处理数据库与磁盘；
- 前端完整显示加载、保存、上传、删除和调用失败；
- 增加 Skills 专项后端、前端和模型上下文测试。

## 6. 用户流程

### 6.1 系统 Skill

1. 用户进入 Skills 页面，默认打开“系统”页签。
2. 前端从后端读取已发布的系统 Skill，并显示当前用户是否已启用。
3. 用户点击“启用”，后端保存当前用户与系统 Skill 的启用关系。
4. 启用成功后，该 Skill 出现在当前用户的对话 Skill 选择器中。
5. 用户点击“停用”，后端删除或关闭该启用关系；该 Skill 立即从新消息的可选列表消失。
6. 普通用户不能编辑、上传附件到、停用平台状态或删除系统 Skill。

### 6.2 个人 Skill

1. 用户进入“我的”页签，创建 Skill。
2. 用户填写名称、使用场景、分析指令和输出格式，可选择保存为草稿或直接发布。
3. 用户可以上传附件；附件只保存，不参与 AI 回答，也不会执行。
4. 已发布 Skill 出现在对话选择器中；草稿和已停用 Skill不出现。
5. 修改个人 Skill 后版本号递增；停用和重新启用也记录为新版本。
6. 用户永久删除 Skill 前必须先停用并二次确认。

### 6.3 对话调用

1. 对话选择器展示当前用户可调用的系统和个人 Skill。
2. 单条消息最多选择 5 个，不允许重复。
3. 用户发送消息后，后端重新校验每个 Skill 的类型、状态、所有权或启用关系。
4. 任意一个 Skill 无效时，本次消息整体拒绝，不创建普通回答。
5. 校验通过后，后端将 Skill 名称、分析指令和输出格式加入本次模型上下文。
6. 助手消息保存本次实际使用的 Skill 名称；刷新会话后仍能显示。
7. Skill 后续被停用、改名或删除，不改变历史消息中已保存的显示名称。

## 7. 功能规则

### 7.1 系统 Skill 规则

- 系统 Skill 至少包含 ID、名称、使用场景、分析指令、输出格式、状态和版本号；
- 系统 Skill 使用稳定 ID，不以名称作为关联键；
- 普通用户读取系统 Skill 时不返回平台内部维护字段；
- 用户启用状态按登录用户名隔离；
- 重复启用应幂等成功，不产生重复记录；
- 重复停用应幂等成功；
- 未发布或已停用的系统 Skill 不能新启用或调用；
- 平台系统 Skill 的数据初始化通过幂等 SQL 种子或受控运维脚本完成，不由前端创建；
- 本期不提供普通用户复制或编辑系统 Skill 的能力。

### 7.2 个人 Skill 字段规则

| 字段 | 规则 |
| --- | --- |
| 名称 | 去除首尾空白后必填，最多 120 字符 |
| 使用场景 | 去除首尾空白后必填，最多 500 字符 |
| 分析指令 | 去除首尾空白后必填，最多 12,000 字符 |
| 输出格式 | `markdown` 或 `text` |
| 状态 | 新建/编辑请求只接受 `draft` 或 `published` |
| 版本号 | 每次成功修改、停用或重新启用后递增 |

- 用户只能查看和管理自己的个人 Skill；
- 越权读取与资源不存在统一返回“Skill 不存在或不可用”，避免暴露其他用户数据；
- 已发布 Skill 允许继续编辑；编辑成功后新消息立即使用新版本；
- 本期历史消息只保留使用时的 Skill 名称，不承诺完整复现当时的提示词内容。

### 7.3 输出格式与多 Skill 冲突

- `markdown`：允许标题、列表、表格和加粗等 Markdown 格式；
- `text`：要求只输出纯文本，不使用 Markdown 标记；
- 输出格式必须与分析指令一起传给模型；
- 平台级安全、真实性和工具调用要求始终高于 Skill 指令；
- **基础版推荐规则**：同一条消息选择的多个 Skill 必须具有相同输出格式；混合选择 `markdown` 与 `text` 时，发送前由前端提示，后端同时拒绝请求；
- 分析步骤之间的其他冲突本期不自动判断，由用户选择兼容 Skill。

### 7.4 模型上下文与安全边界

- 平台系统提示词继续保存角色、安全、真实性、工具调用和投资建议边界；
- 个人 Skill 是用户自定义内容，必须作为“用户选择的执行要求”加入本次用户上下文，不能与平台系统提示词处于同等优先级；
- 系统 Skill 与个人 Skill 使用统一的结构化包装，明确标记每个 Skill 的开始、结束、名称、分析指令和输出格式；
- Skill 指令不得修改平台鉴权、访问其他用户数据或绕过工具权限；
- 模型上下文只使用后端从数据库重新读取的内容，不信任前端传入名称、指令或输出格式；
- 本期不读取附件内容，因此附件中的提示词或脚本不会进入模型上下文。

### 7.5 幂等与状态变化

- 首次发送消息时完成 Skill 权限与状态校验；
- 相同 `client_message_id` 的重试应返回首次已接受的消息结果，不因 Skill 随后被停用而把同一次重试改判为失败；
- Skill 在首次请求校验前已停用或失去权限时，本次请求失败；
- 校验失败时不创建用户消息、助手占位消息或 Skill 使用记录。

## 8. 附件规则

### 8.1 范围与限制

- 允许扩展名：`.pdf`、`.docx`、`.xlsx`、`.csv`、`.txt`、`.md`、`.py`、`.js`、`.sql`、`.sh`；
- 单个附件大小为 1 字节至 10 MB；
- 单个个人 Skill 最多 8 个附件；
- 前端做体验性预校验，后端做最终强制校验；
- 后端数量校验必须包含已有附件，并防止并发上传突破 8 个；
- 只有个人 Skill 创建者可以上传或删除附件；
- 系统 Skill 不开放用户附件上传；
- 页面固定展示：“附件已保存，本期暂不参与 AI 回答；脚本不会在服务器执行。”

### 8.2 数据库与磁盘一致性

- 文件使用服务端生成的随机文件名，不能使用用户文件名作为磁盘路径；
- 上传失败时不得留下可见的数据库记录；发生数据库或写盘异常时执行补偿清理并返回真实失败；
- 删除单个附件时同时删除数据库记录和对应文件；任一步失败都要记录错误并向前端返回失败，不展示已完全删除；
- 永久删除 Skill 时清理该 Skill 的全部附件记录、文件和空目录；
- 增加可独立运行的附件一致性检查，用于发现数据库孤儿记录或磁盘孤儿文件；本期只要求检查和日志，不开发管理页面；
- 前端批量上传出现部分失败时保留编辑页，明确列出成功和失败文件，不把整个操作显示为完全成功。

## 9. 数据模型调整

### 9.1 沿用表

- `workbench_skills`
- `workbench_skill_versions`
- `workbench_skill_attachments`
- `workbench_message_skills`

### 9.2 新增用户系统 Skill 启用关系

建议新增 `workbench_user_system_skills`：

| 字段 | 说明 |
| --- | --- |
| `username` | 当前用户 |
| `skill_id` | 系统 Skill ID |
| `enabled_at` | 启用时间 |
| `updated_at` | 最近更新时间 |

约束：

- `(username, skill_id)` 为唯一键或联合主键；
- `skill_id` 外键关联 `workbench_skills.id`；
- 只允许关联 `owner_type = system` 的 Skill，该规则由仓储层事务校验；
- 基础版采用“存在记录即已启用，停用时删除记录”的简单模型；
- 系统 Skill 被永久删除时启用关系级联删除。

### 9.3 数据迁移

- 新增迁移文件，不能修改已在环境中执行过的旧迁移来替代增量迁移；
- 将前端现有系统 Skill 中经过内容确认的条目写入后端，使用固定 UUID 和幂等写入；
- 前端过去通过“添加”生成的同名个人 Skill不自动转换或删除，避免误删用户已编辑的数据；可在页面上继续作为个人 Skill 展示；
- 上线前在测试库执行全量迁移，并验证旧个人 Skill、版本和附件仍可读取。

## 10. 接口设计

接口路径沿用 `/sapi/skills`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/sapi/skills?scope=system` | 获取系统 Skill，并返回当前用户 `is_enabled` |
| GET | `/sapi/skills?scope=mine` | 获取当前用户个人 Skill |
| GET | `/sapi/skills/chat-options` | 获取当前用户对话可调用 Skill 的并集 |
| POST | `/sapi/skills/{id}/enable` | 启用系统 Skill，幂等 |
| POST | `/sapi/skills/{id}/disable` | 停用系统 Skill，幂等 |
| POST | `/sapi/skills` | 创建个人 Skill |
| GET | `/sapi/skills/{id}` | 获取可访问 Skill 详情 |
| PUT | `/sapi/skills/{id}` | 修改个人 Skill |
| POST | `/sapi/skills/{id}/archive` | 停用个人 Skill |
| POST | `/sapi/skills/{id}/activate` | 将已停用个人 Skill重新发布 |
| DELETE | `/sapi/skills/{id}` | 永久删除已停用个人 Skill |
| POST | `/sapi/skills/{id}/attachments` | 上传个人 Skill 附件 |
| DELETE | `/sapi/skills/{id}/attachments/{attachment_id}` | 删除附件 |

接口要求：

- 系统启停接口必须根据数据库中的 Skill 类型和状态校验，不能只信任路径 ID；
- `chat-options` 只返回已启用且平台已发布的系统 Skill，以及当前用户已发布的个人 Skill；
- 消息发送接口仍以 `skill_ids` 接收选择结果，最多 5 个；
- 业务失败返回稳定错误码和可展示的中文信息；
- 推荐错误码包括 `SKILL_UNAVAILABLE`、`SKILL_PERMISSION_DENIED`、`SKILL_OUTPUT_FORMAT_CONFLICT`、`SKILL_ATTACHMENT_LIMIT`、`SKILL_ATTACHMENT_STORAGE_FAILED`。

## 11. 前端要求

### 11.1 Skills 页面

- 系统页签完全使用后端列表，不再保留固定列表作为正式数据回退；
- 系统卡片显示“已启用/未启用”，操作为“启用/停用”；
- 系统卡片不提供编辑、附件和删除入口；
- 我的页签继续展示草稿、已发布、已停用和版本号；
- 表单增加输出格式选择项；
- 附件区同时计算已上传和待上传数量；
- 加载失败显示错误和重试入口，不把失败伪装为空列表；
- 保存 Skill 成功但附件部分失败时，明确显示两部分结果。

### 11.2 对话页面

- 使用专用 `chat-options` 接口，不再通过 `scope=mine` 后在前端过滤；
- 系统 Skill 和个人 Skill应有来源标识；
- 最多选择 5 个，达到上限后给出明确提示；
- 输出格式冲突时禁止发送并指出冲突的 Skill；
- 可选 Skill 加载失败时显示“Skills 加载失败”，而不是“还没有可用 Skill”；
- 发送后以后端实际接受结果为准显示使用记录；
- Skill 校验失败时保留用户输入和已选择 Skill，便于修改后重试；
- 对话历史继续在助手消息下显示“本次使用：……”；
- 纯文本回答仍可使用现有消息组件显示，但不应生成 Markdown 样式结构。

## 12. 错误与异常处理

- 无效、越权、未发布、已停用或未启用的 Skill：整条消息拒绝；
- Skill 列表加载失败：页面显示真实错误和重试；
- 模型调用失败：消息标记失败，保留已经接受的 Skill 使用记录；
- 上传类型、大小或数量超限：上传前端提示，后端再次拒绝；
- 磁盘写入或删除失败：记录服务端日志，前端显示存储操作失败；
- 前端不得在失败时更新为成功状态，不得静默创建个人 Skill替代系统启用。

## 13. 测试范围

### 13.1 后端单元与仓储测试

- 个人 Skill 创建、修改、版本递增、发布、停用、启用和永久删除；
- 用户 A 不能读取、修改、删除或调用用户 B 的个人 Skill；
- 系统 Skill 对普通用户只读；
- 系统 Skill 启用、重复启用、停用、重复停用和用户隔离；
- 系统 Skill 平台停用后不能调用；
- 对话选项只返回可调用 Skill；
- 草稿、已停用、未启用和不存在的 Skill 调用失败；
- 最多 5 个、重复 ID 和混合输出格式校验；
- 最终模型输入包含名称、指令和输出格式，且平台系统约束优先；
- 相同 `client_message_id` 重试的幂等行为；
- Skill 名称写入消息记录并可随历史读取；
- 附件类型、大小、数量、并发上限、删除和永久删除清理；
- 模拟写盘/删除失败，验证错误和补偿行为。

### 13.2 前端测试

- 系统列表从接口渲染；
- 系统 Skill 启用和停用；
- 系统 Skill 不出现编辑/删除入口；
- 个人 Skill 创建、编辑和状态操作；
- 输出格式表单；
- 对话 Skill 选择、5 个上限和输出格式冲突；
- 列表、保存、上传、删除和调用失败提示；
- 会话刷新后显示已使用 Skill 名称。

### 13.3 集成验收

至少使用两个启用账号完成：

1. 用户 A 启用系统 Skill，用户 B 状态不受影响；
2. 用户 A 创建并发布个人 Skill，用户 B 无法读取或调用；
3. 用户 A 在真实对话中选择系统/个人 Skill，模型输入确实包含相应指令和输出格式；
4. 停用后新消息不能继续调用；
5. 历史消息刷新和重新登录后仍显示使用名称；
6. 附件上传和删除后同时检查数据库与磁盘。

## 14. 验收标准

- 系统 Skill 列表完全来自后端；
- 用户可以真实启用和停用系统 Skill，且状态按用户隔离；
- 普通用户不能修改、上传附件到或删除系统 Skill；
- 用户可以完整管理自己的个人 Skill；
- 不同用户之间不存在个人 Skill 数据泄露或越权调用；
- 对话只展示并允许调用当前用户可用的 Skill；
- Skill 名称、分析指令和输出格式真实进入本次模型上下文；
- 平台系统约束不会被个人 Skill提升到同级后覆盖；
- Skill 无效时明确失败，不生成普通回答；
- 会话刷新后仍显示本次使用的 Skill 名称；
- 附件最多 8 个，删除附件或永久删除 Skill 后数据库与磁盘无正常流程残留；
- 页面明确说明附件本期不参与 AI 回答且脚本不会执行；
- 加载、保存、上传、删除和调用失败均显示真实错误；
- 后端、前端和集成测试覆盖核心验收路径并通过。

## 16. 上线与回滚

- 先应用新增表和系统 Skill 种子，再发布兼容新旧数据的后端，最后发布前端；
- 新增迁移必须幂等，并先在独立测试库验证；
- 前端发布前确认 `chat-options` 和系统启停接口已可用；
- 如果新前端需要回滚，新增启用关系表和系统 Skill 数据可以保留，不影响旧个人 Skill；
- 上线后检查系统 Skill 数量、用户启用记录、Skill 调用失败率和附件存储错误日志。

## 17. 已确认的基础版方案

2026-09-08 确认按以下推荐方案进入开发：

1. **系统 Skill 首批内容**：首批发布 5 个经过审核、指令完整的系统 Skill，其余现有前端卡片暂不迁移。
