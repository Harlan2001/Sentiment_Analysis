## 【第一部分：背景与痛点】（占比 20%）

### 1.1 业务场景描述\*

固收（债券）投研团队每天的核心工作是：从**财经新闻、机构研报、宏观数据、收益率曲线、量化因子、策略信号**等多源信息中，梳理出影响国债/利率债走势的关键信号，并据此形成市场判断与投资策略建议。

这是一条固定且高频的链路，每天循环发生：**早间复盘 → 盘中盯新闻 → 因子归因 → 策略研判 → 晚间报告**。以某固收研究员为例，一个交易日要过数百条新闻、十几份研报、几十项宏观数据，再把它们“翻译”成对债券收益率的判断。

### 1.2 原流程痛点\*

在引入 AI 之前，这条链路几乎全部依赖人工，存在三个叠加的瓶颈：

1. **信息过载**：彭博、Wind、研报系统、社交媒体等来源每天涌入海量信息，真正有价值的关键信号被淹没。漏看一条央行公开市场操作/MLF 降准的新闻，可能就是几个基点的损失。
2. **数据孤岛**：新闻、宏观、收益率、因子、研报散落在不同系统，格式各异、时效不同步、彼此关联难挖掘。做一次完整的“新闻→因子→收益率”溯源分析，往往要跨系统来回切换、手工拼表。
3. **经验依赖**：判断高度依赖个人“盘感”，决策标准不统一；新人从入职到独立看盘培养周期以月/年计；核心交易员一旦离职，经验与知识随之流失，传承效率极低。

> 量化痛点的典型场景：**单个研究员每日人工整合多源信息耗时 2–4 小时**；手工阅读并提炼一份研报约 30 分钟；把“一个策略想法”落到“可回测的代码”需要同时具备金融与编程双重技能，门槛高、周期长。

### 1.3 预期目标\*

希望通过大模型驱动的智能化改造，实现三层目标：

- **提效**：把每日 2–4 小时的人工信息整合压缩到**分钟级**，让人从“搬运工”变成“决策者”；
- **提质**：AI 输出**可溯源、可验证**的结构化结论（方向 / 期限 / 理由 / 因子 / 证据出处），降低人为疏漏；
- **降门槛**：把策略验证的门槛从“会写代码”降到“会描述思路”，并沉淀团队知识资产。

## 【第二部分：解决方案与实施路径】（占比 30%）

### 2.1 AI 应用方案\*

**核心思路**：不把大模型当“聊天框”，而是当作一个**调度中枢**——大模型理解用户意图后，自动调用合适的工具与数据源，再整合成专业、可溯源的分析输出。

技术架构分三层：

```
┌─────────────────────────────────────────────────────────────┐
│ 应用层：对话 / 分析 / 策略生成 / 研报解读 / 预测报告          │
├─────────────────────────────────────────────────────────────┤
│ 能力层：向量检索(FAISS) · 因子引擎 · 回测 · 工具调用框架      │
├─────────────────────────────────────────────────────────────┤
│ 数据层：新闻 · 宏观 · 收益率 · 因子 · 策略库 · 研报(多源)     │
└─────────────────────────────────────────────────────────────┘
```

**端到端决策链路**（8 个环节全部 AI 化）：

> ① 数据采集 → ② 智能分析 → ③ 因子信号 → ④ 策略生成 → ⑤ 变动追踪 → ⑥ 报告分发 → ⑦ 监控运营 → ⑧ 研报分析

关键设计点：

1. **新闻情感分析（核心 Prompt）**：每条财经新闻用结构化 Prompt 约束大模型输出“影响方向（利多/利空/中性）+ 时间跨度 + 因子列表 + 逻辑传导链”，并**强制复用预定义因子**、禁止同义因子泛滥（见下方 Prompt）。
2. **多智能体 Agent**：内置 6 类工具（新闻搜索分析、相似新闻检索、因子列表查询、宏观信号判断、收益率查询），工具定义**由后端 OpenAPI 规范动态生成**（`backend/agent/spec.py`），实现“意图识别 → 工具规划 → 结果整合”的可溯源交互。
3. **向量相似检索**：用 FAISS 对新闻/研报建立向量索引，当重要事件出现时自动检索历史相似事件及当时市场反应，支持“这次会不会重演历史”的判断。
4. **多模型可切换**：GLM-5.2 / DeepSeek-V4 / Qwen3.6 / 豆包 经统一网关接入，按场景与成本路由。
5. **可扩展**：通过 MCP 连接外部/内部系统，通过 Skills 机制上传自定义分析技能，平台“生长”为机构专属的投研底座。

**关键提示词 / 代码片段（评审重点）：**

```
# ── 新闻情感分析核心 Prompt（节选自 backend/analysis/analyzer.py）──
你是中国宏观与债券市场分析专家，基于新闻事件判断对【中国国债】的影响。

【核心任务】1. 提取新闻事件对应的相关因子 2. 构建逻辑推导链

【因子规则 · 复用优先】
- 必须优先从【预定义因子列表】选择，禁止创建同义因子

- 禁止创建：具体政策名称 / 具体国家+事件拼接 / 单次新闻标签

【因子字段规范】
- category: POLICY(政策) | MACRO(宏观) | LIQUIDITY(流动性) | RISK(风险) | SENTIMENT(情绪) | INDUSTRY(行业)
- direction: positive(利多/收益率下行) | negative(利空/收益率上行) | neutral
- logic_impact 必须显式包含：触发事件 → 中间变量 → 利率方向

【输出格式】仅输出合法 JSON，含 direction / horizon / reason / factors
```

def generate_tool_definitions(ops: List[Operation]) -> List[dict]:
    tools = []
    for op in ops:                       # 遍历后端所有 GET 接口
        properties, required = {}, []
        for p in op.params:
            properties[p.name] = {
                "type": _TYPE_MAP.get(p.type, "string"),
                "description": p.description or p.name,
            }
            if p.required:
                required.append(p.name)
        tools.append({
            "type": "function",
            "function": {
                "name": f"{op.group}_{op.name}".replace("-", "_"),
                "description": op.summary or op.description,
                "parameters": {"type": "object",
                               "properties": properties,
                               "required": required},
            },
        })
    return tools        # → 直接作为 OpenAI function-calling 工具注入 Agent

### 2.2 实施步骤\*

1. **数据底座**：搭建新闻爬取、收益率导入、债券标的/策略库同步、研报 PDF 采集清洗的标准化入库管线。
2. **AI 分析引擎**：以结构化 Prompt 约束大模型，对新闻批量产出“方向/期限/理由/因子”结论并落库；同步做向量化索引与相似新闻检索。
3. **因子体系**：新闻分析结果自动汇入六大类因子库（政策/宏观/流动性/风险/情绪/行业），新因子经相似度判定后自动入池，支撑宏观信号计算。
4. **策略与报告**：接入策略推送、AI 标的/策略推荐、日/周/月预测报告与 PDF 生成、飞书/微信推送。
5. **交互与治理**：构建 Perplexity 风格的融合终端（市场/收益/预测/看板），叠加 Agent 对话、研报分析、策略生成、项目协作与运营监控看板。

### 2.3 工具选型理由\*

| 选型 | 理由 |
| ---- | ---- |
| **大模型（GLM/DeepSeek/Qwen/豆包）** | 经公司 kingstar 网关统一接入，符合主推模型路线，成本可控、可灰度切换 |
| **FastAPI + React/Vite + MySQL** | 团队既有技术栈，落地成本低、易在部门内复制 |
| **FAISS 向量检索** | 轻量、无需额外向量数据库，满足相似新闻/研报检索场景 |
| **OpenAPI 驱动 Agent 工具** | 工具定义从接口规范自动生成，新增一个后端接口即自动成为 Agent 能力，零重复开发 |
| **Claude Code 辅助开发** | 在开发过程中辅助编码、测试、文档，本身即体现“编程提效” |

## 【第四部分：推广价值与总结】（占比 10%）

### 4.1 可复用性评估\*

- **架构可复用**：“OpenAPI 驱动 Agent 工具”的机制意味着任何具备标准接口的系统，都可快速接入成为 Agent 能力，无需重复开发。
- **Prompt 可复用**：新闻情感分析的“复用优先因子 + 传导链约束 + 结构化 JSON”Prompt 模板，可迁移到宏观事件、信用事件、行业政策等其他研判场景，仅需替换领域词表。
- **平台可生长**：MCP + Skills 机制让机构能接入内部数据、封装专属策略，形成标准 SOP，具备跨部门/跨客户低成本复制的基础。

### 4.2 经验总结与避坑指南\*

- **用 Prompt 约束而非放任模型发挥**：通过“复用优先、禁止同义因子、logic_impact 三要素”等硬约束，显著提升输出稳定性与因子库质量——这是避免因子库“爆炸”的关键。
- **工具调用要做兜底**：Agent 每个工具执行器都做了异常捕获与错误回传（HTTP/网络/未知异常统一降级），保证多轮对话不因单点失败中断。
- **JSON 解析要容错**：大模型输出存在尾逗号、代码块包裹等格式问题，统一用“提取 + 正则清理 + 解析失败回退中性”兜底，避免一条坏数据拖垮整条链路。
- **演示与生产解耦**：发布会演示采用“预生成数据包 + 导演台中控”，断网也可完整演示，流程完全可控——这是 ToB 场景下稳定交付的关键经验。
- **治理要跟上**：AI 平台必须配套 Token 用量、覆盖率、时效等监控，否则“提效”无法被度量，也难以向管理层证明投入产出。
