# AI 辅助开发流程

核心思路：**先明确意图，再通过文档、测试和 Spec 逐步约束 AI，最后进入开发。**

**实际使用**：先写文档，文档写完也要看一下是否符合我们的想法，确认完毕之后让AI写Spec，写好Spec之后也要看一下，之后让AI写测试，最后在做真正的开发也就是代码实现，实现好之后做测试看有没有问题



## 1. 先写 PRD / Design Doc

在开发前，先将需求沉淀为 **PRD（需求文档）** 和 **Design Doc（设计文档）**，帮助 AI 准确理解需求、目标和实现方案。

相比直接告诉 AI：

> AI，帮我改造前端。

更推荐：

> AI，@前端改造.md 是我的 Design Doc，请基于这份文档开始改造。

**文档是 AI 理解开发意图的重要上下文。**

---

## 2. Test-first Programming

开发新功能时，优先编写测试，再进行实现。

例如开发功能 A：

1. 编写功能 A 的需求 / 设计文档：`@A.md`
2. 基于文档编写功能 A 的测试
3. 基于文档和测试完成功能开发

即：

> AI，@A.md 是功能设计文档，请基于文档先编写 A 功能的测试。

然后：

> 测试完成后，基于 `@A.md` 和测试开始实现功能 A。

这样可以让测试成为需求的**可执行约束**，减少 AI 偏离需求的情况。

---

## 3. 要求 AI 明确 Spec（规约）

在正式开发前，让 AI 根据**文档 + 测试**进一步提炼实现规约，包括：

- 函数声明
- 参数与返回值
- 类型约束
- 核心行为
- 边界条件
- 异常处理
- 不变量 / 约束条件

例如：

```python
def calculate_discount(price, rate) -> float:
    """
    Spec: 计算折扣价
    1. 接口
      函数 calculate_discount(price, rate) -> float，返回打折后的价格。
    2. 参数与返回值
      price: 原价，float；rate: 折扣率，float，0~1；返回 float。
    3. 类型约束
      price/rate 必须是数字；rate 必须在 0 到 1 之间。
    4. 核心行为
      返回 price * (1 - rate)，结果保留两位小数。
    5. 边界条件
      rate=0 返回原价；rate=1 返回 0；price=0 返回 0。
    6. 异常处理
      非数字抛 TypeError；rate 越界抛 ValueError。
    7. 不变量
      不修改输入；结果 >= 0；同一输入结果相同。
    8. 验收标准
      calculate_discount(100, 0.2) == 80.00
      calculate_discount(100, 0) == 100.00
      calculate_discount(100, 1) == 0.00
    """
    函数具体实现
```
