# Docker 部署与定时任务完整指南

本指南结合 Docker 部署和定时任务调度，适用于生产环境一次性部署。

---

## 快速部署清单（一句话版）

```bash
# 1. 上传项目代码
scp -r /path/to/Sentiment admin@server:/opt/

# 2. 上传定时任务脚本到服务器任务目录
scp /path/to/Sentiment/scripts/*.sh admin@server:/opt/sentiment-tasks/

# 3. SSH 进去配置环境、启动容器、配置 cron
ssh admin@server

# 在服务器上：
cd /opt/Sentiment
cp .env.example .env
# 编辑 .env 填入实际的数据库和 API 密钥
vi .env

# 启动 Docker
docker compose up -d

# 配置定时任务
chmod +x /opt/sentiment-tasks/*.sh
crontab -e
# 添加三行 cron 定时任务（见下面的 crontab 示例）
```

## 第一部分：Docker 部署准备

### 环境要求

- Docker 20.10+
- Docker Compose v2+
- 至少 20GB 存储，16GB RAM（推荐）
- 外部 MySQL 5.7+ 数据库已准备好

### 1. 环境变量配置

```bash
cd /path/to/Sentiment

# 从模板创建 .env 文件
cp .env.example .env

### 2. 构建镜像

```bash
# 使用国内源加速（可选）
docker compose build --no-cache

# 或者如果已构建过，跳过缓存重新构建
docker compose build --no-cache backend frontend
```

### 3. 启动容器

```bash
# 启动所有服务（后台运行）
docker compose up -d

# 验证启动状态
docker compose ps
docker compose logs backend -f  # 查看后端日志
docker compose logs frontend -f  # 查看前端日志
```

## 第二部分：定时任务配置（Linux/Unix）

推荐方案：**在主机上用 cron 调度，通过 docker exec 调用容器内脚本**。

### 1. 上传并配置定时任务脚本

项目里已预制好三个脚本文件（`scripts/yield_update.sh`、`scripts/report_gen.sh`、`scripts/analysis_fallback.sh`），直接上传即可：

```bash
# 在本地项目根目录执行，上传脚本到服务器
scp scripts/*.sh admin@your_server:/data/sentiment/

# 在服务器上添加执行权限
ssh admin@your_server "chmod +x /data/sentiment/*.sh"
```

如果你需要自己编辑脚本，主要修改点是 `WORKDIR` 变量，把它改成实际的 Sentiment 项目路径。

### 2. 配置 crontab

```bash
# 编辑 crontab
crontab -e

# 添加以下定时任务：
# ============ Sentiment 定时任务 ============

# 20:00 - 更新收益率数据
0 20 * * * /opt/sentiment/yield_update.sh

# 09:00 - 生成昨日交易日报告
0 9 * * * /opt/sentiment/report_gen.sh

# 23:00 - 兜底补偿任务（处理触发失败的新闻）
0 23 * * * /opt/sentiment/analysis_fallback.sh

# ============================================
```

### 3. 验证 cron 任务

```bash
# 查看已配置的定时任务
crontab -l

# 查看 cron 日志
tail -f /var/log/syslog | grep CRON

# 手动测试某个任务脚本
/opt/sentiment/yield_update.sh
/data/sentiment/report_gen.sh
/data/sentiment/analysis_fallback.sh

```

### 4. 监控日志

```bash
# 创建日志目录
mkdir -p /var/log/sentiment

# 实时监控各任务日志
tail -f /var/log/sentiment-yield.log
tail -f /var/log/sentiment-report.log
tail -f /var/log/sentiment-fallback.log

# 查看容器内业务日志
docker compose logs -f backend
```

## 第五部分：任务监控与告警

### 1. 查看任务运行记录

后端数据库中已记录所有任务执行历史，可查询：

```sql
-- 查看最近的任务运行
SELECT id, task_name, task_type, status, total_count, processed_count, 
       started_at, finished_at, error_message
FROM task_runs
ORDER BY created_at DESC
LIMIT 20;

-- 查看某个任务的详细事件
SELECT event_type, news_id, status, message, created_at
FROM task_events
WHERE task_run_id = ?
ORDER BY created_at ASC;
```

### 2. 告警规则（最小集）

建议监控以下指标：

- **任务失败**：`status = 'failed'` 的 task_runs
- **任务超时**：`finished_at - started_at > 30 minutes`
- **报告缺失**：某天 09:00 后 `forecast_report` 没有新增 `full_report`
- **分析积压**：`analyzed = 0` 的新闻数量超过 100 条

### 3. 日志查询

```bash
# 查看最近一小时内的错误
docker compose logs backend --since 1h | grep -i error

# 查看分析任务的详细日志
docker compose logs backend --since 24h | grep "分析"

# 导出日志用于分析
docker compose logs backend > sentiment-backend.log 2>&1
```

## 第六部分：版本更新

当代码有更新时，执行以下步骤：

```bash
cd /path/to/Sentiment

# 1. 拉取最新代码
git pull

# 2. 重新构建镜像
docker compose build --no-cache

# 3. 停止旧容器并启动新容器
docker compose down
docker compose up -d

# 4. 验证新容器状态
docker compose ps
docker compose logs backend -f

# 5. 检查新增的表和数据结构
docker compose exec backend bash
mysql -h$MYSQL_HOST -u$MYSQL_USER -p$MYSQL_PASSWORD $MYSQL_DATABASE -e "DESC task_runs;"
```

## 故障排查

### 容器无法启动

```bash
# 查看启动错误
docker compose logs backend

# 验证环境变量
docker compose config | grep kingstar_API_KEY

# 尝试重新启动
docker compose restart backend
```

### 定时任务没有执行

```bash
# Linux/Unix：检查 cron 日志
tail -f /var/log/syslog | grep CRON

# 验证 cron 配置
crontab -l

# 手动执行任务脚本，查看错误
/opt/sentiment-tasks/yield_update.sh

# Windows：检查任务计划程序中的事件日志
```

### 容器内脚本无法运行

```bash
# 进入容器调试
docker compose exec backend bash

# 确认环境变量已加载
echo $MYSQL_HOST

# 手动运行脚本
python backend/analysis/generate_report.py --trade-date 2026-05-18
```

## 检查清单

部署完成后，按以下清单验证：

- [ ] Docker 容器正常运行：`docker compose ps`
- [ ] 后端 API 可访问：`curl http://localhost:8000/health`
- [ ] 前端页面可访问：`curl http://localhost/`
- [ ] 定时任务已配置：`crontab -l`（Linux）或任务计划程序（Windows）
- [ ] 收益率表已初始化：`SELECT COUNT(*) FROM yield_data;`
- [ ] 任务记录表已创建：`DESC task_runs;`
- [ ] 测试内部触发接口：调用 `/api/internal/analysis/trigger`
- [ ] 测试报告生成：`python backend/analysis/generate_report.py --trade-date 2026-05-18`
- [ ] 监控日志输出：`docker compose logs -f backend`

## 总结架构

```
┌─────────────────────────────────┐
│   Linux/Windows 主机            │
├─────────────────────────────────┤
│  Cron / Task Scheduler          │
│  ├─ 19:00 → yield_update.sh     │
│  ├─ 09:00 → report_gen.sh       │
│  └─ 23:00 → analysis_fallback.sh│
├─────────────────────────────────┤
│  Docker Compose                 │
│  ├─ Backend (FastAPI)           │
│  │  └─ /api/internal/...        │
│  └─ Frontend (Nginx)            │
├─────────────────────────────────┤
│  MySQL 数据库                   │
│  ├─ news, analysis, forecast_..│
│  └─ task_runs, task_events      │
└─────────────────────────────────┘

     ↑
   Spider
   (定期抓取 → 调用 API)
```

这套方案简单稳定，不需要复杂的 Kubernetes 或 scheduler 服务，完全足以支撑生产级应用。
