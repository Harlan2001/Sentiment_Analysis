# 定时任务与触发调度指南

本文档说明当前项目推荐的生产调度方式：**Cron 为主，内部 API 触发为辅**。项目不再依赖独立的 `scheduler` 服务入口。

## 生产推荐方案

### Linux 服务器

Spider 项目和 Sentiment 项目都部署在 172.18.0.23 这台 Linux 服务器上，因此推荐直接在同机上用系统 Cron 调度脚本和内部 API，避免跨机器调用：

- 19:00 执行收益率更新
- 09:00 执行昨日交易日报告生成
- Spider 抓取完成后由本机进程直接调用内部分析触发接口
- 23:00 再跑一次兜底补偿任务

### Windows 服务器或本地联调

推荐用 Windows 任务计划程序定时执行同样的命令，不需要常驻 Python 调度进程。

---

## 可执行命令

### 1. 更新收益率数据

```powershell
python scripts/update_yield_data_from_excel.py --excel-path data/GovernmentBonds.xlsx
```

建议在每日 19:00 执行，给当日行情更新留出缓冲。

### 2. 生成昨日交易日报告

```powershell
python backend/analysis/generate_report.py --trade-date 2026-05-18
```

线上建议由定时任务显式传入昨日交易日；如果不传 `--trade-date`，脚本会自动选择当前日期之前最近的可用交易日。

### 3. Spider 抓取后触发分析

```powershell
python scripts/trigger_analysis_example.py ^
  --base-url http://127.0.0.1:8000 ^
  --idempotency-key spider-20260519-0900 ^
  --mode model_missing ^
```

Spider 抓取完成后，在同一台 172.18.0.23 服务器上调用该命令对应的内部 API，Sentiment 会按幂等键去重并执行未处理新闻分析。
如果要做完全增量更新，可以直接不传 `--limit`，这样接口不会对本次分析数量设上限。

---

## 备注

如果后续需要把调度进一步标准化，可以在此基础上再补一层 systemd 或者 Kubernetes CronJob，但当前版本优先保持简单稳定，不引入独立 scheduler 服务。
