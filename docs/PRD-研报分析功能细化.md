# 研报分析功能细化 · 改造规格

> 本文件是给执行改造的 AI 的指令性规格，共三个板块：
> - **板块一：单篇研报 AI 深度拆解** —— 解决分析内容"泛、浅、不可核验"的问题；
> - **板块二：功能与交互修复** —— 修复现有断链/失效逻辑，补齐必要功能；
> - **板块三：页面信息架构调整** —— 重新组织工作台页面的板块与入口。
>
> 执行顺序：**板块二 P0 → 板块一 → 板块二 P1/P2 与板块三**。板块一依赖板块二 P0-3（存量研报才能用新结构重跑），板块三是纯前端体验改版，建议最后做，不要三者混在一次改动里。本文只定义"做成什么样"，不规定具体技术实现。

# 板块一：单篇研报 AI 深度拆解

## 1.1 要解决的问题

当前单篇研报分析（`backend/research_report/llm.py` 的 `PROMPT_TEMPLATE`）只产出扁平的 `summary / key_points / evidence`，摘要浅层，浮于表面：泛化套话多、无论证结构、无前提假设、无推理链路、溯源只覆盖少数几条。用户读完无法复述作者"凭什么得出结论"。

**改造目标**：针对单篇研报/文章，从"概括"升级为"拆解 → 观点识别 → 观点复现"，还原作者的论点、论据、明示假设、推理链路、边界条件；所有提炼必须锚定原文可核验，压缩 AI 臆断。

## 1.2 必须遵守的规则

1. **两区物理隔离，严禁混写**
   - A 区＝**原文作者观点（客观还原）**：只放原文可定位的内容。
   - B 区＝**AI 分析解读（独立模块）**：只放原文之外的分析（隐含假设、逻辑缺口、证据问题、待验证项），默认折叠、带"AI 解读·非作者观点"标识。
   - 同一句/同一卡片/同一单元格不得同时含两区内容。B 区禁止给投资建议、目标价。
2. **A 区每条观点/事实/数字必须带原文溯源**，用全局摘录编号 `[Qx]`，标注页码；摘录逐字、连续，不改写不拼接，跨段拆成多条。不允许"见上文"。
3. **观点复现 = 论点 + 论据 + 前提假设 + 推理链路 + 风险/边界** 五要素，缺一不可；原文确实没有的要素固定写"原文未明确给出"，禁止编造或留空。
   - 前提假设只放**作者明示**的；AI 识别出的隐含假设放 B 区。
   - 推理链路分步呈现"因为…→所以…"，不得跳步。
4. **禁止无指向空话**（"持续向好/值得关注/未来可期"等）。关键判断须含 对象+数值/变化+时间+口径/条件+出处，五具至少其四。
5. 作者自陈的**反方观点、让步、风险、失效条件**必须保留，不得只留有利结论。
6. 数字保留原文口径与单位，不得静默换算/四舍五入；归属第三方的观点不得记为作者本人，归属不确定要标注。

## 1.3 目标输出结构（Markdown，固定骨架）

```
# {标题}
## 一、核心论点（作者观点）     # 一句话主张(可证伪) + 最终结论/操作建议，各行内附逐字原文+页码
## 二、论证结构（观点树）       # 主论点→分论点→论据，标注逻辑关系(支撑/并列/递进/转折)与页码
## 三、观点复现
### 观点N：{论点}
   - 前提假设（作者明示，行内附原文+页码；无则"原文未明确给出"）
   - 论点（含作者措辞强度、时间维度，行内附原文+页码）
   - 论据（具体数据/事实 + 口径，行内附逐字原文+页码，分条）
   - 推理链路（分步）
   - 风险与边界（行内附原文+页码；无则"原文未明确给出"）
## 四、关键证据与数据          # GFM 表：指标/数值/单位/口径期间/实际或预测/原文出处
## 五、作者风险提示与适用边界   # 仅作者原意，逐条行内附原文+页码
## 六、AI 分析解读（非作者观点） # 逻辑缺口 / 隐含假设 / 证据问题 / 待验证项，每条指明针对哪张卡片
```

溯源统一采用**行内摘录**，格式 `（原文："逐字摘录"，第N页）`，不设独立附录、不使用编号引用。

要求：标准 Markdown/GFM，不依赖 CSS 即可读懂；兼容现有 PDF/DOCX 导出，导出后**分区标识、出处、五要素、表格不得丢失**，摘录与 AI 解读版式可一眼区分。

## 1.4 输入 / 异常

- 输入：单篇研报全文（带页码）+ 抽取出的图表（带页码/图号）+ 可提取元信息；可选分析侧重。
- 原文无法解析/过短：如实报错，不得生成看似完整的结果。
- 数字、图表识别不确定：保留并标"低置信 + 原因"，不静默猜测。解析缺口在对应观点卡片中标注。

## 1.5 改造涉及位置（参考，具体实现自定）

- 后端单篇分析：`backend/research_report/llm.py`（重写分析指令与输出结构）、`backend/research_report/service.py`、`backend/research_report/constants.py`
- 数据层：`backend/repositories/research_report_repository.py`（结构化字段存储/读取）
- 路由：`backend/routers/research.py`
- 前端：`api/reportGeneration.ts` 类型、`features/workflow/components/ReportSourceDetailPanel.tsx`（按新结构渲染、B 区折叠）、相关样式
- 导出：`backend/report/export_service.py`
- 下游多研报综合 `backend/research_report/synthesis.py` 应消费新的观点卡片字段（可作为后续改造，至少不与之冲突）

## 1.6 验收口径（自检/抽检红线）

- A 区观点溯源覆盖率 = 100%；摘录页码可定位率 ≥ 95%；摘录逐字忠实。
- 观点卡片五要素齐全率 ≥ 98%；关键数字与原文一致率 ≥ 99%；多空/结论方向写反 = 0 容忍。
- A 区越区混入 AI 主观判断 ≤ 2%，AI 观点冒充作者结论 = 0 容忍。
- 空话句占关键内容 ≤ 5%；推理链无关键跳步的卡片 ≥ 90%。
- 只看分析结果（不看原文）能正确复述"论点+主要论据+关键假设+失效条件"的观点 ≥ 85%。
- PDF/DOCX 导出结构与溯源无丢失。

## 1.7 最小样例（展示写法粒度，研报为虚构）

> **核心论点**：在弱基本面+低通胀+宽货币下，2026 利率债慢牛，10Y 国债收益率中枢降至 1.55%（区间 1.40–1.80%），看多。（原文："我们判断2026年利率债延续慢牛，10年期国债收益率中枢下行至1.55%附近，确定性较高。"，第1页）
>
> **观点 1 复现**
> - 前提假设（作者明示）：赤字率约 3.2%、专项债 4.0 万亿不超预期；美联储降息约 50bp。（原文："赤字率维持在3.2%左右。"，第9页）
> - 论点：10Y 中枢由约 1.80% 降至 1.55%；作者强度"较高确定性"；时间：全年、重心上半年。（原文："我们判断2026年利率债延续慢牛，10年期国债收益率中枢下行至1.55%附近，确定性较高。"，第1页）
> - 论据：地产投资预测 -6%、出口增速回落至 1.8%；CPI 0.4%、PPI -1.2%；预计降准 50bp；保险+理财增量配置 2.1 万亿 > 净供给。（原文："GDP增长4.6%，地产投资-6%，CPI中枢0.4%。"，第3页）
> - 推理链路：地产拖累+外需放缓→产出缺口为负(-0.8%)→核心通胀低、名义增长弱→货币宽松、资金利率下行→配置需求>供给→10Y 中枢降约 25bp 至 1.55%。
> - 风险/边界（作者写明）：赤字率若提至 4.0% 且专项债前置，收益率或阶段性上行 20–30bp，基准判断失效。（原文："若财政赤字率提高至4.0%且专项债前置，收益率或阶段性上行20–30bp，全年判断需修正。"，第13页）
>
> **六、AI 解读（非作者观点）**
> - 隐含假设：以"配置 2.1 万亿 > 净供给"为论据，但原文未给净供给测算，结论力度取决于此 → 列为待验证项。
> - 证据问题：所引"6 次供给冲击后均回落"样本同处宽松周期，外推到财政可能转向的 2026 年存幸存者偏差。

# 板块二：功能与交互修复

> 每条给出【现状问题】和【目标】。涉及文件均在 `frontend/src/features/workflow/` 与 `backend/` 下。

## 2.1 P0 —— 阻断性问题，必须最先修

**P0-1　"新建综合研报"选源链路断裂，任务无法创建**
- 现状：`pages/ReportGenerationPage.tsx` 有 `selectedIds` 状态和"已选 N 份来源"提示，但全页面没有任何给它赋值的入口；研报卡片点击是跳转/打开详情，`ReportSourceDetailPanel.tsx` 也没有"加入本次合成"按钮。用户永远是"已选 0 份"，提交必报错。
- 目标：提供完整选源闭环——研报卡片上可勾选（最多 12 篇，仅 `analyzed` 状态可选，不可选要显示原因如"分析中/未分析"）；已选清单可见、可单篇移除、可清空；选择结果在新建表单中实时展示。

**P0-2　主页发布日期筛选失效**
- 现状：日期只传给 `getReportSources`，而其返回的 `sources` 没有被渲染；真正渲染列表的 `getResearchList` 不传日期，后端 `GET /sapi/research/list`（`backend/routers/research.py`）也不支持日期参数。
- 目标：研报库列表按发布日期区间正确过滤（前端传参 + 后端支持 `date_start/date_end`）；控件与列表使用同一套查询状态。

**P0-3　已分析研报无法重新分析（板块一落地的前置条件）**
- 现状：`POST /sapi/research/{id}/analyze`（`research.py`）对 `analyzed` 状态直接返回"无需重复触发"。新分析结构上线后，存量研报无法升级。
- 目标：
  - 支持单篇"重新分析"（显式覆盖，需二次确认；记录分析版本/时间，失败不得覆盖旧结果）；
  - 支持按筛选条件**批量重跑**（后台排队，有进度与成功/失败计数）；
  - 综合任务引用的来源快照（`source_snapshot_json`）不因源研报重析而被静默篡改（快照策略要明确：保持生成时版本）。

## 2.2 P1 —— 重要体验缺口

**P1-4　单篇详情侧栏升级为新结构载体**（配合板块一）
- 后端详情接口已返回 `figures` 图表列表，但侧栏未渲染：需在证据区展示图表（带页码/图号）。
- 提供**原文对照阅读**：可查看原文 PDF/全文，点击 `[Qx]` 或观点卡片能定位到对应页码/段落并高亮。
- 现状的"原文摘录"只是把 `full_text` 切前 5 段，属于假摘录，移除或替换为板块一定义的摘录库。
- 涉及：`components/ReportSourceDetailPanel.tsx`、`GET /research/{id}`。

**P1-5　单篇深度拆解支持导出**
- 现状：只有综合任务能导出 PDF/DOCX。
- 目标：单篇分析结果按板块一结构可导出 PDF/DOCX，复用 `backend/report/export_service.py`，分区标识与溯源不丢失。

**P1-6　分析失败的研报要有重试入口**
- 现状：`failed` 研报只能重走上传弹窗；弹窗对重复文件点"开始 AI 分析"是空操作。
- 目标：库列表与详情侧栏对 `failed` 提供"重新分析"；上传重复文件时引导"查看已有研报"，不显示无效按钮。

**P1-7　综合报告支持"再生成"与编辑**
- 现状：`backend/report/generation_service.py` 一次合成定终稿，只能整体重试。
- 目标：
  - 基于同一批来源**修改需求后重新生成**，历史版本保留、可查看；
  - 可增删来源后重生成；
  - 生成的 Markdown 可在线小幅编辑后再导出；
  - 创建任务时允许选择模型（对齐单篇分析已有的 model 参数）。

**P1-8　综合环节增加结构化"观点对比"**
- 板块一产出观点卡片后，综合报告除 AI 行文外，增加一张**跨报告观点矩阵**：议题 × 各来源机构（立场/关键数据/核心假设），"分歧与共识"基于矩阵汇总，而非只靠模型自由复述。

## 2.3 P2 —— 入库与库管理优化

- **P2-9 批量上传**：支持多选/多文件拖拽，逐份显示"解析→分析中→完成/失败"进度与去重清单（现状仅单文件）。
- **P2-10 检索增强**：关键词搜索扩展到正文与 AI 观点内容（现状只匹配标题/机构/行业，见 `research.py` 的 `_BROWSE_KEYWORD_COLUMNS`）。
- **P2-11 列表状态收口**：主页研报库混入未分析/失败研报但又不可用于合成；提供"仅看已分析"开关，不可用卡片明确禁用并标注原因。
- **P2-12 工程细节**：筛选关键词输入需防抖（现状每次按键都请求）；任务轮询与异常提示维持现有机制即可。

## 2.4 板块二验收要点

- 不勾选来源时提交按钮禁用并说明原因；勾选→提交→任务出现在列表，全链路可走通。
- 日期、机构、行业、观点、关键词筛选均真实生效（含发布日期区间）。
- 任意一篇存量 `analyzed` 研报可触发重新分析并得到板块一结构；批量重跑有进度、可查失败项。
- 失败研报在列表/侧栏可一键重试；单篇可导出；综合报告可改需求重生成且历史版本不丢。

# 板块三：页面信息架构（IA）调整

## 3.1 核心问题

`/computer/reports`（`ReportGenerationPage.tsx`）一个页面平铺了四类对象：研报库（原料）、需要处理（任务进度）、历史生成（成品）、底部 composer（创建入口）。三种心智混杂，且**原料占据最大最靠上的面积**，与页面主任务"产出综合研报"倒置。

**定位调整：该页面是"研报报告工作台"，只回答三个问题——我的报告在哪、怎么新建、有什么待我处理。研报库降级为被调用的资源。**

## 3.2 删除 / 改造

1. **移除底部聊天框式 composer**。创建综合报告是"选来源+标题+需求+日期"的多步表单，不是对话；现状悬停输入框与研报库没有视觉连接（也是 P0-1 断链根源），且 Enter 易误提交。
   → 改为右上角"＋ 新建综合研报"按钮，打开**多步弹窗/抽屉**：① 选来源（库检索+勾选+已选清单）→ ② 标题/需求/日期（可选模板）→ ③ 确认提交。全页创建入口收敛为这一个。
2. **统计卡片重做**。现状"看多/看空/中性/机构数"是不可操作的装饰数字。
   → 改为行动型指标：**待分析 N 份、分析失败 M 份、本月新增 K 份**，数字可点击跳转对应筛选列表；多空计数删除或并入库页面。
3. **"需要处理"改名并拆分**：运行中任务用户无事可做，不值得独占一区 → 弱化为"**生成中**"进度区（或并入"我的报告"用状态+进度条展示）；另新增一条"**待办提醒**"汇总真正要人处理的事项（解析完未分析、分析失败、生成失败，各带一键处理）。
4. **筛选去重**：工具栏"任务日期"单日选择器与库的"发布日期"区间语义不同却并列，保留一套有效的（任务侧用区间、库侧按 P0-2 修好），不要两个并存。

## 3.3 新增板块

1. **「我的报告」作为页面主体**（原"历史生成"表格升级为 C 位卡片列表）：标题、需求摘要、N 篇来源（含机构）、状态、生成时间、快捷导出/重试/再生成；支持标题搜索、状态过滤。
2. **研报库入口化**：主页只保留"最近上传 5 份 + 管理全部"，完整库管理留在独立页 `/computer/reports/library`，选库动作主要发生在新建弹窗内。
3. **快速入库入口**：工具栏与空状态提供上传入口（对接 P2-9 批量上传），上传后原地可见分析进度。
4. **（可选 P2）报告模板**：周期性需求（如"月度利率债观点综述"）可存为模板，预置需求文本与默认来源筛选，一键发起。
5. **（可选 P2）专题夹**：把一组研报先保存为专题（如"2026 年度策略合集"），生成时直接引用，免去每次重新勾选。

## 3.4 目标页面骨架

```
研报分析工作台（/computer/reports）
├── 顶部标题栏
│    ├── 待办提醒条（待分析 N · 失败 M，点击即处理）
│    └── [上传研报]   [＋ 新建综合研报]
├── 主区：我的报告（C 位，卡片列表；搜索/状态/日期筛选）
│         每张卡片：状态 · 来源机构 · 时间 · 导出/重试/再生成
├── 次要区：生成中（弱化，仅进度）
└── 研报库区：最近上传 5 份 + [管理全部]（跳转 /computer/reports/library）

新建综合研报（弹窗，多步）
  步骤1 选来源：检索/筛选 + 卡片勾选（≤12，仅已分析）+ 已选清单
  步骤2 填信息：标题、需求（可选模板）、日期区间、模型
  步骤3 确认提交 → 跳转任务详情
```

## 3.5 板块三验收要点

- 页面首屏主体是"我的报告"和两个主按钮，研报库不再占据首屏主要面积。
- 创建综合报告只有一个入口，三步弹窗可完整走通（与 P0-1 一并验收）。
- 运行中任务、待办事项、统计卡片各归其位，页面无重复/失效筛选控件。
- 原有路由（`/computer/reports`、`/computer/reports/library`、`/computer/reports/:taskId`）保持可用，书签不失效。
