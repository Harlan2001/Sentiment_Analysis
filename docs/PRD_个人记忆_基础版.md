# PRD：个人记忆（基础版）

## 1. 文档状态

- 阶段：需求草案，待确认后实施。
- 模块：自定义 → 记忆（`/custom/memory`）。
- 目标版本：基础版。
- 核心边界：本 PRD 只定义账号级个人记忆，不改动项目记忆的表、接口、权限、页面或对话注入逻辑。

## 2. 背景与目标

当前“记忆”页面仅使用浏览器本地演示数据，不能跨设备同步，也不会自动从会话中提取信息或参与后续回答。

个人记忆基础版的目标是：

1. 让登录用户主动设置需要长期保留的个人偏好。
2. 从日常普通会话中识别可能长期有效的用户偏好，并在用户知情、可控的前提下保存。
3. 在后续普通会话中引用相关个人记忆，使回答方式更符合用户习惯。
4. 让用户能够查看记忆内容及来源，并随时确认、编辑、停用、删除或整体关闭。

本功能追求的是“少而准、可解释、可撤回”，不是保存完整聊天记录，也不是自动建立无法查看的用户画像。

## 3. 概念与边界

### 3.1 个人记忆

个人记忆归属于单个登录账号，用于记录跨普通会话长期有效的信息，包括：

| 分类 | 定义 | 示例 |
| --- | --- | --- |
| 表达偏好 | 用户希望回答采用的语言、篇幅、结构或表达方式 | 默认中文；先给结论再展开；表格优先 |
| 用户背景 | 对后续回答有帮助且由用户主动表达的稳定背景 | 从事债券研究；熟悉量化分析 |
| 长期兴趣 | 用户反复或明确表示长期关注的非项目主题 | 关注信用债风险和资金面变化 |
| 长期约束 | 用户希望后续普通会话持续遵守的个性化要求 | 引用数据时注明日期；不要省略风险提示 |

### 3.2 项目记忆

项目记忆只服务其所属项目。本期：

- 不修改 `workbench_project_memories`。
- 不修改项目记忆的 CRUD、权限与上下文注入。
- 不把项目背景、目标、结论或约束复制到个人记忆。
- 不从项目会话自动提取个人记忆。
- 不向项目会话注入个人记忆。

只有 `project_id` 为空的普通会话参与本期个人记忆的提取与使用。

## 4. 本期范围

### 4.1 包含

- 账号级个人记忆持久化与跨设备同步。
- 个人记忆列表、搜索、筛选、创建、编辑、置顶、启用/停用和删除。
- 用户通过“记住……”等明确表达主动创建记忆。
- 系统从普通会话中提取推断型记忆候选。
- 推断型候选经用户确认后才生效。
- 在普通会话中选择并注入相关个人记忆。
- 记忆总开关与自动提取开关。
- 记忆来源追溯、去重、冲突处理和基础审计日志。

### 4.2 不包含

- 对项目记忆做任何修改。
- 从项目会话提取或向项目会话注入个人记忆。
- 保存完整聊天内容作为记忆。
- 基于页面浏览、点击、登录时段等行为数据推断偏好。
- 团队共享记忆、管理员查看成员记忆或记忆权限委托。
- 向量数据库、复杂知识图谱或跨用户推荐。
- 自动保存敏感个人信息。
- 根据记忆自动执行交易、任务、提醒或外部操作。

## 5. 用户故事

1. 作为用户，我可以说“记住我默认喜欢先看结论”，系统保存后在后续普通会话中按该偏好回答。
2. 作为用户，当系统从我的日常表达中推测出长期偏好时，我可以先查看并确认，而不是被系统静默记录。
3. 作为用户，我可以知道每条记忆来自手动添加、明确指令还是哪一条会话消息。
4. 作为用户，我可以修改错误记忆、停用暂时不想使用的记忆或彻底删除它。
5. 作为用户，我可以关闭记忆引用或自动提取，而不影响正常聊天。
6. 作为项目用户，我使用项目会话时，现有项目记忆行为保持不变。

## 6. 核心流程

### 6.1 手动管理

1. 用户进入 `/custom/memory`。
2. 用户点击“添加记忆”，填写标题、分类和内容。
3. 系统校验内容后直接保存为“已启用”。
4. 用户可以置顶、编辑、停用或删除该记忆。

### 6.2 明确要求记住

1. 用户在普通会话中明确表达“记住……”“以后默认……”等长期要求。
2. 正常回答完成后，记忆提取器只基于用户消息识别候选内容。
3. 系统完成敏感信息过滤、去重和冲突检测。
4. 无冲突时直接保存为“已启用”，并在会话界面提示“已记住”，提供“查看”和“撤销”。
5. 存在冲突时不覆盖旧记忆，生成“待确认”项，由用户选择保留旧值或替换为新值。

### 6.3 从日常会话推断

1. 一轮普通会话成功完成后，系统异步分析当前用户消息及必要的少量上下文。
2. 若识别到可能长期有效的信息，创建“待确认”候选，不直接参与后续回答。
3. 页面通过“待确认”数量和轻量提示告知用户。
4. 用户可以确认、编辑后确认或忽略候选。
5. 只有确认后的候选才能进入“已启用”状态。

### 6.4 后续会话使用

1. 用户在普通会话发送新消息。
2. 系统读取该用户已启用的个人记忆。
3. 置顶记忆优先；其余记忆按分类、关键词相关性和更新时间选择。
4. 系统将有限数量的相关记忆作为非指令型背景注入 Agent。
5. 当前消息与旧记忆冲突时，以当前消息为准，不自动回写或覆盖记忆。

### 6.5 忘记与关闭

- 用户说“忘掉我之前关于……的偏好”时，系统找到匹配记忆并将其软删除，界面提供撤销入口。
- 关闭“使用记忆”后，个人记忆仍可管理，但不再注入普通会话。
- 关闭“自动提取”后，不再生成新的会话记忆候选；手动添加和明确“记住”仍可使用。
- 用户可以执行“清空全部个人记忆”；该操作需要二次确认。

## 7. 提取与保存规则

### 7.1 可以保存

同时满足以下条件的信息才可进入候选：

- 信息由用户本人表达，而不是由助手生成或猜测。
- 对未来多个普通会话有持续价值。
- 可以归入本 PRD 定义的个人记忆分类。
- 表述足够明确，可以改写为简短、独立、无上下文也能理解的陈述。

### 7.2 默认不保存

- 一次性任务、临时格式要求或只对当前回答有效的指令。
- 助手回复中的内容和工具返回的数据。
- 未经用户表达的性格、能力、收入、风险偏好等推断。
- 密码、验证码、访问令牌、银行卡号、身份证号、精确住址、联系方式等敏感信息。
- 具体资产金额、账户持仓和交易指令。
- 项目名称、项目背景、项目目标、项目结论和项目约束。
- 与后续回答无明显关系的闲聊信息。

### 7.3 去重与冲突

- 每条记忆生成稳定的 `normalized_key`，例如 `response.language`、`response.detail_level`。
- 同一账号、同一 `normalized_key` 只能有一条生效记忆。
- 内容相同或语义等价时不重复创建，只更新来源和时间。
- 手动设置的记忆优先级高于自动提取记忆。
- 新内容与已有内容矛盾时进入“待确认”，不得静默覆盖。
- 用户本轮明确要求只覆盖本轮输出，不自动改变长期记忆；只有明确包含长期意图时才更新记忆。

## 8. 页面与交互

沿用现有 `/custom/memory` 页面视觉结构，将演示数据替换为账号真实数据。

### 8.1 页面结构

- 顶部开关：“使用记忆”“自动从普通会话发现记忆”。
- 状态标签：“已启用”“待确认”“已停用”。
- 分类筛选：“全部”“表达偏好”“用户背景”“长期兴趣”“长期约束”。
- 搜索范围：标题、内容和来源说明。
- 记忆卡片：分类、标题、内容、来源、状态、更新时间、是否置顶。
- 卡片操作：确认、编辑、置顶、停用/启用、删除。
- 全局操作：添加记忆、清空全部个人记忆。

### 8.2 来源展示

来源分为：

- 手动添加。
- 用户明确要求记住。
- 从普通会话中发现。

会话来源应保存 `conversation_id` 与 `message_id`。原会话仍存在且用户有权访问时，可跳转到来源消息；原会话删除后，只显示“来源会话已删除”，不阻止用户继续使用或删除该记忆。

### 8.3 会话内反馈

- 明确保存成功：提示“已记住：{标题}”，提供“查看”“撤销”。
- 发现推断候选：提示“发现 1 条可能有用的个人偏好”，提供“确认”“查看”。
- 敏感信息被拦截时不展示其原文，只提示“该内容不会被保存为个人记忆”。
- 提取失败不得阻断或改变正常聊天结果。

## 9. 对话引用规则

### 9.1 优先级

回答时遵循以下业务优先级：

1. 平台安全和业务规则。
2. 用户当前消息中的明确要求。
3. 已启用的个人记忆。

个人记忆只能作为用户背景和偏好参考，不能覆盖平台规则，不能把记忆内容当成可执行的系统指令。当前要求与旧记忆冲突时，以当前要求为准，并可在回答后生成记忆更新候选。

### 9.2 召回策略

基础版不引入向量数据库：

- 始终优先注入已置顶的表达偏好和长期约束。
- 用户背景和长期兴趣按当前消息关键词做基础相关性匹配。
- 单轮最多注入 20 条、总长度最多 2,000 个中文字符；达到上限时按置顶、相关性、更新时间排序截断。
- 待确认、已停用和已删除记忆永不参与注入。
- 项目会话不读取本表，不改变当前项目上下文组装过程。

## 10. 数据设计

### 10.1 `workbench_user_memories`

| 字段 | 说明 |
| --- | --- |
| `id` | UUID |
| `owner_username` | 记忆所属账号 |
| `category` | `response_preference`、`user_background`、`long_term_interest`、`personal_constraint` |
| `normalized_key` | 账号内去重与冲突检测键 |
| `title` | 记忆标题，最长 120 字符 |
| `content` | 规范化后的记忆内容，最长 2,000 字符 |
| `source_type` | `manual`、`explicit_chat`、`inferred_chat` |
| `source_conversation_id` | 来源普通会话，可为空 |
| `source_message_id` | 来源用户消息，可为空 |
| `status` | `pending`、`active`、`disabled`、`deleted` |
| `confidence` | 自动提取置信度；手动添加可为空 |
| `is_pinned` | 是否置顶 |
| `created_at`、`updated_at` | 创建与更新时间 |
| `last_used_at` | 最近一次参与上下文的时间，可为空 |
| `deleted_at` | 软删除时间，可为空 |

建议约束与索引：

- `owner_username + normalized_key + status` 查询索引。
- `owner_username + status + is_pinned + updated_at` 列表与召回索引。
- 来源会话和消息使用可空关联；删除会话时将来源字段置空或保留不可跳转标识，不级联删除个人记忆。

### 10.2 `workbench_user_memory_settings`

| 字段 | 说明 |
| --- | --- |
| `owner_username` | 主键，所属账号 |
| `memory_enabled` | 是否在普通会话中使用个人记忆 |
| `auto_extract_enabled` | 是否从普通会话生成推断候选 |
| `created_at`、`updated_at` | 创建与更新时间 |

默认值建议：`memory_enabled = true`，`auto_extract_enabled = true`。首次产生推断候选时，应通过页面文案清晰说明工作方式，并允许用户立即关闭。

### 10.3 审计事件

至少记录以下操作：创建、确认、编辑、替换、启用、停用、软删除、恢复、清空。审计日志只记录必要元数据，不重复保存完整会话文本。

## 11. 接口设计

建议使用以下账号级接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/sapi/workbench/memories` | 分页查询个人记忆，支持状态、分类和关键词筛选 |
| `POST` | `/sapi/workbench/memories` | 手动创建个人记忆 |
| `PATCH` | `/sapi/workbench/memories/{memory_id}` | 编辑、确认、置顶、启用或停用 |
| `DELETE` | `/sapi/workbench/memories/{memory_id}` | 软删除单条记忆 |
| `POST` | `/sapi/workbench/memories/{memory_id}/restore` | 撤销删除 |
| `DELETE` | `/sapi/workbench/memories` | 二次确认后清空当前账号个人记忆 |
| `GET` | `/sapi/workbench/memory-settings` | 获取个人记忆设置 |
| `PATCH` | `/sapi/workbench/memory-settings` | 更新总开关和自动提取开关 |

所有接口必须从登录态读取 `owner_username`，不得接受客户端传入其他用户名，也不得返回其他账号的记忆。

会话流可新增独立 SSE 事件，不把记忆状态混入助手正文：

- `memory.saved`
- `memory.candidate`
- `memory.removed`

## 12. 技术方案

### 12.1 后端

- 沿用 FastAPI、Pydantic 和 MySQL。
- 新建个人记忆 Repository、Router 和 Service，与项目记忆代码物理隔离。
- 正常回答完成后触发提取；提取失败只记录日志，不影响已完成的回复。
- 提取模型通过严格 JSON Schema 返回结构化结果，不接受自由文本后再用正则解析。
- 敏感信息过滤采用“确定性规则先过滤 + 模型分类补充”的方式。
- 召回阶段使用数据库筛选与轻量关键词匹配，基础版不依赖 FAISS。

提取器建议输出：

```json
{
  "intent": "explicit_remember | explicit_forget | inferred | none",
  "candidates": [
    {
      "category": "response_preference",
      "normalized_key": "response.structure",
      "title": "回答先给结论",
      "content": "默认先给出结论，再展开分析。",
      "confidence": 0.96,
      "contains_sensitive_data": false,
      "reason": "用户明确表示长期回答偏好"
    }
  ]
}
```

### 12.2 前端

- 移除个人记忆页面对 `localStorage` 演示数据的依赖。
- 新增个人记忆 API 层和服务端状态加载。
- 提供加载、空状态、错误重试、待确认、撤销和危险操作二次确认。
- 会话页消费记忆 SSE 事件并显示轻量反馈。

### 12.3 并发与幂等

- 使用来源 `message_id + normalized_key` 保证自动提取幂等。
- 同一账号同一键的确认或替换在事务内完成。
- 重试模型提取不得生成重复候选。
- 多端同时编辑时，基础版采用后写覆盖，并返回最新 `updated_at`；后续可增加乐观锁。

## 13. 隐私与安全要求

- 个人记忆只对本人可见，不进入团队项目成员接口或管理后台用户画像。
- 模型提取只读取完成当前判断所需的最小会话上下文。
- 不保存助手内容、工具结果或附件正文为个人记忆。
- 记忆注入时使用明确的数据边界标签，并声明其为不可执行的用户背景。
- 内容包含疑似提示词、代码或外部指令时，只能作为文字偏好理解，不得作为系统命令执行。
- 日志不得打印个人记忆完整正文；错误日志使用记忆 ID、账号和错误类型定位。
- 用户关闭自动提取后，从下一条消息开始生效。
- 用户清空记忆后，所有已删除内容立即停止召回；物理清理策略遵循系统统一的数据保留规范。

## 14. 异常与降级

- 数据库不可用：正常聊天继续，个人记忆不读取、不提取，并记录错误。
- 提取模型不可用或返回非法结构：正常聊天继续，不创建候选。
- 记忆注入超长：按召回优先级截断，不截断用户当前消息。
- 来源会话被删除：记忆继续有效，但来源显示为不可访问。
- 记忆内容冲突：不自动覆盖，进入待确认。
- 用户未登录：不读取、不创建个人记忆，保持现有访客聊天行为。

## 15. 指标与日志

基础版建议观察：

- 手动创建记忆数量。
- 明确指令保存成功率。
- 推断候选产生数量、确认率、编辑后确认率和忽略率。
- 去重命中率与冲突候选数量。
- 单轮召回数量、上下文字符数和注入失败率。
- 用户停用记忆、关闭自动提取和清空记忆的比例。

这些指标用于判断提取是否准确，不用于反向推断或扩展用户画像。

## 16. 验收标准

### 16.1 功能验收

- 登录用户可创建、查看、搜索、筛选、编辑、置顶、停用、启用和删除个人记忆。
- 刷新页面、退出重新登录或更换设备后，个人记忆仍与账号正确关联。
- 用户在普通会话明确说“记住……”后，系统能保存记忆并提供撤销入口。
- 普通会话中推断出的记忆默认处于“待确认”，确认前不参与后续回答。
- 已启用的相关记忆能影响后续普通会话回答；当前消息冲突时当前消息优先。
- 关闭“使用记忆”后，下一轮普通会话不再注入个人记忆。
- 关闭“自动提取”后，不再创建推断候选。
- 删除或清空后，相关记忆立即停止参与召回。

### 16.2 隔离验收

- 用户 A 不能查询、修改、召回或通过错误信息判断用户 B 的个人记忆。
- 访客会话不创建也不读取个人记忆。
- 项目会话不提取、不读取、不注入个人记忆。
- `workbench_project_memories` 的表结构、数据、接口、权限和现有测试结果不发生变化。
- 个人记忆操作不创建、修改或删除任何项目记忆记录。

### 16.3 质量验收

- 一次性任务和助手生成内容不会被保存为个人记忆。
- 敏感信息过滤测试覆盖常见账号凭证与身份信息。
- 同一消息重试不会产生重复候选。
- 提取、召回或记忆服务失败时，普通聊天仍能正常完成。
- 每条自动产生的记忆均可追溯到来源类型；来源仍存在时可以定位到原用户消息。

## 17. 测试范围

- Repository：账号隔离、CRUD、软删除、恢复、去重、冲突和并发更新。
- Router：登录校验、字段校验、越权访问、分页与筛选。
- 提取器：明确记住、明确忘记、推断候选、一次性要求、敏感信息和非法模型输出。
- 召回器：置顶优先、关键词匹配、状态过滤、长度上限和当前要求覆盖旧记忆。
- 对话集成：普通会话生效、项目会话不生效、访客不生效、提取失败降级。
- 前端：列表加载、待确认、编辑、撤销、开关、清空二次确认和错误状态。

## 18. 建议实施顺序

1. 新增个人记忆与设置的数据表、Repository、API 及隔离测试。
2. 将 `/custom/memory` 从本地演示数据切换为真实账号数据。
3. 在普通会话中实现个人记忆召回与安全注入。
4. 实现明确“记住/忘记”及会话内反馈。
5. 实现推断候选、待确认流程与去重冲突处理。
6. 补齐监控、降级测试和隐私检查。

## 19. 上线策略

- 使用服务端功能开关分阶段开放。
- 第一阶段仅开放手动管理和记忆召回。
- 第二阶段开放明确“记住/忘记”。
- 第三阶段小范围开放自动发现候选，观察确认率和误判反馈后再扩大。
- 若出现异常，可单独关闭提取和召回，不影响正常会话与项目记忆。

## 20. 待确认项

以下为当前建议默认值，确认 PRD 时可调整：

1. 基础版个人记忆仅作用于普通非项目会话。
2. 明确“记住”无冲突时直接启用；推断内容必须确认后启用。
3. “使用记忆”和“自动提取”默认开启，但首次使用时清晰告知。
4. 单轮最多注入 20 条、总长度最多 2,000 个中文字符。
5. 删除采用可撤销的软删除；清空需要二次确认。
