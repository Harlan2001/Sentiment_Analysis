本周工作总结：

### 1. 标准化因子事件时序接口（PR #51，已合并）

- **接口能力**：面向外部策略及回测系统新增 `GET /sapi/factors/events`，将内部非标新闻数据的因子结构化结果以统一事件格式开放。支持通过 `factor_code` 查询多个因子，通过 `start_time/end_time` 限定发布时间，通过 `model` 固定抽取模型，并结合 `direction/include_neutral` 过滤正向、负向及中性事件；分页单页最多返回 500 条。
- **回测时间口径**：时间锚点统一使用 `news_factor.pub_time`，而不是新闻入库时间或因子计算时间；带时区的入参先转换到上海时区，再按数据库的时间存储约定查询，起止时间采用闭区间，避免外部回测与内部数据出现时间口径偏差。
- **查询与分页实现**：新增只读仓储关联 `news_factor`、`factor`、`news` 三张表，在相同过滤条件下分别查询事件页和总数；按 `pub_time、news_id、factor_id` 稳定升序排列，解决仅靠时间排序时同时间事件跨页重复或遗漏的问题。每次查询只使用一个模型，避免不同模型对同一新闻的抽取结果混用。
- **返回数据与质量保障**：事件数据包含因子代码、分类、类型、方向、模型、新闻标题和驱动因素等字段，并保留新闻 ID 供结果追溯。同步更新对外对接文档及 OpenAPI 契约快照，补充参数校验、方向过滤、时区转换、稳定分页等单元测试，以及真实 MySQL 查询集成测试。

### 2. 策略历史结果版本切换（PR #52，已提交）

- **版本选择状态**：基于已有会话版本和消息数据实现，不新增结果副本。在前端向导状态中增加 `selectedVersionId`，默认回退到最新版本；普通轮询刷新不会覆盖用户正在查看的历史版本，只有检测到最新版本 ID 发生变化时才自动切回最新结果。
- **结果视图联动**：结果报告不再直接读取固定的 `lastVersion`，而是统一由当前选中版本驱动策略概要、平台回测状态、核心指标、收益质量与风险指标、Python 代码、完整回测日志及退出码，避免切换版本后页面不同区域展示不同次生成的数据。
- **验收结论隔离**：通过选中版本的 `source_message_id` 找到对应 assistant 消息，再读取该消息的 `validation_json`，使内部验收结论与版本一一对应；历史版本没有验收数据时明确显示“回测通过（未验收）”，不会串用最新版本的“验收通过”结论。
- **交互与测试**：版本切换时同步重置代码复制状态并清理相关定时器；补充多版本切换、各结果区域联动、无验收数据、同版本刷新保留选择以及新版本出现自动切换等前端测试场景。

### 3. 账号级研究组合

- **持久化模型**：本周完成现状梳理和方案设计并进入开发，正在新增研究组合与持仓两类独立数据模型。组合记录 `owner_username`、研究规模、指标日期、目标久期、归档状态和乐观锁 `version`；持仓记录债券快照、配置权重、可空久期、到期收益率及排序号，并对组合内债券代码做唯一约束。
- **指标计算口径**：使用 `Decimal` 进行指标计算，已投资权重为各持仓权重之和，现金权重为 `100 - 已投资权重`。久期和收益率只在对应字段非空的持仓上加权，分母使用有效持仓权重，同时返回有效权重覆盖率；缺失值不按 0 参与计算，避免指标被低估。
- **交易一致性与权限**：持仓新增、修改、删除、复制及批量导入均在事务中锁定父组合，串行化“组合权重不得超过 100%”校验并递增版本号，防止并发请求同时通过校验。所有持仓操作先校验组合归属，归档组合只读；权重不足 100% 的差额自动作为现金，不再通过修改其他持仓进行隐性平衡。
- **导入导出与产品边界**：CSV 导入按 UTF-8-SIG 处理，支持 append/replace，逐行返回行号、字段和错误，任一行失败则整批不写入；导出增加文本字段的公式注入防护。配置金额仅按“研究规模 × 权重”估算，不展示无数据依据的真实市值、净值、收益或 AI 配置结论。目前该模块仍处于开发与联调阶段。

### 4. 统一 AI 任务中心与政策分析闭环

- **统一执行模型**：针对研报解析、政策文件、综合研报和新闻总结四类任务，正在现有领域表上补充 `queued_at、lease_token、lease_expires_at、stage、active_run_id、retry_count` 等执行字段，不另建第二套任务状态表双写。API 只负责持久化入队，调度器通过有界执行池和每领域并发限制领取任务，避免批量任务为每个排队项创建一个等待线程。
- **并发与防旧结果覆盖**：任务领取采用带状态条件的原子 `UPDATE`，只有 queued/pending 能进入 running/analyzing，并写入随机租约 token；执行期间通过心跳续租，阶段更新、结果保存和终态变更都校验 token。重试会产生新 token，即使旧 worker 延迟返回，也不能覆盖新一轮执行结果。
- **日志事务与重启恢复**：复用现有 `task_runs/task_events` 记录真实执行阶段，通过任务类型、领域 ID 和 claim token 构造幂等键，领域终态、业务结果与执行日志在同一业务库事务提交。服务重启后 queued/pending 任务继续被扫描领取；running/analyzing 且租约过期的任务标记为“服务中断”，由用户手动重试，不自动重复调用 LLM。
- **统一查询与前端展示**：统一读服务正在接入任务类型、状态、日期筛选和服务端分页，在服务端完成 owner 隔离、各领域状态映射、排序及 totals 统计；任务详情通过 `active_run_id` 读取阶段事件，展示真实阶段、完整错误、重试入口及结果或文件链接。前端仅对 queued/running 任务节流轮询，页面隐藏时暂停，终态后停止。
- **政策分析闭环**：上传时的 `focus_title` 和 `analysis_requirement` 将持久化并实际拼入政策分析提示词，重试沿用原请求参数；关键词、方向、日期筛选及统计下推数据库，避免只统计当前页数据。重复文件需用户确认后重新分析，上传反馈改为真实“已加入队列”，移除固定 1200ms 的模拟分析定时器。目前整体处于开发与联调阶段，后续还需完成迁移、并发与重启场景回归以及前后端集成验收。
