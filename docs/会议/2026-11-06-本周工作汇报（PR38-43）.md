## 二、策略工作台改版（#38–#42，已上线 main）

### 1. #38 S1：验收门废单判定 + 后端质量补全

**问题背景（均有实测样本，非推测）**：回测平台对"通过"的口径是进程正常退出，源码注释明确 `total_trade_count=0 is OK`——实测 25 个历史模板中 21 个零成交却全部 passed；10-30 会话 #60 又暴露第二种假阳性：`Total Orders 29`、Win Rate 64%，但 Net Profit 0.000%、Portfolio Turnover 0%、Average Win/Loss 均为 0%，订单提交了却没有任何真实成交盈亏（废单/未撮合），旧验收门走订单数回退分支误判 passed。

**（1）废单判定（`backend/strategy/backtest_validation.py`）**

在订单数回退分支之前先查成交的经济实质，指标缺失时视为证据不足、保持既有行为（不武断判废），满足任一证据链即判 `no_trade` 并可带原因重生：

- 证据链 A：Average Win 与 Average Loss 绝对值均 < 0.005%，且 Win Rate 或 Loss Rate > 0（平仓被记录却没有盈亏）；
- 证据链 B：Portfolio Turnover < 0.005% 且 |Net Profit| < 0.01%（订单从未形成真实持仓周转）。

验收结论统一为四态 `passed / no_trade / backtest_failed / backtest_error`，前端按结论选徽章文案、不自行推断；只有"跑完了但没成交/废单/演示稿"类失败带原因重生（上限 2 轮），回测失败/异常默认不重试。

**（2）生成代码 AST 静态检查（新增 `strategy_code_review.py`）**

回测跑起来之前先拦两类高频废稿：

- **无真实下单调用**：`ast.parse` 后遍历 `ast.Call`，匹配 13 个 KSAPI/Lean 下单方法名（`MarketOrder / LimitOrder / Buy / Sell / SetHoldings / OrderTarget…`，大小写不敏感）；注释和字符串里的文字不会命中，避免误判；
- **演示稿自陈**：对注释（tokenize 提取）和字符串字面量按句扫描 9 条正则（"信号日志形式""仅打印交易信号""不进行真实下单"等），命中句若含"禁止/不得/严禁"等否定词则放行——那是在复述任务卡要求而非自陈；
- 刻意只做高置信度拦截：参数硬编码、保证金异常等拿不准的留给上层 advisory，避免误伤能成交的策略；语法错误标 `syntactically_valid=False` 走回测失败分支。

**（3）指定标的强校验与情报口径修复**

- 落实此前空转的 `expected_instrument`：代码/参数中必须出现任务卡指定代码，白名单 6 个券种 + `100040` 别名（与 `FCT_T_MAIN` 互通），不匹配判 `backtest_error` 可重生；`FCT_AU_MAIN`（黄金）本期拒绝；另检测 XBOND 现券买卖类型下到期货品种的错配；

### 2. S3-2：重要性打分后端（纯规则、可解释，无黑盒）

打分拆两层：**静态重要性分预计算落库，时间衰减读时实时施加、不入库**。

**9 个信号加权合成 0–100 静态分 `I_news`**（权重/词表/类别全部在 `backend/config/config.py`，调参不改代码，单测校验权重和为 1）：

| 信号 | 权重 | 归一化要点 |
|---|---|---|
| 分析方向 s_direction | 0.18 | 利多/利空对利率交易同等可操作记 1.0，中性 0.4，无分析 0.2 |
| 模型一致性 s_agreement | 0.14 | 多模型归一化方向投票 max(票数)/模型数；单模型给中性分 0.6 |
| 期限 s_horizon | 0.08 | 中期 1.0 > 长期 0.8 > 短期 0.65（时效性交给衰减项） |
| 因子类别 s_category | 0.20 | 政策 1.00 > 宏观 0.90 > 资金面 0.85 > 风险 0.70 > 情绪 0.55 > 行业 0.45，取关联因子最高类别 |
| 事件研究命中率 s_hit | 0.12 | 不用裸命中率，用相对多数类基准的 edge：`clip(0.5+2×(hit_rate−majority_base), 0.2, 0.9)`，防类别失衡；样本 < 20 条向 0.5 收缩 |
| 因子数量 s_nfactor | 0.10 | 关联因子数 /5 饱和，防关键词堆砌膨胀 |
| 内容丰富度 s_rich | 0.08 | 表格 1.0 > 配图 0.5 > 标题块 0.25×4，数据型文章优先 |
| 政策标记 s_policy | 0.07 | 关联 POLICY 因子即命中；否则标题关键词兜底（降准/降息/MLF/LPR/逆回购/央行等） |
| 来源 s_source | 0.03 | 合规脱敏后 v1 两源同分，保留配置位待行为数据拉开 |

**时间衰减**：`final = I_news × EXP(-λ × age_days)`，λ=0.08，半衰期约 **8.7 天**，适配 7–30 天推荐窗口；Python 纯函数与 SQL 表达式 `FINAL_SCORE_EXPR` 数学等价（`GREATEST` 把未来发布时间钳到 0 天），库侧排序无需把数据捞回应用层。

- 两条写入路径：`analyzer_runner` 在分析事务提交后增量打分，**失败仅告警不阻断分析主流程**；兜底为 `scripts/recompute_news_importance.py`（`--all` / `--window N`）+ SAAS/大前台两套 23:30 cron 包装（窗口 30 天）；
