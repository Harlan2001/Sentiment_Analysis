# 舆情因子接入策略生成（DreamStrategy）实施方案

> 受众：我方工程/策略同学，以及对方（金仕达平台）对接人
> 目的：定义我们的舆情系统如何调用 DreamStrategy V3_FICC5，把舆情、非结构化因子及已有市场数据资产转化为"标的正确、有成交、可回测验证"的债券策略
> 配套阅读：[策略生成系统-DreamStrategy-必要信息说明.md](策略生成系统-DreamStrategy-必要信息说明.md)（系统能力与实测现状）、[非结构化因子系统对接文档.md](非结构化因子系统对接文档.md)（381 因子的数据模型与 API）
> 版本：v1.0（2026-10-28）

---

## 1. 目标与非目标

### 目标

1. **跑通**：我方页面点"确认生成"能稳定在 DreamStrategy 上完成 建模板/会话 → 生成 → 回测 → 结果回显 全链路。
2. **提质**：由我方情报指定**交易标的、模式、周期、开平条件骨架**，模型只负责把需求翻译成 KSAPI 代码，杜绝"沪金双均线 0 成交"类产物。
3. **用数**：把 381 个非结构化因子中**经事件研究验证有效**的子集，以信号面板（L1，立即落地）和因子数值序列（L2，需对方配合）两种方式接入。
4. **可验证**：每条策略留存情报快照、提示词版本、回测指标；支持"有舆情门控 vs 无门控"的对照评估，证明增量价值。

### 非目标（本期明确不做）

- **实盘交易**：对方现役部署无脚本运行时、无执行器（V1 已编译剔除，V2 下单为空桩）。本期终点是"带回测报告的策略研究草案"。
- 改造对方 C++ 服务、破解 licence、替代其回测平台。
- 让策略代码在回测运行时联网取新闻/调我方 API（对方法则与沙箱均禁止，也无必要）。

## 3. 总体方案：四层演进

```
                ┌────────────────────────────────────────────────────────┐
                │                  我们的舆情/因子平台                     │
                │  news/analysis · 381因子事件流 · 事件研究命中率          │
                │  曲线/利差/持仓 · forecast · 组合约束                    │
                └───────────────┬───────────────────────┬────────────────┘
                                │ L1 结构化情报文本       │ L2 因子数值序列
                                ▼                       ▼
┌───────────────────────────────────────────────┐   ┌──────────────────────────┐
│ L0 通道：DreamStrategy WS+Protobuf（已打通）    │   │ qfm 推送 / mock_factor   │
│ 160050 建模板 · 160060 会话 · 160070 消息       │   │ HTTP / 因子文件（待建）  │
│ 160054 取版本 · 160055 独立回测 · 160057 token │   └─────────────┬────────────┘
└───────────────┬───────────────────────────────┘                 │
                ▼                                                 ▼
        LLM 生成 KSAPI 代码（bar/tick 模式）          ◄──── factor 模式 on_factors(factor_id)
                │
                ▼
        Bond-Backtest /qt 回测 → 日志 + STATISTICS
                │
                ▼  L3 评估闭环
        情报/提示词/指标落库 → 门控对照 → 反哺信号阈值与提示词
```

- **L0（M0）**：通道级修复，让它跑通、报错可见。
- **L1（M1）**：强化"生成期情报包"，把我们的数据资产变成聊天文本里的任务卡+信号面板+验收标准。**不依赖对方排期，是本期价值主战场。**
- **L2（M2）**：因子数值序列进金仕达平台，factor 模式策略在回测每个时点读取。**依赖对方提供通道。**
- **L3（M3）**：回测结果资产化与对照评估，证明舆情/因子的增量价值并持续迭代。

## 4. L0：通道修复与跑通（M0，约 1–3 人日）

### 4.1 模板自动供给（修 G1，推荐方案）

服务端 160050（`AddAiStrategyV2Template`）的行为已核实：**请求里的 name/description/code 会被服务端强制置空**，一次调用自动建好「空模板 + 初始版本(version_no=0) + 默认会话」并回传模板对象。改造：

1. [client.py](../backend/integrations/dream/client.py) 新增命令号 `EI_ADD_TEMPLATE=160050`、`EI_LIST_SESSIONS=160063`、`EI_BACKTEST=160055`、`EI_SET_BOND_TOKEN=160057`（160057 仅联调用，可只做管理脚本）。
2. [service.py](../backend/integrations/dream/service.py) 启动/首次使用时：
   - 若配置了有效的 `DREAM_TEMPLATE_ID`，用 160053/160054 探活；
   - 否则调 160050 自动建模板，取返回的 `template.open_id`，默认会话经 160063 取得（open_id），映射关系**落我方库**（建议新增表，见 §8）；
   - 推荐粒度：**我方一个"策略对话"对应对端一个模板**（模板即策略容器，版本天然隔离），后续追问在其默认会话内进行。
3. `DREAM_TEMPLATE_ID` 降级为可选覆盖项；迁移期也可人工在 Web UI 建模板把 open_id 填进环境变量。

### 4.2 错误态与超时（修 G2、G10）

接收循环中增加终态判定：

- `content_type==5` 或 `strategy_generation_status==5(ERROR)`：立即结束等待，抛出含消息 content（错误说明）的业务异常，落库为"生成失败"。
- 状态 1/2/3 推送（GENERATING/CHECKING/REGENERATING）与普通 TEXT：转发给任务状态通道供前端展示，不结束循环。
- 明确"无取消协议"：前端取消 = 放弃等待+本地标记取消；提示用户对端仍会跑完。**单飞期间禁止发起第二个生成**（见 4.4）。

### 4.3 回测令牌与登录账号核实（修 G3）

- 与对方确认门户 publicKey 登录映射的 `user_id`（现存模板全在 user_id=3）；
- 用管理脚本调 160057 为该账号设置回测令牌（令牌值不得入库代码/文档，走环境变量或密钥管理）；
- 联调一条最简 bar 日频策略（如 T 主力 5/20 双均线），确认回测产出非空日志与成交。

### 4.4 单飞互斥（修 G4）

- 我方加进程内/数据库级生成锁（对端按用户单飞，锁粒度=Dream 账号）；请求排队，前端显示"队列中"；
- 任务记录远端 `template_id/session_id/message_id`，断连重连用 160054/160073 回收结果，避免重复发起把对端搞成多个空模板。

### 4.5 M0 验收标准

- [ ] 空库（无 DREAM_TEMPLATE_ID）情况下自动建模板/会话成功；
- [ ] 故意发送非法需求时，30 秒内前端看到明确错误，而非 900s 超时；
- [ ] 国债期货日频策略从发起到回测完成 ≤ 5 分钟，回测日志含成交与 STATISTICS 指标；
- [ ] 连续发起两次生成，第二次排队且不会收到对端"忙碌"错误。

## 5. L1：生成期情报包（M1，约 1–2 周，价值核心）

### 5.1 设计原则

1. **我们做投资决策，模型做翻译**：标的、模式、周期、开平骨架、仓位/止损由我方给定；模型负责 KSAPI API 正确性。
2. **只带验证过的因子**：进入情报包的因子必须满足 `n≥20 且 Wilson 下界 > 多数类基准命中率`（沿用 factor_event_study 口径），其余因子不出现在提示词里，避免噪声。
3. **舆情是门控不是信号源**：延续既有铁律"新闻不得单独触发交易"——舆情用于**允许/禁止/确认**技术条件、方向过滤与冲突裁决。
4. **防前视**：情报锚点为窗口内 `MAX(news.pub_time)`，所有数据（含曲线、持仓）只用该时点之前可得的值。
5. **频率匹配**：新闻小时级 → 策略默认 **bar 日频**；不做 tick 级舆情幻想。
6. **全程留痕**：每次情报包内容、prompt_version、模型 agent、回测结果整体快照入库。

### 5.2 情报包结构（替换现五段式中的"当前市场情况/新闻分析"两节）

```text
【策略任务卡】（强制，不可被模型更改）
- 交易标的：T 主力（国债期货10Y），辅助标的 240004.IB 类活跃券 ……（标的代码必须
  来自平台可交易清单；模型可用 get_tradable_instrument_codes / get_bond_basic_info 核验）
- 模式与周期：bar，1d；回测区间 2024-01-01 至 {锚点日}；初始资金 1000 万
- 开仓骨架：技术触发（如均线/动量）+ 情绪门控同向才允许开仓
- 平仓骨架：反向技术信号 / 止损 1.5% / 止盈 3% / 情绪门控翻转
- 风控：单笔敞口 ≤20%；门控冲突时空仓；下单接口必须与标的类型匹配（禁止 XBOND 下期货）

【因子信号面板】（仅列通过事件研究检验的因子，按 |净方向|×命中率 排序，≤8 个）
因子(中文/code)        方向   信号分  命中率(基准)   Wilson95%   n    有效期限  最近触发
货币政策-降准预期       多    +0.72   0.63 (0.51)   [0.55,0.70] 47   5交易日  2026-10-27
政府债供给-增量发行     空    -0.55   0.59 (0.51)   [0.51,0.67] 38   10交易日 2026-10-25
面板用法：方向=债市口径（多=收益率下行）；信号分=presence/directional 衰减值；
门控规则：同向信号数 ≥2 且无强反向信号时允许开仓；多空阵营数量相等→不开新仓。

【市场验证块】（锚点时点 T0 的客观行情）
- 国债曲线：1Y 1.45% / 5Y 1.78% / 10Y 2.12% / 30Y 2.35%；近5日 bp：+1/-2/-3/-4
- 信用利差（AAA/AA+ 中票）：当前值与 20 日分位
- 中美利差：当前值与 20 日方向
- 国债期货持仓排名：T/TF/TS/TL 前 20 多空持仓与周变动
- forecast 模型下一周期方向 + 历史准确率（若 > 随机基准才展示）

【组合约束】（来自 portfolio_analysis，目标日 T0）
久期 3.5–4.5 年；利率债占比 60–80%；信用债 AA+ 及以上；……（JSON 原文附录）

【冲突与纪律】
- 新闻/因子方向与市场验证块（如曲线已大幅下动）矛盾时：降低目标仓位 50%；
- 信号面板为空（无过关因子）：只允许生成纯技术基准策略并在描述中标注"无情绪门控"；
- 禁止使用新闻原文逐条触发；禁止运行时访问任何外部数据源；
- 回测要求：必须产生成交（目标 ≥10 笔/年）；0 成交视为策略不合格。
```

实现位置：新建/重构 [sentiment_context.py](../backend/strategy/sentiment_context.py)（建议拆出 `signal_panel.py`），数据来源映射：

| 情报块 | 数据源 / 接口 | 备注 |
|---|---|---|
| 因子面板 | factor + news_factor + factor_event_study；信号分沿用 `/sapi/macro/signal` 逻辑（λ=0.1、阈值 0.3） | 因子事件时序接口待补：`GET /sapi/factors/events`、`GET /sapi/factors/signals/panel`（见因子对接文档 §7-A），L1 可直接查库先行 |
| 代表事件 | news_factor 关联 news，取每因子最近 1 条标题 | 每事件一句话，控制 token |
| 曲线/利差 | yield_data、信用利差、中美利差 | 现有 1/5/10/30Y 扩展利差与分位数 |
| 持仓/预测 | 期货持仓排名表、forecast + 准确率评估 | 准确率不达标不展示，避免误导模型 |
| 组合约束 | portfolio_analysis 缓存 | 仅当目标日与锚点匹配时注入 |

### 5.3 token 预算

服务端单条消息 ≤10000 token（约 1.2–1.5 万汉字），还要给系统提示词与模型输出留空间。建议：**我方 content ≤ 4000 汉字**（任务卡 400 / 面板表格 ≤1200 / 市场块 700 / 约束 400 / 规则 400 / 其余为现有保护段）。面板因子数、代表事件条数、曲线精度按预算裁剪并在日志记录裁剪情况。

### 5.4 回测验收门与反馈重生（修 G6）

终态结果在我方再过一道门（与平台 `backtest_passed` 无关，那个只代表"跑完了"）：

| 检查 | 通过标准 | 不通过动作 |
|---|---|---|
| 代码完整性 | code 非空、语法/合约标的类型与下单 BusinessType 匹配 | 静态规则检查 + 重生 |
| 成交 | 日志成交笔数 > 0（建议 ≥10 笔/年） | 重生 |
| 方向一致性 | 多头策略的持仓/盈亏方向不与情报门控系统性相反 | 标记存疑，人工复核 |
| 指标 | Sharpe/回撤可解析；无异常报错栈 | 重生 |

反馈重生：把**失败原因 + STATISTICS 摘要（≤300 字）+ 原任务卡**作为新一轮 user 消息发同一会话（模型能看到上下文），最多 **2 轮**（服务端自身还有 ≤3 轮重生，叠加耗时可控在 10 分钟内）；每轮消息计数，逼近 50 条上限时自动开新会话并携带任务卡。

### 5.5 提示词与留痕

- prompt_version 升级为 `sentiment-intel-pack-v1`；保留旧版可切换，支持 A/B（同一情报包分别出码对比）。
- 新增落库：`prompt_version`、`agent`、情报包全文 JSON、信号面板因子清单（含命中率快照）、重生轮次、每轮回测指标。
- agent 建议固定一个做评估基线（`deepseek-chat` 走 DeepSeek、支持 3 个内置工具，可用于标的核验；待与对方确认线上路由与 licence 状态后锁定，见 §10）。

### 5.6 M1 验收标准

- [ ] 同一情报包连续生成 5 条策略：标的 100% 落在任务卡白名单内、成交笔数 >0、无 BusinessType 错配；
- [ ] 面板中每个因子都可点击溯源到事件研究记录（命中率/n）；
- [ ] 任意策略的情报快照可在我方页面完整复现当时输入；
- [ ] 前端可见"生成中/回测中/重生中/失败原因"实时状态（修 G7）。

## 6. L2：因子数值序列进回测（M2，约 2–4 周，依赖对方）

L1 的因子只影响"生成那一刻的策略文本"；L2 让 factor 模式策略在**回测的每个历史时点**读取因子值，从而能回测"情绪门控策略"本身。

### 6.1 事件流 → 日频因子序列的构造

1. **矩阵**：381 因子 × 交易日（先做通过事件研究检验的子集，约 10–30 个）。
2. **两类值**（与现有信号一致）：
   - presence：当日是否有该类事件（0/1，再做 λ=0.1 指数衰减）；
   - directional：事件方向（债市口径，多=收益率下行）的方向加权和/净值，衰减后取值 [-1,1]；阈值 0.3 离散化为 {-1,0,1} 或直接给连续值（由消费方选）。
3. **时间对齐**：用 `news_factor.pub_time`（不用入库时间/爬取时间），T 日盘中公布归入 T 日收盘后可得 → T+1 日交易可用，杜绝前视。
4. **模型分区**：在线抽取固定 GLM；历史回灌来自 doubao/deepseek，序列必须按 model 打标，评估时只在同模型区间内进行（沿用因子对接文档纪律）。
5. **历史长度约束**：回测区间不能超过因子序列覆盖长度；若事件数据仅覆盖近 1–2 年，回测窗口相应缩短，并在结果中标注统计显著性受限。

需要先补的我方接口（因子对接文档 §7-A 已提议）：`/sapi/factors/events`（事件时序，支持 model 过滤）、`/sapi/factors/signals/panel`（多因子日频面板）。

### 6.2 三条机器子路径（已核实，按推荐顺序）

| 路径 | 机制（已核实的契约） | 工作量 | 依赖对方 |
|---|---|---|---|
| **B1 qfm 推送（首选）** | 金工因子平台有推送表 `qfm_factor_info`（factor_id varchar32、名称、类型、频率、状态、ms 时间戳）与 `qfm_factor_data`（factor_id、calculate_time、**publish_time**、value_type、factor_value 数值/JSON；唯一键 factor_id+calculate_time） | 我方写推送客户端，每日增量推送 | 推送 API 地址/鉴权、factor_id 号段、value_type 字典、平台侧部署确认（现仅见测试库空表） |
| B2 mock_factor HTTP | 对方 C++ `MockMarketHttpSource` 从 `MOCK_MARKET_BASE_URL/api/v1/mock/standard/query?source=3&quotation_type=mock_factor&variety_code=X&start_date=2017-01-01&end_date=2027-01-01&page_index&page_size` 分页拉取，JSON 与 CMDS 标准 K 线兼容（因子值编码进 1 分钟 K 线 OHLCV） | 我方实现该 HTTP 服务（按其字段），对端设环境变量 | 由谁部署服务、网络放通、variety_code 命名约定 |
| B3 因子文件/FactorHandlerAPI | KSAPI FactorHandlerAPI 支持文件上传读取（Web 示例：factor_id_main + 活跃券组合） | 一次性文件较轻，不适合每日更新 | 上传入口、文件格式、factor_id 分配 |

B1 的优势：publish_time 字段天然表达"公布时点"，与我们防前视纪律一致；是金工平台生产级通道（同库现有 270 万+计算结果）。B2 更像测试/演示通道，但服务端代码现成。

### 6.3 factor 模式策略骨架（供提示词库预置）

```python
class SentimentGateT(SentimentStrategyTemplate):
    # factor_id 由金工平台分配后注入提示词，模型不自行编造
    factor_list = ['{factor_id_main}']
    variety_list = ['T主连']
    def on_factors(self, factors: dict, bars):
        gate = factors['{factor_id_main}'].value          # 已对齐 publish_time
        ma_cross = self.am.sma(5)[-1] > self.am.sma(20)[-1]
        if gate > 0.3 and ma_cross and self.get_pos(...) <= 0:
            self.buy(...)                                  # 情绪门控 + 技术触发
        elif gate < -0.3 or not ma_cross:
            self.sell_all(...)
```

- [ ] 前视抽查：随机 10 个时点，策略读到的因子值不超过当时最新公布值。

## 11. 红线与纪律

- **凭据纪律**：SSH/数据库/回测令牌/公钥值不进入代码库、文档、日志；联调只读对方环境，不做写入（建模板除外的正式业务调用）、不重启服务。
- **数据纪律**：固定单一抽取模型分区；统一 `pub_time` 防前视；因子命中率必须带样本量与置信区间，不使用未检验因子指导生成。
- **策略纪律**：新闻不单独触发交易；信号冲突降仓/空仓；频率匹配（小时舆情→日频）；0 成交不予通过。
- **对外口径**：研究辅助，非实盘系统；页面保留 AI 生成与回测风险提示。
