### 1.2 既有计划里还没做的（本计划要消化）

**后端 / 质量**

1. **代码静态检查未做**（优化方向 P0）：25 个历史模板 21 个零成交，病根之一是模型写出"只 `Debug` 打印、不调下单接口"的 POC 稿；现在没有任何发送前/回收后的静态拦截。
2. **账号级单飞未做**：现只有会话级锁；两个不同会话同时确认，第二个会撞对端 content_type=5"其他AI生成任务正在执行中"。需求文档 §3 已定调：**不做队列，直接友好拒绝 + 提示稍后重试**。
3. **验收门不校验"是否真用了指定标的"**：`expected_instrument` 参数空转，只做白名单集合检查（白名单是唯一防线，必须卡到"那一个"）。
4. **性能 P0 未做**：首次 DB 连接约 2s（连接池预热）；情报面板重复构建约 0.7s（带时间锚点的 60s 短缓存）。
5. **生成过程无真实进度**：对端推送的 generation_status 1/2/3（生成中/检查回测中/重生中）service 收到但不透传；前端 4s 整体重拉，只有一根静态灰条，无阶段、无耗时、无日志尾部、无退避、无超时上限、无"放弃等待"。
6. **情报包未做满**（实施方案 §5.2 的市场块/组合约束）：无信用利差、无期货持仓排名、无 forecast 准确率；portfolio_analysis 是独立功能、**完全没接线**到生成流程。
7. **结果数据未结构化**：逐笔成交、平仓原因、权益曲线都埋在回测日志文本里；28 个指标平铺、可疑值（Sharpe -234、波动率 0）一本正经展示。
8. **版本不可回溯**：API 已返回全部 versions/regenerations，页面只取 versions[0]，无版本切换、无重生记录展示。
9. 一批工程杂项：dream_strategy_prompt.py 常量重复定义两遍；`replace_prompt_draft` 死代码（且无"放弃草稿"接口，pending 后只能 confirm）；conversations.instrument 列恒 NULL；MIN_TRADES_PER_YEAR/PANEL_TOKEN_BUDGET 空定义；token 预算与路由生命周期零测试；新增接口后需重导 openapi.json（agent/MCP 依赖快照）。

**前端 / 体验**

10. 两个页面**零页面级测试**；样式是 1500+ 行全局 CSS 叠床架屋（同一选择器多处覆盖、`!important`）。
11. 列表页死控件："＋添加文件"无 handler、"仅未读"不生效、"会话/文档"视图切换无功能、归档筛选有 UI 无调用；无状态/验收结论/时间等有用列信息。
12. 提示词一大坨 ~3000 字 textarea，`[XXX]` 模板标记裸露，可编辑段无标识，无 token 用量条。
13. 失败时只有一行错误文案，无重试入口；交易参数在提示词缺块时显示**硬编码假默认值**，会被误读为模型输出。
14. 步骤导航可任意前点、未生成步骤空态；轮询无上限（后端 16 分钟 sweep，前端会一直转）。
15. 策略概要只是复述任务卡，没有"赌什么/何时会亏"的可信层；无买入持有基线对比。

## 2. 目标与非目标

### 目标

1. 策略生成页整体改版为**向导式工作台**：新手照着走得完，老手看得懂、改得动。
2. 结果页回答三个问题：**这策略在赌什么、凭什么、什么时候会亏**——核心指标置顶、成交可核查、异常不粉饰。
3. 消化既有计划 P0/P1：静态检查、真实进度、指标分层、提示词分段、版本回溯。
4. 全程可溯源、可复现；所有结论有依据，拿不到数据标"数据不可得"。

### 非目标（本期不做）

- **实盘**：对端 V2 无执行器，终点始终是"带回测报告的研究草案"，页面固定风险标注。
- 改对端 C++ / 破解 licence / 改接入协议主体（仅新增已核实的 160055 命令封装）。
- 因子数值进回测（L2/M2）：卡在对方 factor_id 号段，见 §7，只跟踪不排期。
- 不引入 antd 等组件库、不换主题色系、不改导航归属（/strategy 保持首页导航栏 tab）。
- 不做账号级队列（既有决策：拒绝并提示）。

**步骤定义与锁定规则**

| 步骤 | 内容 | 进入条件 |
|---|---|---|
| ① 需求与参数 | 一句话需求 + 标的/模式/周期 + 开平/仓位/止損止盈表单（去掉假默认值：缺块时显示"草稿生成后回填"） | 始终可进 |
| ② 情报与因子 | 因子信号面板表（方向/信号分/命中率(基准)/n/最近触发，行内展开依据）；任务卡/市场块/纪律**分段折叠只读**；顶部 token 用量条（已用/6000，≥80% 变黄）；相关新闻 | draft 生成后 |
| ③ 确认发送 | 提示词分段折叠：只有【用户需求】【交易参数】可编辑，改过的段标色条；"还原/重新生成/确认并生成" | draft 待确认 |
| ④ 生成与回测 | 真实阶段进度（情报装配/生成中/检查回测中/重生中/验收中）+ 已用时长 + 日志尾部快照 + 放弃等待（明确告知对端仍跑完）；轮询 4s、对齐 16 分钟上限后停轮询显超时态 | confirm 后 |
| ⑤ 结果报告 | 见 §3.3 | 有 version |

- 已完成步骤可任意回看；未解锁步骤不可前点（修复"空态随便跳"）。
- 失败不是独立步骤：④ 内嵌错误面板（对端原文 + 原因）+「重新生成」按钮；无成交走重生时显示"第 N 轮修正中"（不显示对端内部重试次数，沿用需求文档降级口径）。
- 底部 composer 发新需求 = 开新一轮，步骤轨回到 ①。

## 5. 阶段计划

### S0 · 链路实跑验证（0.5 人日，最先做，会在对端产生真实数据，需负责人点头）

1. 用默认 FCT_T_MAIN / bar / 1d 经页面完整跑一条，验证：回测令牌是否有效（会不会 401）、任务卡后是否真实成交、耗时、错误帧路径。
2. 取回 2–3 份真实回测日志（含历史 105/234 笔成交模板各一），冻结为 B2 解析器夹具。
3. 产出：一页实测记录（更新到认知文档 §7），若令牌缺失 → 升级为外部阻断，先找对方。

### S1 · 质量门与后端补全（约 2 人日，与 S2 设计并行）

B3 静态检查、B4 指定标的校验、B5 单飞友好拒绝、B7 性能、B9 清理；补测试：token 预算拦截、resolve_instrument 白名单、静态检查规则、路由 draft→confirm→version 生命周期（mock generate_strategy）。

**验收**：0 成交/演示稿在验收门与静态检查双处被拦；跨会话双发拿到友好 409；首请求不再付 2s 连接税。

### S2 · 向导式工作台改版（约 5–7 人日，主战役）

顺序建议：
1. tokens.css + 列表页去死控件/信息重排（1d）；

## 6. 整体验收口径

1. 新用户无帮助走完：输入需求 → 看情报 → 确认 → 等进度 → 看懂结果，全程不遇到死控件/空态/假数据。
2. 同一情报包连续生成 5 条：标的 100% 在白名单且等于所选标的；至少 4 条有成交（未达标归因情报质量 vs 平台，不硬凑 KPI——需求文档 §9 口径）。
3. 0 成交、回测失败、对端报错三类失败在 30s 内有明确结论与下一步动作，不出现 900s 空等。
4. 结果页每个数字可点到依据（日志原文/因子命中/情报快照），拿不到的显"数据不可得"。
5. 历史会话（含旧版本无 validation_json 的）打开不崩、降级文案正确。
6. CI 四道闸门全绿；新增/改动后端单测 + 两页页面级测试；无新增全局样式污染。

## 7. 风险与外部依赖

## 8. 工程纪律（沿用既有）

- 只改 Sentiment 仓库；不动对端、不破解 licence；联调只读，正式业务调用除外。
- 令牌/凭据不入库不入文档不入日志。
