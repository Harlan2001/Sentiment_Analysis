## 二、下周主要任务：数据分析智能体

下周我们最主要的工作就是推进巧巧老师提到的数据分析智能体，顺便可能还要做一些配套的智能体。**数据分析智能体是优先级最高的**。

简单来说，我们要关注这几个核心方面：

1. **先把数据准备好**：梳理清楚我们有哪些数据源（数据库、API、文件这些），把数据清洗、标准化、质量检查这些基础工作做好，确保进来的数据稳定可用。

2. **指标要统一说法**：把核心指标的计算口径统一好，常用的分析维度也整理出来，免得后面大家各算各的，同一个指标出来好几个结果。

3. **先从简单的做起**：先把基础的分析能力搞定（比如描述性分析、简单找原因），然后再慢慢加预测或者更复杂的分析功能。

4. **把经验存起来**：把我们已经有的分析经验和业务规则整理成结构化知识，下次分析的时候直接用，不用每次从头开始。

5. **要用起来方便**：支持大家用自然语言提问，而且给出来的结果要讲清楚结论是怎么来的，不能只给个答案就完事了。

6. **工具选合适的就好**：想想大模型、规则引擎和传统方法该怎么组合，别过度设计，用合适的工具解决合适的问题就行。

7. **要能撑得住后续发展**：考虑一下数据多了之后能不能处理得了，以后扩展到其他业务场景能不能复用。

8. **要知道做得好不好**：定好怎么评估效果（准不准、快不快、用得顺不顺），然后持续优化。

## 三、我们最终要做成什么样

目标很简单：打通一个完整流程 - **用户提问题 → 自动查数据 → 做分析 → 给出结论**，形成一个可以反复用的闭环，给后面做其他智能体打个样。

### 理想的使用体验是这样的：
> 用户不用写SQL，也不用懂很多数据分析知识，只要用平时说话的方式问问题就行，比如：
> - "最近一周哪个品类卖得最好增长最快"
> - "这次活动转化率怎么下降了呀"

系统就能自己查数据、做计算、分析，然后给你一个清楚的结论，还告诉你原因是什么。

说白了，就是把原来需要数据分析师做的一整套流程（**提需求 → 写SQL → 出报表 → 解读数据**）拆解开，能自动化的都自动化，提高效率，降低门槛，让业务部门能更快拿到结论。

## 四、火山智能体平台

### 为什么考虑用火山平台的HiAgent？

做数据分析智能体，如果我们从零开始自己写，所有组件都要自己搭，太费时间了。火山平台的HiAgent其实已经把智能体开发的基础设施都帮我们搭好了，用它的话，我们可以：

1. **更快上线**：不用从头造轮子，框架、调度、状态管理这些都已经做好了，我们专注在业务逻辑和工具开发就行
2. **企业级能力**：本身就是字节跳动火山引擎出品，有大模型支持，稳定性和扩展性都有保障
3. **降低开发成本**：很多常用功能（工具调用、记忆管理、流程编排）都内置了，开发起来事半功倍
4. **和自己开发比**：
   - 自己开发：需要搞定所有环节，周期长，维护成本高
   - 使用HiAgent：基于成熟平台快速搭建，我们聚焦业务，能更快验证想法

### 一个数据分析智能体，本质是什么？

不管用不用平台，核心架构其实都是这几部分：

`LLM + 工具系统 + 状态管理 + 执行策略`

基本流程：

```
用户提问
    ↓
[意图理解/规划]
    ↓
[工具调用层]
    ↓
[执行层]
    ↓
[记忆/状态管理]
    ↓
最终回答
```

我们一步步说：

#### 1. 意图理解（把人话转成任务）

**目标**：把用户说的大白话，变成机器能执行的分析任务

举个例子：
- 用户说："帮我看看最近一周用户增长怎么不正常了"
- 我们转成结构化的任务：

```json
{
  "task": "anomaly_detection",
  "metric": "user_growth",
  "time_range": "last_7_days"
}
```

**怎么实现**：
- 最常用的就是Prompt + LLM
- 也可以规则+LLM结合
- 有的会加上格式约束，保证输出对

这一层其实就是个**语义解析器**。

#### 2. 任务拆解（把大问题拆成小步骤）

复杂问题不可能一步做完，得拆成一个个小任务：

比如：
```
任务：分析用户增长为什么异常
↓
拆解：
1. 先把用户增长数据拿出来
2. 算一下环比同比
3. 找到异常的点
4. 分析为什么异常
```

输出大概就是这样：

```json
[
  {"step": "fetch_data", "tool": "sql_query"},
  {"step": "compute_metrics", "tool": "python"},
  {"step": "detect_anomaly", "tool": "python"},
  {"step": "generate_report", "tool": "llm"}
]
```

**怎么实现**：
- 常用ReAct或者Plan-and-Execute模式
- 工程化一点的话可以用DAG

说白了就是**把问题变成可执行的步骤图**。

#### 3. 工具层（真正干活的地方）

数据分析智能体的核心其实不是大模型，是工具：

常见工具类型：

**（1）数据查询工具**
- SQL查询（MySQL、ClickHouse这些）
- API或者数据仓库调用

```python
def run_sql(query: str) -> DataFrame
```

**（2）计算工具**
- Python的pandas/numpy做计算
- 各种统计函数

```python
def analyze(df):
    return df.describe()
```

**（3）可视化工具**
- matplotlib/echarts这些
- 输出图表JSON给前端

**（4）知识工具（可选）**
- RAG存业务指标解释
- 口径说明这些

**核心原则**：Agent就是让LLM来调度工具干活，不是让LLM自己算。

#### 4. 执行层（跑起来）

主要做这几件事：
- 调用工具
- 处理工具返回的结果
- 把结果再喂给LLM，继续下一步

典型的循环就是：

```python
while not done:
    LLM decide next step
    call tool
    get observation back
```

这就是我们常说的**ReAct模式**。

#### 5. 状态管理（记得自己干了啥）

数据分析得一步一步来，必须记住之前干了什么，所以得有状态管理：

- **短期记忆**：当前这轮分析的过程、中间结果、执行历史，存在会话里
- **长期记忆**（可选）：比如用户习惯、常用指标、数据结构这些

#### 6. 输出层（生成报告）

最终输出不能只给一句话，得是：
- 结构化的结论
- 好看的图表
- 指标解释
- 异常原因说明

比如这样：

### 用户增长分析报告

- 时间范围：2026-03-01 ~ 2026-03-07
- 异常日期：03-05
- 主要原因：投放渠道X流量突增

### 最小可用架构（MVP）

如果我们自己从零做一个最小系统，大概技术栈就是这样：

- LLM：OpenAI或者本地部署模型
- 编排：LangChain或者自己写
- 执行：Python
- 数据：SQL + pandas
