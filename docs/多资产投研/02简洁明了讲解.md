# 多资产投研引擎技术设计——简洁明了讲解

> 本文面向不熟悉金融和计算机的管理者，用通俗语言解释《02-多资产投研引擎技术设计-TDD》各模块准备怎样建设、为什么要这样建设，以及怎样保证系统可靠、安全并且不破坏现有业务。

## 一、先理解：TDD和PRD有什么区别

PRD主要说明“产品要提供什么能力、用户能做什么”。

TDD主要说明“系统内部怎样组织这些能力，才能把产品安全、稳定地做出来”。

可以把它们理解成：

- PRD像一份房屋需求：要几间房、给谁使用、需要哪些功能；
- TDD像一份施工设计：地基怎样建、水电怎样走、不同房间怎样连接、出现问题怎样维修。

TDD里虽然有很多英文名称和字段，但管理层不需要逐个记住。真正重要的是理解这套设计想解决哪些风险。

## 二、这份技术设计要解决的核心问题

当前系统已经有中国国债相关功能，但新闻、因子、预测、组合、报告和回测并不是一条完全统一的流程。新增美债、信用债和国债期货后，如果每类资产各自再做一套，很快会出现：

- 相同概念在不同模块里含义不一致；
- 同一条新闻被重复保存和重复计算；
- 中国和美国的时间对不上；
- 数据更新后历史报告无法复现；
- 数据不够时，AI被迫输出看似完整但不可靠的结果；
- 新功能改坏原有中国国债系统；
- 研究结果、历史统计和真实策略回测混在一起。

因此，这份TDD的核心思路是：

1. 先制定一套最小公共规则；
2. 每类资产保留自己的专业计算方式；
3. 新旧系统并行一段时间，通过转换层连接；
4. 所有重要结果保存时间、来源和版本；
5. 数据不足时允许降级或拒绝，不允许造数；
6. 第一版优先打通“市场研究—事件证据—研究判断—案例—报告”；
7. 预测、风险和策略等高级能力按真实条件逐步开放。

## 三、老板最需要关注的六个技术原则

### 1. 新系统不会直接替换旧系统

现有中国国债页面、接口、数据和策略链路继续运行。新增能力通过转换层读取旧数据，等新体系稳定后再讨论是否迁移。

### 2. 统一的是表达方式，不是强迫所有资产使用同一种算法

四类资产都要说明“研究对象、时间、来源、状态和版本”，但美债、信用债和国债期货仍使用各自适合的计算方法。

### 3. 每个高级能力前都有检查关卡

数据能展示，不代表可以用于分析；能分析，不代表可以做历史验证；能验证，也不代表可以进行正式策略回测。

### 4. AI负责理解和解释，程序负责正式数字

AI可以整理新闻、识别原因、提出候选情景，但正式风险、损益和回测数字必须由固定程序计算。

### 5. 历史结果不能被新数据覆盖

数据、预测、案例和报告都保留版本。以后数据修订时，生成新版本，而不是偷偷修改过去的研究结论。

### 6. 第一版不追求一次做完所有基础设施

只建设真实业务当前需要的表、接口和任务，避免先花大量时间建设一个过度复杂但还没有实际用户的“大平台”。

## 四、第1部分：设计背景是什么意思

这一部分是在诚实说明现有系统的真实状态。

目前中国国债相关功能分散在不同模块中：新闻分析、事件研究、预测、组合、报告和外部策略服务各自能够工作，但没有全部自动串起来。

新增资产也只有局部数据：

- 信用债有整体曲线；
- 国债期货有会员持仓排名；
- 美债有2年、10年和30年收益率。

系统当前还缺少统一的数据更新调度、完整历史修订记录、通用互联网搜索、组织级研究案例、多格式报告导出等能力。

这部分最重要的结论是：文档不会把“计划建设的能力”说成“现在已经具备的能力”。

## 五、第2部分：设计目标是什么意思

技术设计希望达到以下结果：

- 四类资产使用一套基本交流规则；
- 第一版能够完成从研究到正式报告的完整链路；
- 资产差异通过独立模块处理，不把所有算法硬凑成一样；
- 原有中国国债功能不受影响；
- 时间、方向、数据状态和能力状态都说清楚；
- 后台任务失败后可以安全重试；
- 新旧系统可以同时运行并逐步切换；
- 数据授权决定系统能否使用、保存和导出数据；
- 因子、预测、组合和风险都有明确版本；
- 研究组合不会被误做成真实客户账户。

简单说，就是要建立一个“可以扩展，但不混乱；可以使用AI，但不依赖AI造数；可以升级，但不破坏旧功能”的底座。

## 六、第3部分：哪些事情不在当前技术设计中完成

这部分限制技术范围，避免项目越做越大。

当前不做：

- 真实下单和订单管理；
- 把所有数据供应商强制改造成同一种接口；
- 让所有资产使用同一种收益计算方法；
- 一次性迁移全部旧数据；
- 在数据盘点前指定必须采购哪家供应商；
- 现在就锁死所有阈值、样本数、更新频率和存储期限；
- 第一版建设复杂审批平台、知识图谱或自动因果判断系统；
- 第一版建设真实持仓、实时强平和大型实时风险系统。

这些内容有些是未来可能建设，有些明确不属于本项目。当前设计只预留合理边界，不提前投入过多成本。

## 七、第4部分：总体架构和三类闭环

### 什么是总体架构

总体架构就是系统各部分怎样连接。可以把整个系统理解为一条有多个出口的加工链：

```text
外部或内部数据
→ 检查数据是否有权使用
→ 转换成系统能理解的统一格式
→ 分析事件、行情和影响因素
→ 形成研究、预测或组合风险
→ 输出报告，或在条件满足时进入策略回测
```

这不是要求所有任务必须自动连续执行，而是规定不同模块怎样共享数据和版本。

### 三类闭环为什么要分开

#### 研究闭环

回答“发生了什么、为什么、可能影响什么”。它可以使用定性分析，不要求一定有精确概率。

#### 统计验证闭环

回答“过去类似情况是否经常出现这种结果”。它需要足够的历史数据和正确的时间对齐。

#### 策略回测闭环

回答“如果真的按照一套买卖规则操作，过去可能获得什么结果”。它必须考虑具体交易对象、成本、成交和资金变化。

三类结果不能互相冒充。看到历史上经常一起变化，不等于已经证明一套策略能够赚钱。

## 八、第5部分：资产配置协议是什么意思

这里的“配置协议”可以理解成每类资产的一张统一说明卡。

每张卡会写明：

- 资产叫什么；
- 可以研究哪些具体对象；
- 默认看哪个对象；
- 使用哪个市场时区和交易日历；
- 重点研究哪些指标；
- 哪些数据模块和计算模块负责它；
- 当前能做到整体市场、行业、企业还是单只证券；
- 当前能力是不可用、部分可用、可研究、可验证还是可正式回测。

这样做的好处是，系统增加一种资产时，不需要到处修改含义，而是先补齐这张说明卡和专属模块。

它不是让所有资产变得一样，而是让系统知道“这类资产应该怎样被正确对待”。

## 九、第6部分：时间模型是什么意思

金融研究中，时间不只是一个日期。

一项信息可能有多个时间：

- 事情真正发生的时间；
- 官方或媒体发布的时间；
- 市场参与者最早能够看到的时间；
- 系统抓取到的时间；
- AI完成分析的时间；
- 研究人员作出判断的时间；
- 策略最早能够模拟成交的时间。

为什么要分这么细？

例如，一项数据在下午收盘后才发布，就不能假装当天收盘前已经知道并完成交易。美国和中国还有时区、夏令时、节假日和交易时段差异。

系统因此要做到：

- 保存原始时间和所属时区；
- 确认信息什么时候真正可用；
- 周末和节假日顺延到合理的交易时间；
- 中国和美国分别计算市场反应时间；
- 不确定信息可用时间时，只允许定性研究，不进入严格回测；
- 保留现有中国国债时间规则，通过兼容层说明其限制。

这个模块主要防止“拿后来知道的信息回到过去做出完美判断”。

## 十、第7部分：方向和目标指标是什么意思

系统需要把两个容易混淆的问题分开：

1. 一个数字准备上升还是下降；
2. 这种变化对市场意味着利好还是利空。

例如，“债券收益率上升”描述的是一个指标方向，但对债券价格通常是压力。用户实际赚钱还是亏损，还取决于他持有什么、方向如何。

因此每条判断都要写清楚：

- 研究的是哪个指标；
- 指标预计上升、下降还是无法判断；
- 从明确视角看属于利好、利空还是混合影响；
- 研究周期多长；
- 当前是已识别影响、证据不足、没有明显影响还是分析失败；
- 判断理由和失效条件是什么。

证据不足不能写成“没有影响”，没有分析也不能写成“市场中性”。

## 十一、第8部分：数据模型是什么意思

“数据模型”可以理解为系统内部准备建立哪些档案，以及每份档案至少要记录什么。

这一章不是说必须立刻建立几十张数据库表，而是先划清不同信息的边界。真正开发时只建设当前用例需要的最小部分。

### 8.1 数据来源、转换和授权

系统的数据可能来自：

- 公司购买的专业数据；
- 官方网站和公告；
- 按需互联网搜索；
- 用户上传文件；
- 公司内部数据；
- AI对已有材料的理解和解释。

每个来源都先经过授权检查和格式转换。系统要记录数据来自哪里、代表什么、使用什么单位、什么时候可用、质量如何，以及是否允许保存、展示、导出或发送给外部AI。

如果两个来源数值冲突，不能直接平均或覆盖，而是保留各自原值，并按事先规则选择或阻断。

### 8.2 系统准备保存哪些主要档案

#### 资产档案

记录中国国债、信用债、国债期货和美债等大类资产的名称、时区、交易日历和当前是否启用。

#### 具体研究对象档案

记录10年期国债、某个期货合约、某条信用债曲线等具体对象，以及币种、期限、评级和行业等信息。

#### 市场原始观察档案

保存某个对象在某个时间的一个真实指标值，并记录来源、单位、数据批次和质量问题。

#### 市场表现档案

保存一段时间内指标怎样变化。不同资产仍由各自计算程序负责，统一档案不代表所有变化可以直接比较。

#### 事件、证据和影响档案

公共事件只保存一次，再关联新闻、政策、研报、行情等不同证据。系统另外保存该事件对每类资产的独立影响判断。

同一事件可以有支持证据、反对证据和补充证据。没有影响记录不等于没有影响。

#### 因子档案

保存可能影响市场的原因或主题，并记录不同叫法、审核过程、当前状态和适用范围。一个因子在美债中失效，不代表它在所有资产中都要删除。

#### 跨资产传导档案

保存一个事件可能怎样影响其他资产，同时注明这只是理论机制、AI推断、个别案例还是历史统计支持，不能把相关性写成确定因果。

#### 历史有效性档案

记录某个因素在指定资产、指标和周期中的历史表现，包括样本数、命中情况、市场阶段和不确定性。

#### 预测档案

每次预测单独保存研究对象、期限、数据截止时间、证据、模型、结果状态和失效条件。数据不足时，概率、幅度等字段可以为空，不能用默认数字补齐。

#### 预测能力清单

记录哪些资产、指标、周期和预测类型已经满足条件。新增资产没有登记并通过检查时，不能生成正式预测。

#### 策略标的能力清单

记录某个具体交易对象究竟只是配置过、完成基础测试，还是已经满足正式研究回测要求。白名单、接口能接收或单次运行成功，都不等于正式支持。

#### 策略业务版本和执行尝试

用户确认的策略规则形成一个业务版本。如果只是网络失败重试，属于同一版本的新执行尝试；如果资金、标的、规则或成本发生变化，就必须形成新版本并重新确认。

#### 回测运行档案

分别保存任务是否完成、研究质量是否合格以及历史表现好不好。程序成功运行不等于研究可靠，研究可靠也不等于策略赚钱。

#### 策略情报包

只挑选与当前策略有关的数据、证据和限制，不把所有新闻和数据全部塞给AI。用于过去某个时间点的内容只能包含当时已经知道的信息。

#### 研究组合和模拟持仓档案

区分目标配置和模拟持仓。权重、假设资金、数量、面值、市值、成本、期货手数、名义金额和保证金分别保存，不能混成一个金额。

真实持仓只预留未来接口，第一版不开放真实账户模式。

#### 风险结果档案

保存风险种类、数值、单位、币种、市场、参数来源、计算方法、覆盖范围和缺失原因。不把所有风险压成一个简单总分。

#### 情景分析档案

保存“假设市场发生某种变化”的定义、运行过程和估算结果。AI只能提出候选情景，正式损益数字由固定程序计算。

#### 研究案例档案

案例保存对事件、证据、预测、组合、风险和报告等固定版本的引用，不复制底层内容。底层内容更新时，旧案例不会自动变化。

#### 监测规则和提醒档案

保存用户关注什么、在什么条件下提醒、按什么频率检查、怎样避免重复提醒。日频数据不能标成实时监测，提醒不会自动触发预测或交易。

#### 正式报告和导出档案

正式报告固定使用的案例、数据、证据、模型和计算参数。重新生成产生新版本。导出时再次检查权限和数据许可。

#### 删除记录

记录什么内容被软删除、恢复或永久删除，以及报告、缓存和搜索结果是否同步处理。授权到期后只能保留不泄露内容的最小记录。

### 8.3 四级数据检查关卡

系统把数据使用能力分成四层：

1. **展示级**：数据可以合法、正确地显示；
2. **分析级**：数据足以支持研究解释；
3. **验证级**：历史数据足以支持正式统计检验；
4. **交易级**：具体标的、行情、规则、成本和成交条件足以支持正式策略回测。

上一层通过不代表下一层自动通过。局部数据有问题时，只关闭受影响的功能，不把整个资产页面全部关闭。

### 8.4 原始数据、修订和研究快照

在授权允许的情况下，系统保留数据原始批次、修订关系和研究使用版本。

“研究快照”就像在研究发生时拍一张照片，记录当时实际看到了哪些数据。以后数据被修改，仍然可以复查当时的判断。

第一版只保存必要版本和引用，不提前建设庞大的完整数据仓库。

### 8.5 新旧系统怎样兼容

第一阶段不直接搬迁中国国债旧表，而是建立一个转换层，把旧结果翻译成新系统能够读取的格式。

这样可以：

- 保持旧页面和旧接口继续运行；
- 新资产使用新规则；
- 避免一次性修改大量历史数据；
- 等公共引擎稳定后，再决定是否迁移旧数据。

### 8.6 组合、多币种和风险怎样兼容

现有人民币研究组合保持原样。新增多资产组合通过旁路方式逐步扩展。

美债首先保存美元结果。如果换算成人民币，要另外保存汇率来源和时间；美元利率风险和中国利率风险不能因为都换算成人民币就合成同一种风险。

## 十二、第9部分：服务分层是什么意思

服务分层就是把系统按职责拆成多个相对独立的工作部门，例如：

- 数据接入部门负责取得和整理数据；
- 市场部门负责行情和市场表现；
- 事件部门负责事实、证据和影响分析；
- 因子部门负责影响因素；
- 预测部门负责有条件的预测；
- 组合、风险和情景部门负责模拟研究；
- 回测和策略部门负责高级策略能力；
- 报告部门负责案例、报告和导出。

每个部门有清楚的输入和输出。某一资产需要特殊算法时，可以替换该资产的专属组件，不必修改整个系统。

这样做的好处是：职责清楚、容易测试、故障不容易扩散，也便于逐步开发。

## 十三、第10部分：API设计是什么意思

API可以理解为页面和后台之间约定好的“服务窗口”。

例如页面要查询美债行情，会去对应的行情窗口；要生成报告，会向报告窗口提交任务。

技术设计提前规划了资产、行情、事件、证据、因子、预测、组合风险、情景、策略、案例、提醒和报告等窗口。

这些地址是目标设计，不代表现在已经全部实现。没有真实数据或计算能力的窗口，不能返回占位数字。

耗时很长的操作不会让网页一直卡着等待，而是：

1. 页面提交任务；
2. 后台返回一个任务编号；
3. 后台继续处理；
4. 页面根据任务编号查询进度和结果。

## 十四、第11部分：事件分析、因子治理和跨资产传导

### 11.1 事件分析

系统先识别事实，再核查来源、删除重复内容、关联证据，最后分别判断对不同资产的影响。

新闻和政策可以形成候选事件；研报通常先作为观点和研究证据。研报中的事实只有经过核实后，才能升级为公共事件。

AI输出必须引用原文，并区分事实、观点、预测和市场预期。不同资产的具体方向由资产专属规则处理。

### 11.2 因子标准化

AI可能对同一个因素使用不同叫法。系统先保留原始叫法，再尝试匹配标准名称。

不能只因为两个词看起来相似就自动合并，也不能把“已经发生”和“市场预期会发生”混成同一个因素。

### 11.3 自动审核和生命周期

新因子先由一个任务提取，再由独立审核和程序规则检查。审核冲突或证据不足时保留为候选，不直接发布。

正式因子以后可以进入休眠、观察、暂停、合并或退休状态。低活跃或样本少不能直接导致退休，所有状态变化都保留历史。

### 11.4 三个评价维度

系统分别评价：

- 某一个事件重要不重要；
- 某个因素最近出现得多不多；
- 某个因素过去是否真的有效。

三者不能互相替代，也不会强制合成一个看似简单但缺乏依据的总分。

### 11.5 相反信号

只有研究对象、指标和时间范围都一样时，相反结论才叫直接冲突。

如果短期和长期结论不同，或者美债和中国国债方向不同，可能只是周期或资产差异，不应简单标红为冲突。

### 11.6 跨资产传导

系统可以使用通用模板提出候选解释，例如“美国利率变化可能影响国内债市”，但每次具体事件仍要重新判断是否适用。

页面同时展示文字解释和结构化关系，但不会建设复杂图数据库，也不会把历史相关直接说成确定因果。

## 十五、第12部分：市场表现、历史相关和事件研究

### 市场表现

每类资产用自己的计算方式回答“这段时间发生了什么变化”。

- 中国国债和美债可以先看收益率变化；
- 信用债可以看整体曲线和条件满足后的信用利差；
- 国债期货当前可以看会员持仓变化，价格收益要等待价格数据。

统一输出格式只是为了便于管理，不代表这些不同指标可以直接相加或排名。

### 三类结果必须分开

#### 历史相关性

说明两个指标过去是否经常一起变化，不证明谁导致谁。

#### 事件研究

说明一类事件发生以后，市场通常怎样变化，不代表能够按该结果真实成交。

#### 策略回测

使用具体买卖规则、行情、成本和成交条件模拟过去的交易。

### 事件样本怎样管理

系统会去掉重复新闻、识别主事件和后续事件、记录窗口重叠和干扰因素，并事先定义样本筛选规则。

不能看到结果后再决定哪些样本保留，否则会让统计结果看起来虚假优秀。

## 十六、第13部分：回测框架

### 13.1 哪些标的允许正式回测

每个具体交易对象都有能力等级。只有真实标的映射、行情、成本、成交、结算和安全检查都通过，才能进入正式研究回测。

系统不会因为某个别名、白名单或单次成功就自动升级能力。

### 13.2 策略情报包

系统只向策略服务提供与当前需求有关的市场数据、证据和限制。

历史回测只能看到当时已经存在的信息。今天的新闻、预测和风险不能放进过去的决策中。

### 13.3 业务版本和执行尝试

用户确认的是一套明确的业务规则。标的、资金、时期、参数、仓位或成本变化时，必须形成新版本并重新确认。

网络重试属于同一业务版本的新执行尝试，不能因为第一次结果亏损就当成“技术重试”偷偷改参数。

### 13.4 外部执行和AI代码安全

DreamStrategy属于外部服务。正式能力需要确认它怎样隔离文件、密钥、网络、资源和不同用户数据。

如果安全边界无法验证，结果只能标成实验。AI生成的代码和外部返回内容始终当成不可信输入继续检查。

### 13.5 回测必须考虑四类金融模型

- **成本**：手续费、买卖价差、滑点等；
- **成交**：订单什么时候、按什么价格成交，是否可能无法成交；
- **结算**：资金、持仓、保证金、到期和换月怎样变化；
- **核算**：价格损益、利息、违约、外汇和现金流怎样计入收益。

如果外部服务无法真正应用这些规则，只能输出理论或实验结果。

### 13.6 怎样评价回测

系统分别判断：

- 任务有没有正常完成；
- 数据和方法是否达到正式研究质量；
- 策略过去的表现是好、差、不稳定还是证据不足。

三者不能互相推导。一个亏损但计算严谨的回测仍然是有效研究。

### 13.7 国债期货套保

套保分为三个层次：

1. 文字说明可以怎样降低风险；
2. 数据允许时计算大致需要多少期货合约；
3. 条件完整后进行正式历史套保回测。

国债期货通常只能降低匹配的利率风险，不能消除信用债的违约、信用和流动性风险。

## 十七、第14部分：预测框架

### 保留现有中国国债预测

现有中国国债10年期日、周、月预测继续运行。新预测框架通过转换层读取，不直接改写旧逻辑。

### 新资产预测先检查能力

系统先确认某个资产、指标、周期和预测类型是否已经开放。文字分析、方向、概率、幅度和区间预测分别检查。

### 证据从哪里来

优先使用已授权专业数据、库内新闻、行情和政策。必要时才进行联网搜索，并优先核查官方来源。

搜索失败后可以继续、降级或拒绝，但不能补造事实。

### 可以降级或拒绝预测

如果精确概率条件不足，可以降为方向判断或文字分析。关键数据缺失时可以拒绝预测，并告诉用户缺什么、满足什么条件后可以恢复。

### 多个模型不直接投票

不同模型的结果分别保存。只有比较口径、权重和历史表现都明确时才能生成综合结论，否则保留分歧。

### 预测要接受事后检验

方向、概率、幅度和区间使用不同方法评价，同时统计拒绝和降级比例，防止系统只挑容易的情况展示好成绩。

## 十八、第15部分：组合风险与情景分析

### 15.1 组合模式

目标配置用于表达理想比例，模拟持仓用于表达具体假设持仓。不同资产要求的字段不同，例如期货必须写具体合约、手数和多空方向。

现有CSV继续兼容，但不会被误解为完整多资产持仓文件。

### 15.2 利率风险

系统逐步计算债券或期货对利率变化的敏感程度。正式计算需要可靠市值、久期或期货风险参数。

现有用户手工填写的久期类型不明确，因此不能直接拿来生成正式风险金额。

### 15.3 覆盖率和降级

如果组合里只有部分资产能计算，系统显示这部分结果、覆盖比例和缺失原因。

不同类型资产的覆盖比例不能直接相加，缺失值也不能当成零风险。

### 15.4 不同资产的专属风险

- 信用债关注利率、信用利差、评级、企业、行业和期限集中；
- 国债期货关注合约方向、保证金、杠杆、到期、换月和基差；
- 美债先关注美元利率和期限风险；
- 流动性风险必须有成交、价差等真实数据支持。

### 15.5 美债人民币视角分层开放

美债能力按以下顺序逐步开放：

1. 美元角度研究；
2. 按即期汇率折算成人民币金额；
3. 计算人民币未对冲投资回报；
4. 计算汇率对冲后的回报。

后两层需要更完整的价格、现金流、远期汇率和成本数据，不能把简单汇率换算说成完整投资回报。

### 15.6 情景分析

系统先读取已经确认的市场变化假设，再调用各资产计算程序，最后汇总能够可靠计算的部分。

如果风险参数不全，就只显示已覆盖部分。AI可以提出候选情景，但不能直接写正式损益数字。

## 十九、第16部分：前端页面怎样复用

### 16.1 保留现有页面结构

现有一级导航、路由和数据展示全部保留。新增资产通过子标签、卡片和详情入口加入。

没有完成的数据能力可以先设计入口，但不能展示虚假行情或结果。

### 16.2 页面之间怎样保留研究对象

页面链接会明确携带资产、标的、日期、快照和版本等必要信息。

历史结果优先按固定版本恢复，而不是打开同一天的最新数据。旧链接不带这些信息时，继续保持原有默认行为。

### 16.3 统一证据详情

用户可以从事件、因子、预测或报告进入证据详情，再返回原来的研究位置。

新闻、政策、研报、行情和统计结果仍使用各自适合的展示方式，不因为入口统一就把专业信息压成同一种页面。

### 16.4 传导和冲突怎样展示

系统使用容易阅读的传导链卡片和关系表，不建设复杂关系图。

理论机制、AI推断、个别案例和历史统计会使用不同标签。期限或资产不同造成的方向差异不会误标为直接冲突。

### 16.5 页面状态怎样说人话

客户主要看到六类状态：

- 缺少必要数据；
- 只有部分结果；
- 有数据但质量不足；
- 只能提供较低层次分析；
- 请求因业务规则被拒绝；
- 系统发生技术错误。

这些状态与“功能还在开发”不同。预留入口不能用模拟数据假装已经实现。

### 16.6 专业页面、案例、提醒和报告

预测页面展示结论、证据和限制；组合页面展示模式、币种和风险覆盖；策略页面展示用户确认内容和回测状态。

任何页面都可以把固定版本结果加入研究案例。案例默认属于个人，也可以关联项目。

关注列表保留普通收藏，并增加条件提醒；提醒只进入研究流程，不自动触发金融任务。

正式报告与动态最新视图分开，导出时显示权限和许可检查结果。

## 二十、第17部分：后台任务和调度

许多工作不能在用户点击按钮后立即完成，例如下载大量数据、调用AI、运行回测或生成报告。

这些工作会作为后台任务运行。系统记录：

- 任务是谁发起的；
- 处理到哪一步；
- 是否还在正常运行；
- 是否失败和为什么失败；
- 是否可以安全重试；
- 重试会不会产生重复结果。

数据更新频率按真实来源决定，不要求所有内容实时更新。日频数据按日处理，事件搜索按研究需要触发。

系统使用“唯一任务身份”避免同一请求被重复执行。规则或数据版本真的变化时，才创建新运行。

持续提醒也不能比数据更新得更频繁，并且只生成研究提示，不会自动启动预测、策略或交易。

## 二十一、第18部分：怎样知道系统运行是否正常

“可观测性”可以理解为给系统安装仪表盘和行车记录仪。

管理和运维人员需要看到：

- 各资产的数据最新到哪一天；
- 数据同步成功率和耗时；
- AI任务失败率；
- 预测正常、降级、拒绝和失败的数量；
- 回测处于什么状态；
- 页面是否经常没有数据；
- 案例引用是否失效或无权访问；
- 提醒是否大量重复；
- 报告导出为何被过滤或拒绝。

每次运行还要留下可追踪日志。数据长时间不更新、任务连续失败或系统资源异常时，系统主动向运维告警。

普通策略因为没有信号而零交易，不应该误报成系统故障。

## 二十二、第19部分：安全与合规

主要安全要求包括：

- 密码、密钥和供应商凭据不能写在普通代码或页面里；
- 数据供应商许可必须落实到系统权限；
- 外部AI和策略服务只能接收获准传输的内容；
- AI代码、用户输入和外部返回都按不可信内容处理；
- 上传文件检查类型、大小和内容；
- 策略确认、重试、取消、删除和导出留下审计记录；
- 未授权真实持仓不得发送给外部AI；
- 看案例的权限和看底层数据的权限分别检查；
- 项目成员权限变化后立即生效；
- 查看、研究使用、导出和再分发是不同权限；
- 删除或授权到期时同时处理原始数据、报告、导出文件和缓存。

这部分的目标是：即使研究内容被分享、导出或交给外部模型，也不能绕过原来的数据权限。

## 二十三、第20部分：系统准备怎样测试

测试分成四个层次。

### 1. 小模块测试

分别检查时间转换、方向规则、汇率换算、风险计算、预测状态、权限判断等小功能是否正确。

### 2. 模块之间的约定测试

检查数据接入、页面接口、外部策略服务等双方是否按照同一规则交流，防止一方认为单位是百分比，另一方认为是小数。

### 3. 多模块联合测试

检查一整段流程能否正确连接，例如数据进入系统后，能否形成事件、证据、预测、案例和报告，并在权限变化后正确处理。

### 4. 完整用户流程测试

第一里程碑至少要真正走通：

```text
市场研究
→ 事件和证据
→ 因子或定性判断
→ 研究案例
→ 正式报告
```

即使没有AI预测和统计结果，这条链路也要能够完成。同时验证新增功能没有破坏中国国债现有页面、组合、预测、策略和回测。

## 二十四、第21部分：迁移和实施计划

推荐实施顺序是：

```text
最小公共能力 → 美债 → 国债期货 → 信用债 → 跨资产深化
```

这不是严格串行。各资产的数据接入、页面和独立模块可以并行。

### 阶段A：最小公共能力

建立最少的资产、时间、数据、事件、证据、因子、案例和报告规则，先打通首个研究闭环。旧中国国债通过只读转换层接入。

### 阶段B：美债

利用已有2年、10年和30年收益率验证多资产公共架构、中美时间差、案例和报告流程。

### 阶段C：国债期货

逐步补充合约、价格、换月、保证金和成本能力。定性套保和静态估算先行，完整历史套保回测后置。

### 阶段D：信用债

先复用整体信用曲线，再按数据授权增加评级、行业、期限、企业和单券能力。

### 阶段E：收敛和深化

公共引擎稳定后，再评估是否迁移旧中国国债数据、减少重复接口，并深化跨资产报告、组合、提醒和策略协同。

## 二十五、第22部分：如果新功能出问题怎样回退

新功能按资产单独设置开关。某一新增资产出现问题时，可以只关闭该入口，不影响其他资产。

新旧接口会并行一段时间；新表写入失败时，旧中国国债链路仍然工作。

数据迁移使用可以重复、安全执行的工具，不直接删除旧表。

回滚方案的目标是：新功能上线失败时可以退回原状态，而不是被迫停掉整个网站。

## 二十六、第23部分：还有哪些内容等开发阶段确认

TDD最后列出的31项待确认问题，大部分属于实现参数，不再是顶层产品方向。可以归纳为：

### 数据和采购

- 公司现有供应商能提供什么；
- 是否需要新增采购；
- 数据允许怎样保存、展示和导出；
- 各类数据多久更新一次、保留多久。

### 具体计算规则

- 各资产的收益、风险和回报公式；
- 历史样本和质量门槛；
- 预测概率怎样校准；
- 不同模型怎样形成综合结论；
- 监测阈值和提醒频率。

### 外部服务能力

- DreamStrategy具体支持哪些标的；
- 是否真正考虑成本、成交、结算和换月；
- 外部代码执行是否安全、可取消、可查询和可去重。

### 数据保存和权限

- 研究案例、提醒、报告和导出文件具体存在哪里；
- 恢复窗口和永久删除规则；
- 哪些内容允许查看、研究、导出和再分发。

### 报告交付

- PDF、Word、Excel、CSV和Markdown先实现哪些；
- 不同格式承载什么内容；
- 大报告怎样在后台生成和交付。

这些问题在数据盘点、接口设计和具体开发迭代中确定，不需要现在虚构答案。

## 二十七、管理层可以怎样理解这份TDD的最终价值

### 对业务的价值

- 新增资产不会各自形成信息孤岛；
- 研究结论能够追查证据和历史版本；
- 数据不足时仍可完成定性研究，但不会输出假数字；
- 报告可以复现，不会被最新数据自动改写；
- 高级预测和策略能力只有真正验证后才开放。

### 对研发的价值

- 每个模块职责清楚，可以分阶段开发；
- 旧系统有兼容层保护，降低改造风险；
- 不同资产可以并行接入；
- 数据、权限、版本、任务和错误状态有统一规则；
- 新功能失败时可以单独关闭和回退。

### 对管理层的价值

管理层不仅能看到“系统生成了什么结果”，还能够知道：

- 这个结果使用了什么数据；
- 数据是否完整和有权使用；
- 是定性分析、历史验证还是正式回测；
- 哪些部分由AI解释，哪些数字由程序计算；
- 结果能否复查、导出和对外分发；
- 哪些能力已经验证，哪些仍受数据和外部服务限制。

## 二十八、常用技术词语的简单解释

| 词语 | 简单解释 |
|---|---|
| TDD | 技术设计文档，说明系统内部准备怎样建设。 |
| 架构 | 系统各模块如何分工、连接和共同运行。 |
| 数据模型 | 系统准备保存哪些类型的档案，以及每类档案至少记录什么。 |
| 适配器 | 转换层，把不同来源或旧系统的数据翻译成统一格式。 |
| API | 页面、后台或外部系统之间约定好的服务窗口。 |
| 协议/契约 | 双方约定必须提供哪些信息、信息代表什么。 |
| 快照 | 固定保存某个时点实际使用的数据和条件。 |
| 版本 | 重要修改后保存一个新副本，不覆盖历史结果。 |
| 幂等 | 同一请求意外重复执行时，不会产生重复业务结果。 |
| 后台任务 | 耗时工作在服务器后台运行，页面通过任务编号查看进度。 |
| 调度 | 决定任务什么时候运行、失败后是否重试。 |
| 日志 | 系统运行记录，用于追查谁在什么时间做了什么。 |
| 监控 | 持续观察数据和任务是否正常。 |
| 告警 | 系统异常时主动通知运维人员。 |
| 门控 | 在进入更高级能力前进行条件检查，不满足就降级或阻断。 |
| 降级 | 条件不足时提供较低层次但仍有依据的结果。 |
| 沙箱 | 把外部或AI代码限制在隔离环境中，防止访问敏感资源。 |
| 回滚 | 新功能发生问题时安全退回原有状态。 |
| Feature flag | 单独控制某项新功能是否启用的开关。 |
| PnL | 策略或持仓的损益，不能用普通指标变化冒充。 |
| DV01 | 利率变化一个很小单位时，债券或组合价值大约变化多少。 |
| 覆盖率 | 一项计算实际覆盖了多少应该计算的资产或持仓。 |
| 数据截止时间 | 一项研究最多使用到哪个时间的数据。 |
| 研究案例 | 把一次研究使用的事件、证据、判断和结果按版本组织起来。 |
