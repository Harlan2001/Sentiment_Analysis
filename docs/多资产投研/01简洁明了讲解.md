# 多资产固收投研平台需求文档——简洁明了讲解

> 本文面向不熟悉金融和计算机的管理者，用通俗语言解释《01-多资产固收投研平台需求文档-PRD》各模块要建设什么、为什么需要，以及第一阶段准备交付什么。

## 一、这个项目一句话是什么

我们要把目前主要服务于中国国债研究的系统，扩展成一个可以同时研究以下四类资产的工作平台：

- 中国国债；
- 信用债，也就是企业或机构发行的债券；
- 中国国债期货；
- 美国国债。

这个平台不是替客户买卖债券的软件，也不是自动交易机器人。它更像一个“研究助手和研究工作台”：帮助研究人员发现市场发生了什么、为什么发生、可能影响哪些资产、证据在哪里，并把研究过程整理成可以复查的案例和正式报告。

## 二、老板最需要先知道的五件事

### 1. 我们不是推倒重做

现有中国国债页面、数据、预测、组合、策略生成和回测功能都要保留。新增功能是在原有网站里逐步增加，不重新建设一套网站，也不破坏已经能使用的能力。

### 2. 第一版重点不是“预测涨跌”，而是把研究流程走通

第一版要优先打通下面这条链路：

```text
看到市场变化
→ 找到相关事件和证据
→ 总结主要影响因素，必要时给出预测
→ 保存成一个研究案例
→ 生成一份正式报告
```

如果数据还不足以支持精确预测，系统仍然可以给出有证据、有边界的文字分析并生成报告。不能因为暂时算不出概率或精确数值，就让整个研究工作无法继续。

### 3. 系统必须诚实表达能力

有真实数据就展示真实结果；数据不完整就说明缺什么、哪些结论只能作为参考。不能为了让页面看起来完整而编造行情、风险、预测或收益。

### 4. AI负责辅助理解，正式数字由可靠程序计算

AI适合阅读新闻、整理观点、解释事件、提出可能的研究方向。涉及正式风险金额、组合损益、回测收益等数字时，必须由固定、可检查的程序计算，不能让AI随口给数。

### 5. 最终产品会完整设计，但开发分阶段进行

组合风险、持续提醒和新增资产的策略回测都有完整的产品设计和入口规划，但不要求第一版全部做完。开发顺序暂定为：

```text
公共基础能力 → 美债 → 国债期货 → 信用债
```

这个顺序可以根据客户需求、数据授权和开发条件调整，各资产也可以并行推进。

## 三、用一个例子理解整个平台

假设美国公布了一项重要通胀数据，结果明显高于市场原来的预期。

系统希望完成的工作是：

1. 收集这项数据的官方发布、相关新闻和研究观点；
2. 分清哪些是已经发生的事实，哪些只是媒体或分析师的判断；
3. 判断它可能怎样影响美国国债收益率；
4. 进一步分析它是否会影响中国国债、国债期货和信用债；
5. 展示支持和反对这些判断的证据；
6. 如果数据条件足够，可以查看过去类似事件发生后的市场表现；
7. 如果条件还不够，就只给出定性解释，不编造精确概率；
8. 将本次研究保存成一个案例；
9. 生成一份固定版本的正式报告，之后数据更新也不会偷偷改写这份历史报告。

这就是PRD中所说的“完整研究闭环”。

## 四、PRD第1部分：项目背景是什么意思

### 当前已经有什么

目前系统围绕中国国债已经有不少功能，例如新闻分析、因子、收益率研究、预测、研究组合、报告和策略回测。但这些能力并不是一条完全自动串联的生产线，有些页面和流程相对独立。

另外三类资产已经有一些基础数据：

- 信用债：有整体收益率曲线和信用利差，但还没有评级、行业、企业和单只债券的完整研究；
- 国债期货：有中金所会员持仓排名，但缺少完整价格、换月、基差等数据；
- 美债：有2年、10年、30年收益率和中美利差，但缺少完整的美国事件研究和预测链路。

### 为什么要做这个项目

客户研究时不会只看一种资产。例如美国利率变化，可能影响美债，也可能影响中国国债和国债期货；国内资金变化又可能影响信用债。因此，需要把原来分散的信息连成一个能够跨资产研究的平台。

### 核心要求

扩展新资产时必须保护原有中国国债功能。我们采用逐步扩展方式，而不是一次性重写整个系统。

## 五、PRD第2部分：产品目标是什么意思

### 目标一：帮助研究员快速看懂市场

系统要回答几个最基本的问题：

- 今天哪些资产出现了值得关注的变化？
- 为什么会变化？
- 这个解释的证据是什么？
- 它还可能影响哪些资产？
- 哪些结论比较可靠，哪些只是待验证的判断？

### 目标二：让研究过程能够保存和复查

一项研究不能只留下最终一句结论。系统还要保存当时看到的数据、新闻、模型和分析条件。以后再看这份报告时，可以知道当时为什么得出这个判断。

### 目标三：逐步开放高级能力

统计验证、精确预测和可交易策略属于更高级的能力，必须等历史数据、市场价格和外部回测服务真正满足条件后再开放。

### 怎样才算成功

不是页面越多越成功，而是至少做到：

- 能从市场变化找到事件和证据；
- 能形成有依据的研究判断；
- 能保存研究案例并生成正式报告；
- 数据不足时明确说明，不无限加载，也不输出假结果；
- 原有中国国债功能继续正常使用。

## 六、PRD第3部分：哪些事情暂时不做

这部分是为了防止项目范围无限扩大。

第一阶段明确不做：

- 不接券商或交易所进行真实下单；
- 不建设真实客户账户、真实成交和实时盈亏系统；
- 不做信用债逐笔高频交易；
- 不做国债期货分钟级高频量化交易；
- 不建设非常庞大的知识图谱或自动因果判断系统；
- 不根据一条新闻自动买入或卖出；
- 不抓取没有授权的数据；
- 不把研究人员手工建立的模拟组合说成真实投资账户。

简单来说：这是投研和决策辅助平台，不是完整投资管理系统，也不是实盘交易系统。

## 七、PRD第4部分：谁会使用这个平台

### 第一类：固收研究员

这是最主要的用户。他们需要发现变化、解释原因、核查证据、比较历史情况并形成研究报告。

### 第二类：投资经理

他们更关心研究结论对资产配置和组合风险意味着什么，例如当前组合对利率变化是否过于敏感。

### 第三类：量化或数据研究员

他们关心数据是否准确、样本是否足够、计算方法是否合理，以及结果能不能重复得到。

### 第四类：债券交易员

他们关心具体交易标的、成本、成交限制和策略风险，但只有在相关能力经过验证后才开放正式回测。

### 用户通常会怎样使用

用户可能从首页发现异常，然后依次查看市场、新闻、事件、影响因素、历史表现和预测，最后把重要内容放入研究案例、组合或报告中。

## 八、PRD第5部分：产品必须遵守的原则

### 1. 页面可以统一，但不能混淆不同资产

四类资产可以使用相似的页面操作，但它们的价格、收益和方向含义不同。例如债券收益率上升通常意味着债券价格承压，不能简单把“数值上升”都解释成利好。

### 2. 每个结论都能找到证据

用户看到一个判断后，应该能够继续点进去，看到原始新闻、政策文件、行情或计算结果。

### 3. 不能用后来知道的信息假装当时已经知道

做历史分析或回测时，只能使用当时真实能够获得的信息，不能拿事后数据美化过去的结果。

### 4. 新闻不能直接触发交易

新闻可以提醒研究员、影响研究判断，但不能自动生成并执行交易。

### 5. 没有数据就明确说没有

系统可以显示“数据缺失”“只能分析一部分”或“证据不足”，但不能把缺失当成零，也不能用AI补造。

### 6. 研究和真实交易分开

平台可以给出研究建议、模拟结果和风险提示，但不会替客户真实下单。

### 7. 保留现有系统

新增资产以子页面、卡片或下钻入口加入，不删除现有板块，不改变老用户熟悉的中国国债功能。

### 8. 数据授权优先

即使技术上能够取得某项数据，如果没有展示、保存、导出或发送给AI的授权，也不能使用。

### 9. AI不是行情来源

AI可以解释数据，不能凭自身知识生成当天的行情、评级、经济数据或交易价格。

### 10. 风险结果必须说明覆盖范围

如果组合里只有一半资产能计算风险，页面必须告诉用户只覆盖了一半，不能把部分结果说成整个组合的风险。

### 11. 外币结果要保留原始含义

美债首先以美元角度研究。转换成人民币时，要说明使用了哪一天、哪个来源的汇率，并保留美国利率风险本身，不能换算后把不同市场的风险混成一个数字。

### 12. 产品设计和开发顺序分开

有价值的功能可以先把页面和接口设计完整，再按照优先级逐步开发。未开发完成不等于可以展示假结果。

## 九、PRD第6部分：网站会怎样组织

### 不增加一套全新导航

网站继续保留“市场、信息、因子、收益、预测、关注列表、投资组合、回测仿真、策略生成”等现有板块。

在这些板块内部增加资产选择或子页面。例如在市场板块里查看美债曲线，在信息板块里查看美联储事件，在因子板块里查看不同资产的主要影响因素。

### 公共内容只保留一份

同一条政策或新闻可能同时影响多类资产。系统不会复制四份完全相同的新闻页面，而是在同一个事件页面里分别展示它对各类资产的影响。

### 页面之间可以带着研究上下文跳转

用户从某个资产、某个日期或某个研究案例跳到其他页面时，系统会保留必要信息。历史研究依靠固定版本恢复，而不是只按日期打开最新内容。

### 用户最终看到的典型流程

```text
首页或市场页面
→ 选择资产或具体对象
→ 查看事件及证据
→ 查看影响因素和历史情况
→ 需要时查看预测、组合或策略研究
→ 保存研究案例
→ 生成正式报告
```

## 十、PRD第7部分：各功能模块分别要做什么

### 7.1 资产与标的模块

“资产”是大的类别，例如美债；“标的”是具体研究对象，例如10年期美债或某个月份的国债期货合约。

这个模块的需求是：

- 用户能够明确选择正在研究哪类资产；
- 每项结果都写清楚针对什么对象；
- 页面显示数据更新到什么时候；
- 系统说明自己目前能分析到整体市场、行业、企业还是单只债券；
- 不能把只适用于整体市场的结论冒充成单只债券结论。

它解决的是“我们到底在研究谁”的问题。

### 7.2 数据与行情模块

这个模块相当于平台的原材料管理。

主要需求包括：

- 优先使用公司已经购买或获准使用的数据；
- 不同来源的数据要统一名称、单位和时间，避免把不同口径的数据混在一起；
- 记录数据是否允许保存、展示、导出或发送给外部AI；
- 数据更新失败后可以重试或补跑；
- 清楚区分数据缺失、过期、冲突和权限不足；
- 保留历史版本，供应商后来修改数据时不能覆盖当时研究使用的版本；
- 用户上传的数据必须检查格式和质量，不能上传后直接进入正式计算。

这个模块解决的是“数据从哪里来、是否可靠、能不能合法使用”的问题。

### 7.3 新闻、政策与事件模块

这个模块负责把大量信息整理成可以研究的事件。

例如，同一项政策可能有官方文件、媒体报道和多篇研报。系统需要：

- 把它们识别为同一个事件的不同证据，避免重复计算；
- 区分已经发生的事实、分析师观点、市场预期和未来计划；
- 分别分析该事件对不同资产的影响；
- 允许某项资产暂时没有结论，不能强行凑齐四类资产；
- 同时展示支持和反对某个判断的证据；
- 保存事件发生、新闻发布、系统取得信息和研究人员实际可用信息的时间。

这个模块解决的是“发生了什么，以及我们凭什么这样判断”的问题。

### 7.4 因子模块

“因子”可以简单理解为影响市场的原因或主题，例如通胀、经济增长、资金松紧、政策变化和市场情绪。

这个模块要做的不是给每个因子永久贴上“利好”或“利空”标签，而是根据具体资产、时间和场景判断其影响。

主要需求包括：

- 把不同叫法但含义相同的因素归到一起；
- 保留AI最初识别出的原始名称，方便追查；
- 新因素需要经过独立检查后才能正式进入因子库；
- 分开显示“事件本身有多重要”“最近出现得有多频繁”“过去是否真的有效”；
- 多个因素结论相反时保留冲突，不强行拼成一个分数；
- 已经失效的因素可以暂停或退休，但历史研究仍然能够复现。

这个模块解决的是“市场变化背后的主要原因是什么”的问题。

### 7.5 收益与事件研究模块

这个模块负责观察事件发生前后市场到底发生了什么。

例如，某项政策公布以后，10年期国债收益率在下一天、五个交易日和二十个交易日分别怎样变化。

需要特别注意：

- 收益率变化不等于投资赚了多少钱；
- 期货持仓变化不等于期货投资收益；
- 不同资产使用不同单位，不能直接放在一起排名；
- 中国和美国有不同交易时间和节假日，需要分别计算观察窗口；
- 同一事件的重复新闻不能当成多个样本；
- 历史相关、事件发生后的市场表现和真实策略回测是三种不同结果，不能混为一谈。

这个模块解决的是“类似事情过去发生后，市场通常怎样变化”的问题，但它不能单独证明某个事件一定造成了某个结果。

### 7.6 预测模块

预测模块不是所有资产都默认开放。只有数据和历史表现通过检查的具体对象，才允许输出相应类型的预测。

预测可以有不同层次：

1. 只做文字分析；
2. 判断大致方向；
3. 给出发生概率；
4. 给出可能变化幅度；
5. 给出可能范围。

数据不足时，可以从精确预测降为方向判断或文字分析，也可以明确拒绝预测。拒绝预测不是系统出错，而是系统在诚实说明当前证据不够。

每次预测都要保存当时使用的数据、证据和模型。以后市场数据变化时，只能生成新版本，不能修改旧预测。

AI自己说“我有80%信心”，不等于真实准确率。正式概率必须经过历史结果检验。

这个模块解决的是“在证据和历史数据允许时，对未来给出多大程度的判断”的问题。它不是第一版研究闭环的强制条件。

### 7.7 关注列表与研究组合模块

这一部分其实包含两个不同功能。

#### 关注列表

用户可以收藏新闻、事件、资产、指标和因子。后续还可以把它扩展成研究监测中心，例如：

- 某个收益率超过一个数值时提醒；
- 某项指标变化过快时提醒；
- 出现重要评级或政策事件时提醒。

提醒频率必须符合真实数据更新速度。每天只有一次的数据不能宣传成实时预警。提醒只告诉用户“值得关注”，不会自动启动预测、回测或交易。

#### 研究组合

研究组合分成两类：

- 目标配置组合：表达理想情况下各类资产准备分配多少比例；
- 模拟持仓组合：表达假设持有什么具体债券或期货、数量多少、方向如何。

这些组合用于研究，不代表客户真实账户。系统要分别保存权重、资金、数量、面值、市值、成本和保证金，不能把不同概念都塞进一个“金额”字段。

这个模块解决的是“我想持续关注什么，以及我想研究怎样的资产配置或模拟持仓”的问题。

### 7.8 组合风险与情景分析模块

#### 组合风险

这个模块帮助用户了解：如果市场利率、信用状况、汇率或期货价格发生变化，研究组合可能受到什么影响。

系统会逐步展示：

- 哪些资产对利率变化比较敏感；
- 风险主要来自哪些市场和币种；
- 信用债是否过度集中在某个行业、评级或企业；
- 国债期货是否存在保证金、到期、换月和基差风险；
- 美债的美元风险，以及数据允许时的人民币换算影响。

如果只有一部分持仓能够计算，必须同时显示覆盖比例和缺失原因。

#### 情景分析

情景分析就是回答“如果发生某种变化会怎样”。例如：

- 如果利率上升一点，组合大概怎样变化；
- 如果信用利差扩大，信用债可能受到什么影响；
- 如果美元兑人民币变化，美债人民币价值可能怎样变化。

AI可以建议值得测试的情景，但正式数字要由固定程序计算。结果通常只是近似估算，不能宣传为精确损益、未来预测或最大可能亏损。

这个模块解决的是“如果市场出现某种变化，我们的研究组合可能怎样”的问题。

### 7.9 回测模块

回测可以理解为：把一套交易想法放到过去的数据中试运行，看它过去可能表现怎样。

正式回测必须具备：

- 明确可以买卖的具体对象；
- 当时真实可获得的数据；
- 买卖规则和持仓规则；
- 手续费、价差和滑点等成本；
- 无法成交或资金不足时的处理；
- 清楚的收益和风险计算方法。

如果只是观察“某事件以后收益率经常下降”，这属于研究结果，不等于一套可以交易的策略赚了钱。

回测亏损不代表系统失败；没有交易也可能是因为没有出现信号。系统要区分研究质量、程序是否正常以及策略过去是否赚钱，不能把三件事混成一个状态。

这个模块解决的是“这套交易规则放到过去是否能够真实、合理地运行”的问题。

### 7.10 策略生成模块

策略生成是高级能力。系统会把用户的研究需求、市场数据、成本、限制和可选证据整理后，交给外部策略服务生成代码并回测。

核心要求是：

- 用户必须确认具体交易对象、时间、资金、规则、成本和风险；
- 任何重要变化都要形成新版本并重新确认；
- AI生成的代码不能读取系统密钥、其他用户数据或随意访问网络；
- 用户选择了不支持的标的时，系统要拒绝，不能偷偷替换成另一个标的制造成功结果；
- 新闻和未经验证的预测不能自动触发策略；
- 外部服务如果无法证明安全性和完整成本计算，结果只能算实验，不能称为正式研究回测。

这个模块解决的是“怎样在用户确认和安全限制下，把研究想法变成可以检验的交易规则”的问题。

### 7.11 报告与复盘模块

这是首个可交付版本中的关键模块。

#### 研究案例

用户可以把一次研究涉及的事件、证据、判断、预测、组合、风险、情景和回测结果保存为一个研究案例。

案例保存的是对原始内容固定版本的引用，而不是复制一份新的数据。这样既能复盘，也避免同一内容到处复制后产生不同版本。

案例默认属于个人，也可以关联已有项目并复用项目成员权限。即使有权看案例，也不代表一定有权看案例引用的每一份底层数据。

#### 正式报告

正式报告生成后，会固定当时的案例、数据、证据、模型和计算参数。以后数据更新时，旧报告不会自动改变。重新生成会产生一个新版本，用户可以比较两个版本的差异。

系统还可以提供动态研究视图，用于查看最新数据，但必须明显区别于正式报告。

#### 删除和导出

内容删除优先采用可恢复方式。由于授权到期或权限变化无法继续显示内容时，系统只保留不泄露敏感信息的最小记录，并提示历史报告为何不能完整复现。

报告计划支持PDF、Word、Excel、CSV和Markdown等形式。导出时要重新检查数据是否允许导出和再分发。如果删除受限证据后核心结论已经没有依据，就应该拒绝导出或重新生成报告。

这个模块解决的是“怎样把一次研究沉淀成可保存、可复查、可交付的成果”的问题。

## 十一、PRD第8部分：四类资产分别能做到什么

这张功能矩阵是在告诉管理者：四类资产现在的起点不同，不能要求它们第一天就具有完全相同的功能。

### 中国国债

现有能力最完整。主要原则是继续保留，并通过兼容方式接入新的公共研究流程。

### 美债

已有2年、10年和30年收益率，数据基础相对清楚，因此作为第一个新增资产验证对象。先完成美元角度的市场研究、事件证据、案例和报告，再逐步开放人民币视角、预测和策略。

### 国债期货

目前主要有会员持仓排名。第一步可以研究持仓变化和事件影响，但要等价格、具体合约、换月和成本数据完整后，才能进行正式价格分析和策略回测。

### 信用债

目前主要有整体曲线。可以先研究整体市场变化；评级、行业、企业和单只债券研究要等待更细的数据和授权。

这部分的核心不是比较谁功能多，而是为每项能力设置真实的数据前提。

## 十二、PRD第9部分：跨资产联动是什么意思

跨资产联动是本项目区别于普通单市场看盘工具的重要能力。

系统要帮助用户理解：

- 美国国债变化是否会影响中国国债；
- 中国国债现券变化怎样影响国债期货；
- 无风险利率、资金和市场情绪怎样影响信用债；
- 同一政策为什么可能对不同资产产生不同方向的影响。

页面会用“传导链卡片”和关系表展示这种联系。例如：

```text
美国通胀高于预期
→ 市场认为美国利率可能维持高位
→ 美债收益率上升
→ 全球利率和资金环境发生变化
→ 中国国债、国债期货或信用债受到不同程度影响
```

这些关系可能只是理论解释、AI推断、个别案例支持或历史统计关联，系统必须清楚标明，不能把“经常一起变化”直接说成“一定是前者造成后者”。

## 十三、PRD第10部分：权限与合规是什么意思

这一部分确保不同用户只能看到和使用自己有权访问的内容。

主要规则包括：

- 未登录用户只能看允许公开的页面；
- 组合、策略、上传材料、任务和报告需要登录；
- 个人研究组合默认只属于当前账号；
- 案例关联项目后复用现有项目权限，不再建立另一套复杂角色系统；
- 用户有权看报告，不代表一定有权导出或转发报告；
- 数据供应商不允许导出的内容，系统也不能通过报告导出泄露；
- 所有权转移、永久删除、恢复和导出等重要操作都要留下记录。

这部分解决的是“谁能看、谁能用、谁能导出，以及出了问题能否查清”的问题。

## 十四、PRD第11部分：非功能需求是什么意思

这一部分不是在讲页面上有哪些按钮，而是在要求系统达到基本质量。

### 可用性

一种资产的数据出问题，不能拖垮其他资产页面。

### 速度

常用查询要尽量快速；耗时很长的分析放到后台执行，用户可以看到处理进度。

### 可观察

数据同步、AI分析、回测和报告任务都要显示正在处理、成功还是失败，以及失败原因。

### 可恢复

任务失败后可以安全重试或补跑，不能重复写入一堆相同数据。

### 可测试

不同资产接入后要有统一检查，回测要重点检查是否偷用了未来数据。

### 可追溯

任何正式结果都能找到使用的数据、模型、规则和版本。

## 十五、PRD第12部分：怎样验收这个项目

原PRD列出了48项详细验收要求，可以归纳为以下八组：

### 1. 现有功能保护

中国国债页面、数据、组合、预测、策略和回测不能因为新增资产而被删除或削弱。

### 2. 研究链路完整

用户能够从市场变化进入事件和证据，形成因子或定性判断，再保存案例并生成正式报告。

### 3. 数据诚实

数据缺失、过期、只覆盖一部分或没有权限时必须明确展示，不能生成假结果。

### 4. 证据和历史可追查

结论、预测、风险、报告和策略都能找到当时使用的数据、时间和版本。

### 5. 不同研究结果不混淆

历史相关、事件研究、预测、组合风险和策略回测分别展示，不能把一种结果包装成另一种更强的结论。

### 6. 高级功能有门槛

预测、风险数字和策略回测只有在相应数据与方法满足条件后才产生正式结果。

### 7. 权限和导出安全

案例、报告及其引用分别检查权限；导出时再次检查供应商许可。

### 8. 第一版可以独立交付

即使组合风险、持续提醒或新增资产策略回测还在后续阶段，第一版仍然能够用真实证据完成研究案例和正式报告。

## 十六、PRD第13部分：项目准备怎样分阶段实施

### 阶段0：先打公共基础和研究闭环

先把四类资产共用的基本表达统一起来，例如资产名称、事件、证据、时间、状态、研究案例和报告。

公共能力只建设当前真实需要的部分，不先造一个非常庞大而没有实际用途的平台。

第一阶段最重要的成果是把“研究—证据—案例—报告”打通，并确保现有中国国债功能不受影响。

### 阶段1：美债

利用已有的2年、10年、30年美债收益率验证公共架构，并建立美国宏观、美联储事件、中美市场时间差和跨资产研究能力。

### 阶段2：国债期货

逐步补充具体合约、价格、换月、成本、保证金和期现关系。在数据不足时先研究已有会员持仓，不伪造价格或回测结果。

### 阶段3：信用债

先从整体信用债曲线开始，之后根据数据授权扩展到评级、行业、企业和单只债券。

### 阶段4：跨资产深化

在基础研究报告已经打通后，继续加强跨资产比较、组合风险、持续监测和综合报告。

### 这个顺序是否固定

不固定。美债优先是当前推荐路线，不代表美债必须全部做完后才能开始国债期货。只要数据、客户需求和开发条件允许，各部分可以并行。

## 十七、PRD第14部分：当前仍有哪些风险

目前最大的风险不是页面怎么画，而是以下外部条件是否具备：

### 1. 数据是否拿得到

信用债细分数据、国债期货价格和期现数据、美国宏观预期等，可能需要公司现有供应商或新增采购支持。

### 2. 数据是否允许这样使用

有些数据只允许内部查看，不允许长期保存、导出、转发或发送给外部AI。授权范围会直接影响产品能力。

### 3. 历史数据是否足够

没有足够历史数据，就不能可靠验证预测和策略，也不能为了完整而编造样本。

### 4. 外部策略服务到底支持什么

需要确认DreamStrategy能够处理哪些具体资产和合约，是否真实考虑成本、成交、换月、结算和安全隔离。

### 5. 具体计算规则仍需开发时确定

风险公式、监测阈值、数据更新频率、保留期限和部分统计规则，需要结合真实数据和客户需求在开发阶段确定。现在不提前虚构固定参数。

## 十八、管理层可以怎样理解最终交付物

### 首个可交付版本

管理层可以期待看到：

- 在现有网站中切换或进入新增资产研究；
- 查看真实市场数据及更新时间；
- 从重要变化进入事件和原始证据；
- 查看主要影响因素和跨资产解释；
- 数据允许时查看历史表现或预测，不允许时看到清楚的限制；
- 把研究内容保存成案例；
- 生成一份不会被后续数据自动改写的正式报告。

### 后续逐步增强

- 更细的信用债研究；
- 更完整的国债期货价格和期现分析；
- 美债人民币视角；
- 研究组合风险和情景分析；
- 持续监测和提醒；
- 经验证的新增资产策略回测；
- 更丰富的跨资产综合报告。

### 最终价值

这个项目最终要把分散的行情、新闻、AI分析、历史研究、组合分析和报告工作连起来，让研究人员少花时间找材料和重复整理，多花时间判断市场；同时让管理者能够清楚知道每个结论来自哪里、可靠到什么程度、哪些能力已经验证、哪些仍受数据限制。

## 十九、常用词语的简单解释

| 词语 | 简单解释 |
|---|---|
| 固收 | 以债券、利率等为主要对象的投资和研究领域。 |
| 信用债 | 企业、金融机构等发行的债券，除利率变化外，还要关注发行人能否按时还钱。 |
| 国债期货 | 以国债价值变化为基础的标准化合约，可用于研究、交易或对冲利率风险。 |
| 收益率 | 债券市场常用的利率指标；它的上升不等于投资收益上升，通常与债券价格反向变化。 |
| 信用利差 | 信用债收益率比相近国债收益率高出的部分，可粗略反映额外信用和流动性风险。 |
| bp | 利率变化的常用小单位，1bp等于0.01个百分点。 |
| 因子 | 可能影响市场的原因或主题，例如通胀、政策、资金和情绪。 |
| 标的 | 被具体研究或交易的对象，例如10年期美债或某个月份的期货合约。 |
| 回测 | 把一套规则放到过去的数据中试运行，检查它过去可能怎样表现。 |
| 情景分析 | 假设市场发生某种变化，估算组合可能受到的影响。 |
| 对冲 | 使用另一项资产降低某类风险，但通常无法消除所有风险。 |
| 数据快照 | 把某个时点研究实际使用的数据固定下来，方便以后复查。 |
| 版本 | 每次重要修改都保留新旧内容，不直接覆盖历史结果。 |
| 覆盖率 | 一项计算实际覆盖了多少资产或持仓，防止把部分结果当成全部结果。 |
| MVP/首个可交付版本 | 用于确定开发里程碑的第一批完整能力，不等于最终产品，也不一定等于正式对外上线版本。 |
