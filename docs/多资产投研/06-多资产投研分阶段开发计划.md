# 多资产投研分阶段开发计划

> 文档状态：Draft，可持续修订
> 计划版本：v1.0
> 基线日期：2026-11-27
> 适用范围：现有系统中的“债券市场智能分析”工作区
> 覆盖资产：中国国债、信用债、中国国债期货、美债
> 需求依据：`01-多资产固收投研平台需求文档-PRD.md`、`02-多资产投研引擎技术设计-TDD.md`、`03-信用债资产规格.md`、`04-国债期货资产规格.md`、`05-美债资产规格.md`
> 前端依据：`前端设计方案-v1.md`及当前已实现页面

## 1. 文档目的

本计划把01—05正式需求和当前前端设计转换为可实施、可测试、可独立验收的开发阶段。

阶段按照完整业务功能划分，不按照信用债、国债期货、美债复制三条平行开发线，也不把同一个客户功能随意拆散到多个无法独立使用的阶段。每个阶段完成后，都应形成可在现有系统中独立开启、独立测试、独立回滚的增量能力。

本计划不是固定不变的排期。后续需求、数据授权、接口能力或页面设计发生变化时，应按第15节的变更机制更新，不直接覆盖已经验收的事实。

## 2. 项目范围与边界

### 2.1 本计划负责的范围

```text
债券市场智能分析
├─ 市场洞察
│  ├─ 市场                 /market
│  ├─ 市场数据             /info
│  └─ 市场表现             /returns
├─ 研究分析
│  ├─ 因子                 /factors
│  └─ 预测                 /forecast
├─ 组合管理
│  ├─ 关注列表             /watchlist
│  └─ 投资组合             /portfolio
└─ 策略验证
   ├─ 事件研究             /backtest
   └─ 策略生成             /strategy
```

具体包括：

- 四类资产的市场数据、公共新闻与分资产影响、因子、市场表现、事件研究和预测；
- 多资产关注、研究组合、风险与情景分析；
- 达到交易级门槛后的策略生成和正式回测接入；
- 资产上下文、URL、证据下钻、数据状态、能力门控和前后端公共契约；
- 保持现有中国国债页面、接口、数据和DreamStrategy兼容。

### 2.2 不作为本计划主体交付的范围

- 静态首页 `/home` 的整体重做；
- 工作流中心、项目管理、文件库、通用对话和平台左侧导航的整体改造；
- 研究案例、正式报告、政策解读和研报工作流本身的完整重建；
- 真实交易账户、订单、成交管理、会计核算和真实PnL；
- 未获得授权的数据抓取或再分发；
- 用模拟金融数值代替尚未具备的数据能力。

研究案例和正式报告是01—05文档定义的完整研究闭环组成部分。本计划负责提供稳定的结果、版本、快照和证据引用契约，具体案例/报告工作流由对应项目接入，不在本计划中重复建设。

## 3. 当前基线

### 3.1 已有系统能力

| 功能 | 当前能力 | 当前限制 |
|---|---|---|
| 中国国债 | 新闻方向、因子、收益率、收益日历、预测、事件研究、组合和有限策略链路 | 旧方向和时间模型主要为中国国债专用，需通过兼容层接入公共契约 |
| 信用债 | 整体中短期票据曲线、同期限国债曲线和整体信用利差 | 无评级、行业、主体、单券、历史评级和正式CS01能力 |
| 国债期货 | TS/TF/T/TL会员排名、多空比、趋势和同步 | 无OHLC、结算价、连续合约、换月、基差、CTD、IRR和正式价格收益 |
| 美债 | 美国财政部2Y/10Y/30Y收益率及中美利差 | 无5Y、宏观预期/公布值、拍卖、美债专属事件和预测链路 |
| 新闻事件 | 新闻详情、来源、时间、中国国债方向和因子 | 尚无公共事件实体及信用债、期货、美债的独立影响记录 |
| 因子 | 中国国债因子库、活跃度、重要性和事件研究 | 无资产命名空间、应用级资格、独立审核和完整生命周期 |
| 组合 | 账号级研究组合及CSV导入 | 不是真实持仓；多币种、具体期货合约和正式风险参数能力不足 |
| 策略 | 现有DreamStrategy入口和少量兼容标的 | 白名单或接口可调用不等于正式研究回测可用 |

### 3.2 当前已经形成的前端基线

- 保留原页面和URL，导航调整为“市场洞察、研究分析、组合管理、策略验证”两级结构；
- `/market`仍为默认入口，默认选择“全部资产”；
- 市场页顶部和右侧市场快照已经同时体现四类资产；
- `/info`默认展示四资产2×2市场数据总览，并可进入单资产详情；
- `/returns`默认展示四资产近期变化总览，中国国债保留原收益日历；市场表现不复用市场数据页的完整历史水平图；
- 新闻详情已经展示四资产影响条，不展示冗长的影响原因；当前只有中国国债结果，其余资产在没有独立记录时显示“未分析”；
- “信息、收益、回测仿真”视觉名称分别调整为“市场数据、市场表现、事件研究”，旧URL继续兼容；
- 已完成的前端测试和构建作为后续回归基线，不能因新增资产而删除现有中国国债测试。

上述内容代表前端结构和交互基线，不代表对应后台分析能力已经全部完成。

## 4. 阶段划分原则

1. **按客户功能闭环划分**：市场数据、事件、因子、市场表现、预测、组合、策略各自形成完整阶段。
2. **同一功能内覆盖四资产**：公共页面统一，资产专业算法和数据门槛分离。
3. **先研究、后验证、再交易**：研究闭环、统计验证闭环、可交易策略闭环分别验收。
4. **前端入口与真实能力一致**：可以展示真实数据、分析结果和限制，不展示占位PnL、模拟评级或伪预测。
5. **兼容优先**：新增功能旁路接入；旧中国国债接口、页面和数据行为不被强制迁移。
6. **每阶段可独立发布**：使用资产级和功能级feature flag，新能力失败时不影响其他资产和旧链路。
7. **门槛不足就降级或拒绝**：未分析、无显著影响、证据不足、部分覆盖、业务拒绝和系统错误分别表达。

## 6. P0：基线固化与公共契约

### 6.1 阶段目标

把当前已经确认的前端结构、旧中国国债行为和多资产公共语义固化为可回归基线，避免后续开发过程中反复改变路由、方向、时间和状态含义。

### 6.2 功能范围

- 固化两级导航、页面名称、URL和返回路径；
- 建立四类`AssetResearchProfile`，声明资产、标的、默认基准、方向轴、时区、交易日历、期限和能力状态；
- 定义双轴方向：`target_direction`与`market_effect`；
- 定义`not_analyzed`、`no_significant_impact`、`insufficient_evidence`、`impact_identified`、`analysis_failed`；
- 定义数据缺失、部分覆盖、质量不足、分析降级、业务拒绝和系统错误六类客户状态；
- 定义显式URL上下文、站内返回路由、版本/快照优先级；
- 建立中国国债只读兼容适配器设计，不改旧表和旧写入；
- 建立数据授权、展示级/分析级/验证级/交易级四级门控台账；
- 为当前页面补齐关键组件测试、路由测试和视觉回归清单。

### 6.3 主要交付物

- 资产配置和能力登记契约；
- 公共API响应草案和错误/状态码规范；
- URL参数与返回上下文规范；
- 当前接口、数据源、授权、更新时间和质量能力台账；
- 旧中国国债回归用例集；
- P1—P7统一使用的测试夹具和假数据边界说明。

### 6.4 独立测试与验收

- 单元测试：profile、方向映射、状态映射、URL解析、旧结果兼容；
- 契约测试：四类资产配置完整性，未知资产和未知能力必须拒绝；
- 前端回归：现有九个页面和旧深链均可访问；
- E2E：默认进入市场页，中国国债旧路径和数据行为保持不变；
- 回滚测试：关闭全部新增feature flag后恢复旧系统行为。

**完成标准：** 公共语义通过评审；自动化测试可阻止路由、方向和状态被误改；不需要等待任何新增资产高级数据。

## 7. P1：四资产市场数据与资产上下文

### 7.1 阶段目标

完成“进入平台即可看见四资产真实市场状态，并能进入对应资产详情”的完整市场数据功能。

### 7.2 功能范围

前端：

- 完成当前四资产总览、资产切换、期限/品种切换和详情布局；
- 国债期货详情将合约下拉框放在持仓趋势图右上角，合约和品种均以“期限全称 + 代码”展示，避免仅显示 TS/TF/T/TL；
- 市场页默认全部资产，不保留上次选择；
- 市场表现页默认四资产近期变化总览，不复用市场数据页的完整历史水平图；
- 所有卡片显示数据日期、来源、指标单位和质量状态；
- 单一资产失败不影响其他资产卡片；
- 旧 `/futures`、`/credit-spread`、`/treasury-spread`继续兼容。

后端与数据：

- 为中国国债收益率、整体信用利差、期货会员结构、美债收益率提供统一只读市场观测契约；
- 同步任务幂等，支持失败重试、人工补跑、过期提示和数据日期；
- 保存来源、观测时间、发布时间、可用时间、获取时间和质量标记；
- 资产级缓存和错误隔离；
- 不在本阶段伪造信用评级曲线、期货价格或美债5Y。

### 7.3 资产专业范围

| 资产 | 本阶段正式支持 | 明确不支持或条件开放 |
|---|---|---|
| 中国国债 | 各可用期限收益率、期限曲线、10Y-2Y、历史走势 | 价格总回报另行门控 |
| 信用债 | 整体信用收益率、同期限国债收益率、整体信用利差 | 评级、行业、主体和单券 |
| 国债期货 | TS/TF/T/TL会员多空结构、趋势、排名和数据日期 | OHLC、价格收益、连续合约、基差、CTD、IRR |
| 美债 | 2Y/10Y/30Y收益率、曲线和中美利差 | 5Y、价格回报、总回报；不得插值补齐 |

### 7.4 独立测试与验收

- 数据源适配器单元测试：单位、期限、空值、修订和日期；
- API契约测试：四卡独立响应，异质指标不能合并排名；
- 集成测试：同步→存储→API→四资产总览；
- 异常测试：单资产超时、空序列、过期数据和来源冲突；
- E2E：四资产卡片切换期限/品种、进入详情、返回总览；
- E2E：国债期货可由图表右上角下拉框切换合约，标题、趋势和排名同步更新，并显示完整期限名称；
- E2E：市场数据四类资产详情均由工作区主容器纵向滚动，鼠标位于图表、指标卡和表格宽度内时滚轮仍可推动整页，不产生无效的嵌套滚动区；
- 性能：常用只读接口目标P95小于2秒；
- 回归：中国国债旧收益率与新增统一读取结果一致。

**完成标准：** `/market`、`/info`和`/returns`总览只使用真实数据；四资产均可独立查看；任何缺失都显示原因和数据日期，不出现无限加载或伪数值。

## 8. P2：公共事件、证据与分资产影响

### 8.1 阶段目标

把现有“新闻即中国国债判断”升级为“公共事件只保存一次、每个资产拥有独立影响判断”的研究入口。

### 8.2 功能范围

- 建立`public_event`、事件族、证据引用和资产影响的最小可用模型；
- 新闻、政策和可靠来源形成候选事件，完成事实识别、来源核查和去重；
- 区分事实、观点、预测、市场预期和已确认未来安排；
- 每条资产影响保存资产、标的、目标指标、方向、周期、强度、置信度、传导路径、证据、失效条件、模型、提示词版本和数据截止时间；
- 同一新闻流只出现一次，通过资产筛选和精简标签查看影响；
- 新闻详情固定展示四资产影响条，不展示冗长原因；有记录则展示资产专业方向，无记录显示“未分析”；
- 证据详情按新闻、政策、研报、行情和统计结果使用不同渲染方式；
- 保留原搜索、来源、时间、推荐排序和旧中国国债方向筛选；
- 新资产方向筛选只有在独立影响记录具备后才开启。

### 8.3 资产专属分析最低要求

- 信用债：至少区分无风险利率、信用利差、信用风险和流动性影响；
- 国债期货：把现券收益率方向按确定性规则映射为期货价格方向，持仓结构与价格方向分开；
- 美债：覆盖美联储、通胀、就业、增长、财政供给、拍卖和避险，按期限分别判断；
- 中国国债：旧`positive/negative/neutral`只读映射，原分析链路不被修改。

### 8.4 独立测试与验收

- 单元测试：双轴方向、证据不足不等于中性、各资产专业方向文案；
- 提示词契约测试：必填字段、引用、禁止编造数值和规则冲突拦截；
- 去重测试：重复报道只增加证据，不重复扩大事件；
- 集成测试：新闻→公共事件→四资产影响→详情展示；
- 权限测试：无权证据不能通过事件详情泄漏；
- E2E：全部资产新闻流→打开详情→查看影响→下钻证据→返回原筛选；
- 失败测试：单一资产分析失败不阻断其他资产结果。

**完成标准：** 至少一条真实事件可以保存多个资产的独立影响；缺失记录、无显著影响、证据不足和失败状态在API及页面一致；中国国债旧结果继续可用。

## 9. P3：多资产因子研究

### 9.1 阶段目标

形成统一因子入口，同时保留公共经济驱动和各资产专业应用之间的差异。

### 9.2 功能范围

- 建立公共核心因子、资产专属命名空间和版本化别名；
- 保存AI原始标签、标准化结果、映射依据和模型版本；
- 因子字典状态与“资产×标的×指标×周期”的应用资格分开；
- 新因子提取、独立AI审核和程序校验相互独立；
- 支持候选、审核中、正式、休眠、观察、暂停、合并、拒绝和退休；
- 因子页面按资产、公共/专属、分类和关键词筛选；
- 因子详情采用共享主体，分别展示资产影响、原始证据、反向证据和适用限制；
- 事件重要性、去重活跃度、历史有效性分别展示，不强制综合分；
- 只有同资产、同标的、同指标、同周期方向相反时标记直接冲突；
- 以关系表和传导链卡片展示跨资产机制，不建设复杂图数据库。

### 9.3 资产专属命名空间

- 信用债：`credit.rating`、`credit.payment`、`credit.refinancing`、`credit.fundamental`、`credit.issuer`、`credit.liquidity`、`credit.supply_demand`；
- 国债期货：`futures.position`、`futures.contract`、`futures.basis`、`futures.delivery`、`futures.spread`、`futures.liquidity`、`futures.hedging`；
- 美债：`ust.fed`、`ust.inflation`、`ust.growth_employment`、`ust.supply_auction`、`ust.risk_liquidity`、`ust.term_premium`。

### 9.4 独立测试与验收

- 单元测试：别名归并、事实/预期区分、命名空间和状态转换；
- 契约测试：提取任务与审核任务输入隔离，审核冲突不得自动发布；
- 集成测试：事件影响→因子映射→因子详情→证据返回；
- 冲突测试：跨资产、跨指标和跨周期差异不得误标直接冲突；
- 评价测试：重要性、活跃度、有效性字段互不补值；
- E2E：筛选因子→查看资产应用→下钻正反证据→返回原上下文。

**完成标准：** 同一公共因子可服务多个资产且拥有独立应用状态；资产专属因子不会污染公共字典；缺少历史样本时显示证据不足而不是借用活跃度或重要性。

## 10. P4：市场表现、历史相关性与事件研究

### 10.1 阶段目标

完成“市场发生了什么”和“类似事件历史上通常如何反应”的统计研究功能，并与可交易策略回测严格分离。

### 10.2 功能范围

- 建立统一市场表现契约和资产专属计算器；
- 统一表达目标指标、起止值、变化、单位、时点、周期、方法、基准、来源、数据版本和质量；
- 建立版本化T、T+1、T+5、T+20及资产交易日历；
- 保存事件族、主子事件、样本资格、排除原因、窗口重叠和干扰事件；
- `/returns`展示各资产市场表现和历史相关性；
- “市场数据”负责历史水平、期限结构、分位和底层行情详情；“市场表现”负责较上一有效观测的变化、事件证据和研究边界，两页不得复用同一套主体图表；
- 信用债表现拆分信用利差、信用收益率和同期限国债收益率的日变动；美债表现拆分美债收益率、中债收益率和中美利差的日变动；期货在价格数据缺失时只展示持仓结构变化；
- 表现总览和单资产子页面统一由工作区主容器滚动，不建立固定高度的嵌套纵向滚动区；
- `/backtest`继续命名为“事件研究”，显示样本、基准、平均/中位反应、命中率、不确定性和适用范围；
- 历史相关性、事件研究和策略回测使用不同结果类型、字段和标签；
- 当前中国国债旧事件研究保留并标注其时间/模型限制，不伪装为策略PnL。

### 10.3 资产指标边界

| 资产 | 可先交付结果 | 条件开放结果 |
|---|---|---|
| 中国国债 | 现有收益率bp变化和收益日历 | 修正时间模型后的正式事件研究、价格/总回报 |
| 信用债 | 整体信用曲线收益率bp变化 | 口径匹配信用利差、利率对冲超额收益、总回报、分层研究 |
| 国债期货 | 会员持仓结构变化，明确“不是收益” | 具体合约价格/结算收益、连续序列研究、基差和正式PnL |
| 美债 | 2Y/10Y/30Y收益率bp、曲线和中美利差变化 | 5Y、价格回报、总回报和盘中反应 |

### 10.4 独立测试与验收

- 单元测试：bp计算、单位、基准、市场日历、非交易日和跨市场对齐；
- 美债测试：美东/UTC/北京时间、夏令时、中美源/目标市场独立窗口；
- 期货测试：会员结构不能进入收益字段；未来连续合约换月不能使用事后信息；
- 信用债测试：收益率变化不得自动解释为信用改善；
- 样本测试：重复事件、事件族、重叠窗口和排除原因；
- 集成测试：固定快照→事件对齐→资产计算器→统计结果→页面；
- E2E：四资产总览→单资产表现→事件研究→证据详情→返回原版本；
- 交互测试：总览及全部资产子页面均可使用鼠标滚轮、触控板和键盘连续滚动到页面底部；
- 回归：现有中国国债收益日历和因子事件研究仍可访问。

**完成标准：** 每个正式结果能回答“研究的资产/指标是什么、何时起算、用什么基准、样本多少、数据版本是什么”；任何页面都不会把持仓、bp变化或事件反应显示成策略PnL。

## 11. P5：多资产预测

### 11.1 阶段目标

建立统一预测工作台和能力白名单，只对数据、时间对齐、目标定义和历史评估达标的资产目标生成预测。

### 11.2 功能范围

- 保留现有中国10Y国债日/周/月预测默认行为；
- 预测能力按资产、标的、目标指标、期限和预测类型登记；
- 新增资产日/周/月映射到各自市场1/5/20个有效观察日；
- 一次只选择一个资产和目标，不生成缺乏依据的默认四资产预测；
- 保存生成时间、数据截止时间、证据快照、模型、提示词、假设、反向风险和失效条件；
- 方向、概率、幅度和区间分别门控与评估；
- 多模型结果保持独立；没有验证依据时不平均成共识；
- 页面区分正常、降级、证据不足、信号冲突、业务拒绝和系统失败；
- 拒绝预测不显示为中性，模型置信度不显示为历史准确率；
- 预测版本不覆盖，未到期预测不提前评价。

### 11.3 首批候选目标

- 中国国债：继续保留现有10Y链路；
- 信用债：整体信用曲线收益率方向先评估，信用利差和细分目标独立门控；
- 国债期货：只有取得可靠合约价格后，先评估价格方向和波动状态；会员持仓只作证据；
- 美债：2Y、10Y、30Y收益率方向按期限逐项评估和开放。

### 11.4 独立测试与验收

- 单元测试：白名单、有效观察日、拒绝/降级、可空字段和版本规则；
- 契约测试：方向、概率、幅度、区间不能互相冒充；
- 集成测试：证据准备→预测生成→版本保存→到期评估；
- 评估测试：方向准确率、Brier、MAE/RMSE、区间覆盖和预测覆盖率按类型计算；
- 时间测试：当前模型历史回放与真实历史时点预测分离；
- E2E：选择资产/目标→查看预测或拒绝原因→下钻证据→查看历史评价；
- 回归：中国国债旧预测API和页面继续工作。

**完成标准：** 至少一个新增资产目标通过白名单和历史评估后正式开放；其他目标显示真实拒绝原因和恢复条件，不产生伪概率或伪幅度。

## 12. P6：关注、研究组合、风险与情景

### 12.1 阶段目标

让用户能够持续关注多资产研究对象，并对目标配置或模拟持仓进行有覆盖率说明的风险与情景研究。

### 12.2 功能范围

- 关注列表支持新闻、事件、因子、资产、标的和宏观信号；
- 关注对象可升级为版本化监测规则，但提醒只形成研究提示或待办；
- 区分目标配置组合和模拟持仓组合；
- 复用现有账号级组合，不接入真实交易账户；
- 模拟持仓保存标的、方向、币种、数量/面值/手数、假设市值或成本及输入来源；
- 风险结果显示风险因子、方向、币种、市场、数据时点、参数来源、方法、状态和覆盖率；
- 净DV01与总绝对DV01分别展示，缺失风险不补零；
- 规则情景和自定义冲击保存版本、单位、参数来源、近似方法和限制；
- AI只生成候选情景解释，正式损益由确定性计算器生成；
- 部分结果只显示已覆盖资产，不冒充全组合风险。

### 12.3 资产专业边界

- 信用债：整体曲线阶段只提供基础风险状态；评级/主体/行业集中度和CS01需对应数据；
- 国债期货：模拟持仓必须为具体合约、手数和方向；名义敞口、保证金、DV01、基差和换月分别门控；
- 美债：美元本币结果为正式基线；人民币即期折算、未对冲回报和对冲后回报四层独立门控；
- 中国国债：现有未分类用户久期不能直接生成正式DV01。

### 12.4 独立测试与验收

- 单元测试：组合模式必填规则、期货合约/手数/方向、多币种和覆盖率分母；
- 风险测试：DV01/CS01符号、净值/总绝对值、缺失不补零和冲击防重复计入；
- 契约测试：AI候选情景不能写入正式损益；
- 权限测试：用户/组织隔离，外部AI不得接收未授权持仓明细；
- 集成测试：组合版本→风险计算→情景运行→历史版本；
- 监测测试：来源频率、用户时区、冷却期、去重和提醒不触发下游任务；
- E2E：收藏研究对象→建立模拟组合→查看覆盖率→运行规则情景→回看版本。

**完成标准：** 用户可以构建至少包含两类资产的研究组合；风险页面明确显示已计算和未计算部分；期货会员排名、美债收益率期限点或新闻方向均不会被误作客户持仓风险参数。

## 13. P7：策略能力登记、生成与正式回测

### 13.1 阶段目标

在不削弱现有DreamStrategy链路的前提下，为真正满足交易级条件的标的建立可审计、可复现的策略生成和正式回测能力。

### 13.2 功能范围

- 建立标的能力登记：`not_enabled`、`configured`、`basic_validated`、`formal_research_backtest`；
- 白名单、别名、接口接受或单次成功不能自动升级正式能力；
- 结构化情报包按资产、证据时点和令牌预算生成；
- 业务策略版本与技术执行尝试分离；实质需求变化必须升版并重新确认；
- 保存代码、结构化需求、数据快照、成本、成交、结算、核算模型、日志、指标和验收结论；
- AI代码和外部输入按不可信数据隔离执行；
- 生命周期、研究质量和表现评价分别展示；亏损不等于技术失败，正式可用不等于未来盈利；
- 零成交区分无信号、数据、订单、资金、代码和标的能力原因；
- `/backtest`中的事件研究不迁移为策略PnL；正式回测结果使用独立类型和入口关系。

### 13.3 资产门槛

- 信用债：具体可交易债券池、历史评级、成交/成本、现金流和外部支持全部确认；整体曲线不可交易；
- 国债期货：具体合约、真实映射、换月、手续费/滑点、逐日结算、保证金和资金约束可复现；连续合约不可直接成交；
- 美债：具体券种或获准工具、价格/现金流/总回报、美元成本结算和外部支持确认；收益率期限点不可交易；
- 中国国债：保留现有已验证范围，未验证别名不继承正式能力。

### 13.4 独立测试与验收

- 单元测试：能力升级证据、别名隔离、版本哈希、重试语义和成本模型；
- 契约测试：未开放标的返回业务拒绝，不能静默替换标的；
- 安全测试：沙箱、文件/密钥/用户数据隔离、网络白名单、资源和超时；
- 集成测试：能力解析→情报包→确认→外部执行→结果验收→版本保存；
- 金融测试：未来函数、具体合约、换月、成本、成交、结算和现金流；
- E2E：生成策略→确认冻结版本→执行→查看代码/日志/指标/证据→重试不产生新业务版本；
- 回归：现有中国国债策略链路仍然可用。

**完成标准：** 至少一个经过独立证据验证的标的达到正式研究回测状态；未达到门槛的资产仍可完成研究，但不会生成占位PnL或被标记为“回测成功”。

## 14. P8：跨资产整合与发布加固

### 14.1 阶段目标

把已经独立验收的功能连接成稳定的跨资产研究工作台，并达到生产发布所需的性能、安全、观测、恢复和回滚标准。

### 14.2 功能范围

- 跨页面传递资产、标的、期限、目标指标、数据时点、快照和返回位置；
- 同一事件对四资产的影响对比和跨资产传导关系查询；
- 美债→中美利差→中国国债、现券→国债期货、无风险利率/流动性→信用利差等关系；
- 不同资产、指标或周期的方向差异不标记为直接冲突；
- 全链路任务状态、耗时、错误、数据新鲜度和补跑入口；
- 常用查询性能、缓存、分页、无障碍和响应式布局优化；
- 数据授权、接口权限、审计、导出引用和敏感信息检查；
- 资产/功能级feature flag、旁路API、失败隔离和回滚演练；
- 更新用户说明、运维手册、数据字典和验收记录。

### 14.3 独立测试与验收

- E2E：市场→事件→因子→市场表现/事件研究→预测或组合→证据详情→返回原快照；
- 跨资产E2E：美债事件分别查看美债、中国国债、期货和信用债影响；
- 故障注入：单一数据源、模型、任务或资产服务失败不拖垮其他页面；
- 性能与容量：核心只读P95、批量任务、分页和缓存失效；
- 安全与权限：匿名只读、登录功能、对象级权限、审计和受控返回路由；
- 可恢复性：同步、分析和统计任务幂等补跑；
- 回滚：关闭单资产或单功能后，旧中国国债链路和其他资产继续可用；
- 生产验收：产品、研究、数据、开发、测试和运维共同签字。

**完成标准：** 已开放功能形成稳定跨资产链路；未开放功能只通过真实业务状态表达；系统可以按资产或功能独立回滚，不需要整体停用“债券市场智能分析”。

## 15. 阶段通用准入与完成标准

### 15.1 开始开发前（Definition of Ready）

每个阶段至少确认：

1. 客户场景、页面入口和目标结果；
2. 使用的资产、标的、指标、单位、方向和时间口径；
3. 数据来源、授权、频率、历史覆盖和质量门槛；
4. API或任务契约及旧接口兼容方式；
5. 正常、缺失、部分覆盖、拒绝和失败状态；
6. 自动化测试范围、验收样本和回滚方式；
7. 尚未确认的业务规则已经记录为阻断项或明确的条件开放项。

### 15.2 阶段完成时（Definition of Done）

每个阶段必须同时满足：

- 功能、接口和页面完成，不只完成其中一层；
- 使用真实数据，数据来源和截止时间可见；
- 单元、契约、集成、E2E和旧功能回归测试通过；
- 数据缺失、质量不足、权限不足和系统错误可以恢复或给出明确动作；
- 结果可追溯数据、模型、提示词、计算和代码版本；
- 已完成安全、性能、可观测和回滚检查；
- 文档、接口说明、数据字典、测试记录和变更日志同步更新；
- 产品或研究验收人确认金融语义没有被前端统一布局抹平。

## 16. 依赖与并行策略

### 16.1 必须串行的核心依赖

```text
P0 公共语义
 ├─ P1 市场数据 ───────────────┐
 └─ P2 事件与证据 → P3 因子 ──┼→ P4 事件研究 → P5 预测
                               └→ P6 组合风险 → P7 策略
P1—P7 已开放能力 ─────────────────────────────→ P8 发布加固
```

- P2必须依赖P0资产/方向/状态契约；
- P3必须依赖P2的公共事件与证据；
- P4必须依赖P1市场数据和P2时间/事件模型；
- P5只有对应目标通过P4的历史评价准备后才能正式开放；
- P6可以先做组合输入与基础集中度，但正式风险指标依赖P1数据参数；
- P7必须依赖交易级数据、标的能力和外部服务证据，不能因计划日期强行开放。

### 16.2 可以并行的工作

- P1的数据源盘点、适配器开发和前端详情页可按资产并行；
- P2三类新增资产提示词与分析适配器可并行，共用事件和证据契约；
- P3专属因子字典可由不同资产研究人员并行评审；
- P4各资产计算器可并行开发，共用时间和结果契约；
- 期货行情、信用分层和美国宏观数据采购/授权可在早期并行推进，但未通过门控不能进入正式结果；
- 自动化测试应随各功能同步开发，不集中推迟到P8。

## 18. 风险与阻断项台账

以下事项不应在计划中假定已经解决：

1. 公司专业数据供应商、接口、资产覆盖和使用/展示/再分发授权；
2. 信用债评级、行业、主体、单券、历史评级和成交数据；
3. 国债期货OHLC、结算价、合约主数据、换月、CTD、转换因子和基差；
4. 美债5Y、宏观预期/实际/修订、拍卖和USD/CNY版本数据；
5. 各资产交易日历、盘前/盘中/盘后、T和窗口的最终业务规则；
6. 因子清单、别名、审核提示词和三维评价公式；
7. 预测白名单阈值、概率校准、幅度模型和多模型汇总规则；
8. DV01、CS01、覆盖率分母和情景参数；
9. DreamStrategy对具体标的、真实合约、成本、成交、结算、多腿和幂等的可验证支持；
10. `FCT_T_MAIN`、`100040`及其他别名的独立运行证据。

阻断项必须记录负责人、所影响阶段、所需证据、目标确认时间和临时降级方案。数据或授权没有通过时，该能力保持关闭，但不阻断同资产已经满足条件的其他研究功能。

## 19. 计划和需求变更机制

后续前端、需求和计划可能继续调整，采用以下方式管理：

### 19.1 稳定标识

- 阶段ID `P0—P8`保持稳定；
- 新增工作优先加入现有完整功能阶段；
- 只有出现新的独立客户功能闭环时才新增阶段，不因单个接口或组件增加阶段；
- 删除或合并阶段必须保留原ID的变更记录。

### 19.2 每次变更必须记录

```text
变更编号：CR-YYYY-NNN
变更日期：
变更来源：需求 / 数据 / 合规 / 技术 / 前端反馈
原设计：
新设计：
影响阶段：
影响页面与接口：
数据和授权影响：
测试与回归影响：
是否改变已验收行为：
迁移或回滚方案：
确认人：
```

### 19.3 变更判定规则

- 只调整布局、文案或视觉层级，且不改变数据语义：更新前端方案和对应阶段测试；
- 改变资产、指标、方向、时间或能力状态：同时更新01/02、对应资产规格、本计划和API契约；
- 新增数据源或改变授权用途：先更新数据与许可台账，再允许进入开发；
- 改变统计公式、预测目标、风险或策略模型：创建新计算/模型版本，不覆盖历史结果；
- 已验收阶段发生破坏性变化：形成新的增量里程碑和迁移计划，不能把旧结果静默改写为新口径。

## 20. 当前建议的执行起点

结合当前代码和前端完成度，建议下一步从以下顺序开始：

1. 完成P0的公共契约、能力台账和回归基线；
2. 将当前P1前端原型补齐后端统一观测契约、数据状态、同步任务和接口测试，形成第一个可独立发布版本；
3. 紧接着实施P2，因为新闻详情的四资产影响界面已经存在，但后三类资产仍缺少独立分析记录；
4. P2稳定后进入P3和P4；资产数据采购与适配可以提前并行；
5. P5—P7严格按各自能力门槛开放，不以页面已经存在作为后台能力可用的证据；
6. 每完成一个阶段就更新本文件的状态、实际交付、遗留项和下一阶段准入结论。
