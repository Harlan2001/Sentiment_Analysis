# PRD：期货基差（IRR）

> 面向产品、开发与业务方，说明为什么做、怎么做、前端如何设计。
> 所属方向：业务覆盖主线（FICC 衍生品）

---

## 1. 背景与问题

平台当前已有「期货持仓」页，展示中金所国债期货前 20 会员的多空持仓与多空比。

**但实测下来，它的业务判断价值有限：**

| 页面上的东西 | 问题 |
|---|---|
| 持仓排名（前 20 会员多空） | 只反映"谁在持仓"，**不反映价格是否合理** |
| 多空比 0.856 | **极易被误读成交易信号** —— 但期货市场套保盘天然偏空，0.856 是常态，不是看空 |
| 持仓变化 | 滞后指标，反映的是"已经发生" |

**根本原因**：持仓数据回答的是"**谁在参与**"，而投研真正要回答的是"**期货相对现券是贵还是便宜**"。后者才是能指导决策的指标。

## 2. 这个模块解决什么

引入**期现基差**，把期货持仓从"看持仓"升级为"**看定价偏离**"。

**基差的意义**：国债期货价格与现券价格之间存在偏离，这个偏离（基差 / IRR）反映市场对资金面、交割期权、供需的预期。**期货贴水还是升水、贴水多少**，是国债期货分析的核心指标 —— 比多空比有解释力得多。

## 3. 数据源（已实测验证）

| 数据 | 接口 | 实测结果 |
|---|---|---|
| **期货行情** | 中金所 `sj/hqsj/rtj/YYYYMM/DD/index.xml` | ✅ 实测 2026-10-21 返回 482KB XML，含**开高低收、结算价、持仓量、成交量** |
| **现券收益率** | 库内 `yield_data`（已有） | ✅ 国债 9 个期限，2020 起 |

**实测样例**（2026-10-21）：

| 合约 | 收盘价 | 结算价 | 持仓量 | 成交量 |
|---|---|---|---|---|
| T2612（10年） | 109.87 | 109.885 | 418,593 | 96,064 |
| TF2612（5年） | 106.765 | 106.775 | 240,417 | 68,865 |

**合规性**：中金所官方公开数据，✅ 通过筛查（见《数据源合规与可用性筛查》）。

**已有基础**：持仓数据（`futures_position` 表）与页面**已实现**，本模块是**在其上补行情与基差**。

## 4. 本期范围

### 做
- 新增**期货日行情**取数与入库（新表）
- 计算**期现基差**（简化口径，见下）
- 页面新增**基差走势图**，与现有持仓多空比**并列展示**
- 明确标注：**研究参考，不构成交易信号**

### 不做
- **完整 CTD 券识别与转换因子精算** —— 需要券池（个券数据拿不到，见筛查结论）。本期用简化口径
- 跨期价差、跨品种价差
- 自动交易、套利信号推送
- 现券净价/全价精算

## 5. 基差口径（重要）

完整的国债期货基差需要**转换因子（CF）与 CTD 券**，而**券池拿不到**。故本期采用**简化口径**：

```
基差（简化）= 对应期限国债现券收益率 − 期货隐含收益率
```

即把期货价格与现券收益率做**方向性对照**，判断期货相对现券**偏贵还是偏便宜**，而**不宣称是可用于交割套利的标准基差**。

**页面必须写明口径**，避免用户按标准 IRR 理解。

> 若后续能拿到券池（交易所个券数据），再升级为标准基差/IRR。

## 6. 数据设计

新增 `futures_quote` 表：交易日、品种、合约、开高低收、结算价、持仓量、成交量。

**幂等**：按 `(交易日, 合约)` 唯一键去重。

**与现有表的关系**：`futures_position`（持仓排名）保持不动，本模块新增 `futures_quote`（行情），两者按交易日+合约关联。

## 7. 页面设计

### 7.1 融合位置

**在现有 `/futures` 页内增强**，不新建页面。

```
/futures（现有）
├── 多空比 + 品种对比          ← 现有
├── 合约切换 + 持仓排名表        ← 现有
└── [新增] 基差走势 + 行情摘要   ← 本模块
```

**为什么不新建页面**：基差与持仓是同一分析对象的两个视角，放一起才能互相印证；拆开会让用户来回跳。

### 7.2 新增内容

**① 行情摘要条**（顶部，与多空比并列）

```
T2612   收盘 109.87   结算 109.885   持仓 418,593   成交 96,064
```

**② 基差走势图**（主图）

```
期现基差（10年期，简化口径）
   +5bp ┤     ╱╲
        │   ╱    ╲___
    0bp ┼─╱──────────────  ← 零轴
        │╱    ╲___╱
   −5bp ┤
        └──────────────────
        08-10        10-21
```

- 零轴标出，正负一眼可辨
- 复用现有 ECharts 配置

**③ 持仓 vs 基差对照**

两个小图并排：上为多空比走势，下为基差走势 —— 让用户**自己核对**"持仓变化与基差变化是否一致"，而不是只看单一指标。

### 7.3 展示纪律（必须遵守）

| 要求 | 原因 |
|---|---|
| **标注"研究参考，非交易信号"** | 多空比与基差都不是买卖指令 |
| **写明基差为简化口径** | 无法用标准 IRR 理解 |
| **数据来源与日期常驻** | 中金所官方数据，标注更新日期 |

## 8. 怎么融合到现有产品

| 集成点 | 做法 | 是否动现有代码 |
|---|---|---|

| 计算 | 复用库内 `yield_data` | 否（只读） |

## 9. 验收标准

- [ ] 期货行情可取、可入库，字段完整（开高低收/结算/持仓/成交）
- [ ] 基差计算正确，方向与现券收益率变动一致
- [ ] 基差走势图有零轴，正负可辨
- [ ] 页面标注"研究参考，非交易信号"与"简化口径"
- [ ] 持仓数据与页面**无回归**
- [ ] 取数失败有明确报错与日志
- [ ] 幂等：重复同步不产生重复记录
- [ ] 重新导出 openapi.json

## 10. 风险

| 风险 | 应对 |
|---|---|
| 简化口径被误当标准 IRR | 页面**显著标注口径**；不提供"套利空间"类措辞 |
| 基差定义在业内不统一 | 页面写明计算方式，不预设用户理解 |
| 中金所行情接口路径变更 | 取数失败明确报错；保留手工导入兜底 |
| 现券与期货交易日不同 | 只在双方都有数据的日期计算，**不插值** |
| 后续拿到券池后口径升级 | 表结构预留，升级时新增标准基差字段而非替换 |
