# 前端信息架构

> 本文档定义后续开发各模块**在前端如何归位与展示**，是各模块 PRD「融合位置」章节的权威依据。
> 若 PRD 与本文档冲突，以本文档为准。

## 一、两条前提约束

### 约束一：投资组合板块冻结

`/portfolio`（投资组合）**本期不做任何改动**：

- 不接真实后端、不替换演示数据、不改 UI、不改交互
- 保持现状（含页面上的演示功能标注）
- 不在任何模块中新增"组合会用到 XX"的关联承诺
- 券池不再以"组合的地基"作为存在理由

### 约束二：不新增"大 FICC 模块"

**不做**"一个 FICC 大模块下挂多个子模块"的结构。理由：

1. **会造成两套世界**。现有导航按**对象类型**划分（市场/因子/收益/预测…）。再开一个"FICC"维度，用户需先判断目标属于哪个世界，且收益率、因子等概念会在两个世界重复出现。
2. **会混入不同性质的东西**。预测诊断与回测仿真**不是市场数据**，而是"关于平台自己准不准"的元分析。放进"FICC 数据"模块属分类错误。
3. **叙事失真**。平台主体仍是中国利率债，FICC 是扩展维度。抬成与"市场"并列的一级模块，与实际权重不符。

**替代原则**：按**"用户什么时候会想看它"**归位，而非按技术模块归位。

## 二、归位总表

| 模块 | 归位方式 | 位置 |
|---|---|---|
| 预测诊断 | **并入现有页面子标签** | `/forecast` → 「历史战绩」 |
| 政策事件日历 | **并入现有页面子标签** | `/returns` → 「政策日历」 |
| 回测仿真 | **并入现有详情页区块** | `/factor/:factorId` → 「历史表现」 |
| 信用利差 | **新标签页的子视图** | `/cross-asset` → 「信用利差」 |
| 外部市场数据 | **新标签页的子视图** | `/cross-asset` → 「海外利率」+「商品」 |
| COT 期货持仓排名 | **新标签页的子视图** | `/cross-asset` → 「期货持仓」 |
| 债券档案（券池） | **新标签页** | `/bonds` |

**归位逻辑**：

- **跟着被诊断的对象走**：诊断类（预测诊断、回测仿真）必须长在**被诊断功能旁边**。放到别处，用户需在两个页面间来回跳，且很难意识到"原来还能核查"。
- **同性质的事件并入现有日历**：`/returns` **本身就是一个日历页**（收益日历：月历 + 选中日看当天新闻/因子/收益率）。政策事件天然是"某天发生了什么"，同一个交互范式，直接复用。
- **跨市场数据集中一个入口**：信用利差、海外利率、商品、期货持仓四者同属"国债之外的新品类/新市场"。**若各占一个顶级标签，市场板块会从 6 个涨到 10 个，标签栏挤爆**。合并为一个 `跨资产`、内部二级切换，是唯一可行做法。

## 三、导航结构

### 顶级导航（市场板块）

**只新增 2 个标签，追加在末尾**，现有 6 个标签顺序不动：

```
市场 | 因子 | 收益 | 预测 | 关注列表 | 投资组合 | 券池 | 跨资产
                                          ↑冻结↑   ↑新增   ↑新增
```

**为什么追加在末尾而非插在中间**：现有 6 个标签是用户已形成的肌肉记忆，插入会打乱。新增项放末尾，零干扰。

**为什么不把券池放在投资组合前面**：原方案放在组合前是为了暗示"组合建立在券池之上"。但组合已冻结，**不做这种关联暗示**。

### 子标签（并入现有页面）

```
/forecast          → [预测报告] [历史战绩]      ← 现有 + 1
/returns           → [收益日历] [政策日历]      ← 现有 + 1
/factor/:factorId  → 因子定义 / 关联新闻 / [历史表现]  ← 现有 + 1 区块
```

标签切换交互直接照抄 `/factors` 页已有的「因子信号 / 宏观数据」双标签模式。

### 新标签页内部结构

```
/bonds          单页（列表 + 详情）
/cross-asset    内部二级标签：[信用利差] [海外利率] [商品] [期货持仓]
```

### 完整导航图

```
市场板块
├── 市场                      （现有，不动）
├── 因子                      （现有，不动）
├── 收益                      （现有，不动）
│   └── + 政策日历            ← 政策事件日历

    ├── 信用利差              ← 信用利差
    ├── 海外利率              ← 外部市场数据（美债 + 中美利差 + 汇率）

```

## 四、各位置展示什么

### 4.1 `/forecast` → 历史战绩

**三张周期卡片**（日 / 周 / 月），每张：

```
日度预测                [有效 / 噪音 / 风险]
  命中率   61.8%
  无脑基准 80.3%   ▼ −18.5pt
  平均误差 2.06bp
  样本 76
```

**中部：校准度双折线图**（主指标）
- 折线 A：预测"看涨"占比
- 折线 B：实际上涨占比
- 两条线长期背离 = 存在系统性方向偏置

**下部：置信度分档表**

**强制要求**：命中率旁必须同时显示**多数类基准**（方向预测的正确对照线不是 50%）；样本数常驻；样本 < 20 的分档隐藏；页面固定说明"对照基准是多数类基准"。

### 4.2 `/factor/:factorId` → 历史表现

```
历史表现                    计算于 2026-10-21
基于 1,917 次历史事件（2022-01 ~ 2026-10）

持有期   样本    方向命中率   平均变动   中位数
T+1    1,891    54.2%      −0.8bp    −0.5bp
T+5    1,845    58.7%      −2.1bp    −1.8bp
T+20   1,702    61.3%      −5.4bp    −4.9bp

⚠ 命中率对照：多数类基准 62.1%

▁▂▃▅▂▁ 分年度命中率（看稳定性）
```

**分年度走势条是本区块最有价值的部分**——回答"这个因子是一贯有效，还是只在某个市场环境下有效"。

### 4.3 `/returns` → 政策日历

**月历**：色块深浅表示当天政策事件数（非精确数字，一眼看密集度）。复用现有收益日历的月网格实现。

**选中日事件列表**：每条含标题、来源（沿用脱敏规则显示"数据源1/2"）、方向标签、关联 POLICY 因子；操作为「查看原文」（跳 `/news/:newsId`）与「剔除」。

**确认 / 剔除**：新事件默认"待确认"；支持批量确认与剔除；剔除后不进正式视图但保留记录，提供"已剔除"查看与恢复入口。

### 4.4 `/cross-asset` → 四个子视图

| 子视图 | 主数字卡 | 主图 | 辅助 |
|---|---|---|---|
| **信用利差** | 当前 10Y 利差、历史分位 | 利差时间序列（可切期限） | 信用债 vs 国债双曲线、当日期限结构 |
| **海外利率** | 中美利差、美债 10Y、USDCNH | **中美利差走势**（本模块最有价值产出） | 美债曲线 2Y/10Y/30Y、USDCNH 折线 |
| **商品** | 各品种现价 | 品种价格走势（可切品种） | 与 10Y 国债收益率的相关性表 |
| **期货持仓** | 多空比、数据日期 | **多空比走势** | 前 20 会员持仓排名表、净多空变化 |

**子视图共同要求**
- 顶部标注**数据来源与数据日期**
- 各子视图明确标注**数据频率**（日度/月度）
- 均复用现有 ECharts 能力

### 4.5 `/bonds` → 券池

**列表页**：代码 / 名称 / 类别 / 评级 / 到期日 / 剩余期限；筛选维度为类别、评级、剩余期限；支持搜索；分页。

**详情页** `/bond/:bondCode`：基本信息卡（身份 + 要素）+ 类别归属。**本期不放行情图**（无行情数据）。

**Excel 导入**：有成功/跳过/失败统计；幂等，重复导入不产生重复记录。

## 六、实施注意

### 6.1 需要小幅抽取的现有组件

| 组件 | 用途 | 要求 |
|---|---|---|
| `ReturnsPage` 的月历 | 政策日历复用 | 抽取为公共组件时**保持收益日历行为完全不变** |

这是本方案**唯一需要动现有前端代码**的地方（抽取组件），且可通过补测试保证不回归。

### 6.2 导航配置的改动方式

现有导航由 `frontend/src/config/routes.ts` 驱动：
- `tabLabel` → 市场板块标签
- `navLabel` → 侧边栏入口
- 元素映射在 `frontend/src/routes.tsx`

新增标签**只需在两处各加一行配置**，不需要改导航组件本身。

### 6.3 新增路由清单

| 路由 | 页面 |
|---|---|
| `/bonds` | 券池列表 |
| `/bond/:bondCode` | 券池详情 |
| `/cross-asset` | 跨资产（默认进信用利差） |

### 6.4 所有新模块的集成注意

Agent 与 MCP 的工具清单来自**打包文件** `backend/agent/data/openapi.json`（2026-09-03 导出）。**新增接口后必须重新导出该文件**，否则 AI 对话与 MCP 客户端无法调用新接口。

### 6.5 与投资组合的边界

- 本期**不新增**任何指向 `/portfolio` 的入口或跳转
- 券池页面**不提供**"加入组合"之类操作
- 组合页保持现状，其演示数据标注不变
- 后续若解冻组合，需**单独评估**券池与组合的对接方案
