# PRD：信用利差

> 本文档面向产品、开发与业务方，说明这个模块为什么做、怎么做、前端如何设计。
> 所属方向：业务覆盖主线（信用债 —— FICC 的 "C"）

---

## 1. 背景与问题

**平台只有国债一个品种，FICC 的核心——信用——完全空白。**

实测确认：`yield_data` 表只装国债收益率，共 9 个期限（3M/6M/1Y/2Y/3Y/5Y/7Y/10Y/30Y），表注释写的就是"国债收益率数据表"。**没有任何信用债数据。**

后果很直接：**一个只能看利率债的平台，在债券投研团队眼里只是半个工具。** 信用债是中国债券市场的主体部分，信用利差（信用债收益率 − 同期限国债收益率）是衡量市场风险偏好的核心指标之一。

## 2. 这个模块解决什么

引入**信用债曲线**，并计算**信用利差**，让平台第一次能看到"信用"这个维度。

## 3. 数据来源：复用现有下载器，只加一个参数

这是本模块最重要的技术发现。

平台现有的 `bond_downloader.py` 从中债网站下载收益率 Excel。实测发现——**信用债曲线走的是同一个接口**，只需要改一个参数：

| 参数 | 现有（国债） | 信用债 |
|---|---|---|
| `nameType` | `1` | **`2`** |

- `nameType=1` → 国债收益率曲线（现有功能）
- `nameType=2` → **中短期票据收益率曲线**（本模块需要）

实测验证：`nameType=2` + `gjqx=0` 能一次返回 2026-09-01 ~ 2026-10-20 的 **1/2/3/5/7/10/15/20/30 年完整数据**。

**这意味着信用债取数的开发量极小**——复用现有下载器结构，改一个参数，多一条下载链路。

## 4. 本期范围

### 做
- 新增一条**中债信用债曲线下载**（复用现有下载器结构）
- 新建独立表存曲线数据
- **计算利差**：同日期、同期限的信用债收益率 − 国债收益率（相减即得）
- **展示**：期限利差曲线 + 当前利差的历史分位
- 信用债新闻打标签：新增 `CREDIT_EVENT` 因子类别（违约/评级下调/展期），复用现有分析管线

### 不做
- **评级分档**（AAA/AA+/AA）—— 见下节说明
- 自动定时下载（先手工跑通验证）
- 信用-利率轮动信号
- 信用违约模型、信用债定价

## 5. 为什么不承诺评级分档

原始需求希望按 AAA / AA+/AA 分别看利差——这是行业常规做法。但**技术上做不到**：

实测中债该端点的参数组合：
- `nameType=1` → 国债收益率曲线
- `nameType=2` → 中短期票据收益率曲线（**整体曲线，不分评级**）
- `nameType≥3` → **返回错误页**（不是 Excel，是 HTML 错误页）

也就是说，**该端点只提供"中短期票据"的整体曲线，不提供分评级曲线**。

因此本期**只做整体曲线利差**。若要评级分档，需要：
1. 另找带评级的曲线数据源（中债其它端点、或其它数据商），或
2. 用券池（见《PRD：债券档案》）自行按评级聚合

两条路都超出本期范围，**明确列入后续**。

## 6. 数据设计

**新增独立表**，字段：日期、期限、收益率值。

**关键决策：不改 `yield_data` 的主键。**

`yield_data` 现在是 `(date, period)` 复合主键，只装国债。如果要把信用债塞进同一张表，必须改成 `(date, period, bond_type)`，这会牵动**四处下游查询**：

- `backend/common/db_yield.py`
- `backend/routers/discover.py`
- `backend/routers/returns.py`
- `backend/dashboard/dashboard_service.py`

**这属于大规模改动**，违背"优先新板块、不碰现有逻辑"的原则。所以**新建独立表彻底绕开**——信用债数据独立存储，利差在查询时与国债相减计算。

> 后续若品类变多（信用债 + 国开 + 地方债 + …），再统一评估是否需要"通用曲线表"。那是独立的重构需求，不与本模块混做。

## 7. 页面设计

### 7.1 融合位置

**放在新增的 `/cross-asset`（跨资产）页，作为「信用利差」子视图。**

```
/cross-asset
├── [信用利差]   ← 本模块
├── [海外利率]   ← 美债 / 中美利差 / 汇率
├── [商品]       ← 商品行情
└── [期货持仓]   ← COT
```

**为什么集中在这里**：信用利差、海外利率、商品、期货持仓同属"国债之外的新品类/新市场"。**若各占一个顶级标签，市场板块会从 6 个涨到 10 个，标签栏挤爆**。合并为一个 `跨资产`、内部二级切换，是唯一可行做法。

**为什么不放进 `/returns`**：收益页已承载「政策日历」子标签，再放信用利差会让该页主题过散；且信用利差的心智是"看新品种"，与跨资产其它视图一致。

> 详细归位依据见《前端信息架构.md》。

### 7.2 利差曲线视图

**主图：分期限的利差曲线**

```
信用利差                       1年 | 3年 | 5年 | 10年  （期限切换）
┌──────────────────────────────────────────────┐
│  当前 10Y 信用利差  40.0bp                     │
│  ─────────────────────────────               │
│  历史分位  62%     近1年区间  28 ~ 55bp        │
│                                              │
│      ╱╲    ╱╲                                │
│    ╱    ╲╱    ╲___                          │
│  ╱                                           │
│ └──────────────────────────────────────────┘ │
│  2024-01                        2026-10      │
└──────────────────────────────────────────────┘
```

- **主数字**是当前利差 + 历史分位（分位比绝对值更有信息量——利差 40bp 是高是低，要看它相对历史的位置）
- 图表复用现有 ECharts（项目已用于技术分析、宏观指标等）

**对比图：信用债 vs 国债曲线**

同时画出信用债与同期限国债两条收益率曲线，让用户直观看到利差的空间。

### 7.3 信用事件标签

复用现有新闻分析管线：给信用债相关新闻打标签（**违约 / 评级下调 / 展期**），新增 `CREDIT_EVENT` 因子类别。

**注意**：现有因子类别枚举（POLICY / MACRO / LIQUIDITY / RISK / SENTIMENT / INDUSTRY）在代码中是**写死的**，需要加一个枚举值。**这是本模块自身的前置条件，改动仅限枚举值，不触碰 prompt 主体逻辑与调用链。**

## 8. 怎么融合到现有产品

| 集成点 | 做法 | 是否动现有代码 |
|---|---|---|
| 前端入口 | 新增 `/cross-asset` 页的「信用利差」子视图 | 是（新增页面，不改现有页面） |
| 后端取数 | **复用** `bond_downloader.py` 结构，新增信用债下载 | 否（新增独立下载函数） |
| 后端接口 | 新增信用利差查询路由 | 否（纯新增） |
| 数据表 | **新建独立表，不改 `yield_data`** | 否 |
| 因子类别 | 新增 `CREDIT_EVENT` 枚举值 | 是（改一个枚举值，本模块前置条件） |
| 新闻分析管线 | **完全复用**，不改分析逻辑 | 否 |
| 投资组合 | **不涉及**（该板块本期冻结） | 否 |
| Agent / MCP | 新增接口后需**重新导出** `backend/agent/data/openapi.json` | 需重新导出 |

## 9. 验收标准

- [ ] 能取到中债中短期票据曲线数据，期限覆盖 1/2/3/5/7/10/15/20/30 年
- [ ] 利差计算正确（同日期同期限信用债 − 国债）
- [ ] 利差曲线与历史分位展示正确
- [ ] **未改动 `yield_data` 表结构**，四处下游（db_yield / discover / returns / dashboard_service）行为无回归
- [ ] 信用债新闻能被打上 `CREDIT_EVENT` 标签
- [ ] 现有国债下载功能**完全不受影响**
- [ ] 取数失败有明确报错与日志，不静默失败
- [ ] 重新导出 openapi.json，Agent/MCP 能调用新接口

## 10. 风险与注意

| 风险 | 说明 | 应对 |
|---|---|---|
| 中债接口参数变更 | 站点改版导致取数失败 | 取数失败**必须明确报错并记录**；保留手工导入兜底路径 |
| 只有整体曲线 | 无法按评级看利差 | 已在文档中明确本期不承诺；后续另寻数据源或用券池聚合 |
| 与国债数据日期不齐 | 利差算不出来 | **只在双方都有数据的日期计算利差**，不插值 |
| 误改 `yield_data` 主键 | 牵动四处下游 | **强制新建独立表**，验收项单列检查 |
| 因子枚举改动 | 影响现有分析 | 改动仅限枚举值；新增类别不改现有六类行为 |
| 利差数据的起始时间 | 新表数据从上线日开始积累 | 首次导入时**尽可能回溯下载历史**（现有下载器支持最长 1 年窗口） |
