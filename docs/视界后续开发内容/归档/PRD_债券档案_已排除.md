# PRD：债券档案（券池）

> 本文档面向产品、开发与业务方，说明这个模块为什么做、怎么做、前端如何设计。
> 所属方向：业务覆盖主线（FICC 的地基）

---

## 1. 背景与问题

平台目前**没有"债券"这个实体**。

实测确认：全库**没有任何债券主数据表**。这导致一连串问题：

- **投资组合页的持仓是假的**。页面上显示的"23国开10 / 24附息国债04 / 24中电投MTN018"这些债券及其权重、收益率、久期，**全是硬编码在代码里的字符串**，不来自任何数据源。
- **连"关注某只债券"都做不到**。关注列表（`/watchlist`）只支持三种对象：新闻、因子、宏观信号。债券不在其中。
- **后续一切都缺地基**。组合、持仓、敞口、信用分析，**全都需要一个"债券"实体**作为锚点。

换句话说：平台能分析"市场"，但**无法表达"某一只具体的债"**。

## 2. 这个模块解决什么

建立平台的**债券主数据**，回答"我们说的是哪只债"。

**它的价值有三层**：

1. **让平台能表达"某一只具体的债"**——现在只能分析"市场"，无法指向具体标的
2. **为信用利差的券级深度铺路**——信用利差若要从"一条整体曲线"深化到"按评级/类别聚合"，需要券级数据
3. **未来的地基**——持仓、敞口等能力都需要债券实体（但**本期不做这些**）

**明确说明**：本模块**不以"投资组合的基础"作为存在理由**。投资组合板块本期冻结，本模块与组合**不做关联**。

## 3. 本期范围

### 做
- **债券要素的增删改查**：债券代码、名称、类别、发行人、评级、到期日、票面利率、发行规模、行业
- **Excel 批量导入**：照抄现有收益率 Excel 的导入模式，支持一次导入多只
- **列表页**：按类别、评级、剩余期限筛选，支持搜索
- **详情页**：展示债券要素，以及它关联的类别信息

### 不做
- 估值、行情、净价/全价、应计利息
- 久期、DV01、凸性等风险指标计算
- 与外部数据源自动同步（Wind/中债直连）
- 持仓、交易、限额

### 说明
本期只做**静态要素**。一只债券"是什么"先搞清楚，"它现在值多少钱、风险有多大"留到后续。

## 4. 数据设计

新增独立表，字段分为三组：

**身份**：债券代码、名称、类别

**要素**：发行人、评级、到期日、票面利率、发行规模、行业

**项目惯例字段**（必须带）
- `owner_username` —— 项目所有表都是这个多租户模式，不是独立租户库
- `deleted_at` —— 软删，与现有仓储模式一致

**参考模板**：`workbench_watchlist_items` —— 现成的最轻量表结构，含 `owner_username` + 软删，直接照抄。

**类别枚举**建议与现有组合约束分析保持一致（后端 `portfolio_analysis.py` 已定义 9 类：国债、地方政府债、公司信用债、金融债（不含政策性）、其它债券、政策性金融债、政府支持机构债、同业存单、资产支持证券）。**复用这套分类，不要另立一套**，否则后续组合模块对不上。

## 5. 页面设计

### 5.1 融合位置

**作为市场板块的新标签页 `/bonds`，追加在末尾。**

```
市场板块： 市场 | 因子 | 收益 | 预测 | 关注列表 | 投资组合 | [券池]
                                                          ↑新增，追加末尾
```

**为什么追加在末尾而非插在中间**：现有 6 个标签是用户已形成的肌肉记忆，插入会打乱。新增项放末尾，零干扰。

**为什么不在它旁边放"投资组合"的关联暗示**：组合板块**本期冻结**（不动前端、不接真实后端），因此本模块**不做任何指向组合的关联或跳转**，独立存在。

**页面形态**：单页（列表 + 详情），内部不需要二级标签。

> 详细归位依据见《前端信息架构.md》。

### 5.2 列表页

```
┌──────────────────────────────────────────────────────┐
│ 债券档案                        [导入 Excel] [新建债券]  │
├──────────────────────────────────────────────────────┤
│ 🔍 搜索代码或名称   类别 ▾   评级 ▾   剩余期限 ▾         │
├──────────────────────────────────────────────────────┤
│ 代码        名称           类别      评级  到期日  剩余  │
│ 230210     23国开10       政策性金融债 AAA   2030-01  3.2年│
│ 240004     24附息国债04   国债       AAA   2031-06  5.6年│
│ ...                                                  │
├──────────────────────────────────────────────────────┤
│ 第 1 / 5 页 · 共 98 只债券          [上一页] [下一页]    │
└──────────────────────────────────────────────────────┘
```

- 筛选维度：**类别 / 评级 / 剩余期限**（剩余期限由到期日与当天计算，不存库）
- 剩余期限分档建议：1 年以内、1–3 年、3–5 年、5–10 年、10 年以上
- 参考范式：`/factors` 页的筛选下拉与分页，直接复用其交互与样式

### 5.3 详情页

复用现有详情页的路由模式（`/factor/:factorId`、`/yield/:period` 已有先例），新增 `/bond/:bondCode`。

展示：基本信息卡（身份 + 要素）+ 该债券的类别归属。**本期不放行情图**（没有行情数据）。

### 5.4 Excel 导入

- 复用现有 `GovernmentBonds.xlsx` 的导入模式（pandas 读表 → 字段映射 → `INSERT IGNORE` 去重）
- 必须有**导入结果反馈**：成功 N 条、跳过 M 条（重复）、失败 K 条及原因
- 导入任务**必须幂等**：重复导入同一文件不产生重复债券

## 6. 怎么融合到现有产品

| 集成点 | 做法 | 是否动现有代码 |
|---|---|---|
| 前端导航 | 市场板块新增标签页（追加末尾） | 是（`config/routes.ts` 加一行 + 元素映射加一行） |
| 前端路由 | 新增 `/bonds`（列表）与 `/bond/:bondCode`（详情） | 否（纯新增） |
| 后端 | 新增 repository + router，`app.py` 注册 | 否（纯新增） |
| 投资组合 | **不涉及**——该板块本期冻结，**不做任何关联或跳转** | 否 |
| 关注列表 | **本期不做**（加 `'bond'` 枚举值属触碰现有结构） | 否 |
| Agent / MCP | 新增接口后需**重新导出** `backend/agent/data/openapi.json` | 需重新导出 |

**关于关注列表**：现有 `workbench_watchlist_items` 的 `object_type` 枚举为 `('news','factor','macro_signal')`，加 `'bond'` 只需改一个枚举值，价值也明显。但按"优先新板块、不碰现有逻辑"的原则，**本期不做**，留待后续。

## 7. 验收标准

- [ ] 能新建、编辑、删除（软删）债券，要素字段完整
- [ ] Excel 批量导入正确，重复导入不产生重复记录，有成功/跳过/失败统计
- [ ] 列表页按类别、评级、剩余期限筛选正确，搜索可用
- [ ] 详情页展示完整要素
- [ ] 数据按用户隔离（`owner_username`）
- [ ] 类别枚举与 `portfolio_analysis.py` 的 9 类一致
- [ ] 剩余期限由到期日实时计算，不存冗余字段
- [ ] 重新导出 openapi.json，Agent/MCP 能调用新接口

## 8. 后续如何被复用

本模块**当前独立存在**，不绑定任何单一功能。可能的后续用途（均不在本期）：

- **信用利差的券级深化**：把市场级整体利差，深化为按评级/类别/行业的聚合利差
- 持仓台账与敞口计算（需先有行情数据）
- 关注列表支持债券标的

**注意**：投资组合板块本期冻结，**不在其列**。若后续解冻组合，需**单独评估**券池与组合的对接方案。

## 9. 风险与注意

| 风险 | 说明 | 应对 |
|---|---|---|
| 与组合模块的类别定义不一致 | 后续信用利差按类别聚合时对不上 | **强制复用** `portfolio_analysis.py` 的 9 类枚举（复用其**分类定义**，不涉及组合功能） |
| 债券代码格式不统一 | 银行间/交易所代码体系不同 | 代码字段存原始值，不做格式校验，另设"市场"字段区分 |
| 评级口径混乱 | 外部评级 vs 中债隐含评级 | 字段命名为"评级"并注明口径，本期不区分 |
| Excel 列名不固定 | 用户上传的表各异 | 做模糊匹配（照抄 `yield_db.py` 的期限列匹配逻辑） |
| 与组合板块的关系被误解 | 用户以为券池是组合的一部分 | 券池**独立成页**，页面不提供任何"加入组合"类操作 |
