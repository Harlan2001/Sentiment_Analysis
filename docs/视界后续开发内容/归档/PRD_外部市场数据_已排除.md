# PRD：外部市场数据（美债 / 汇率 / 商品）

> 本文档面向产品、开发与业务方，说明这个模块为什么做、怎么做、前端如何设计。
> 所属方向：业务覆盖主线（海外债 + 全品类商品）

---

## 1. 背景与问题

平台的跨资产维度是空白的。需求里包含**海外债**与**全品类商品**两项，本质是同一类问题：**平台看不到债券市场之外、但会显著影响债券市场的那些价格。**

具体缺失：

- **美债**：全球利率的锚。中美利差是资本流动与人民币汇率的核心驱动之一。平台看不到。
- **汇率**：USDCNH 与国债收益率的联动，是跨境资金分析的基础。平台看不到。
- **商品**：原油、铜、螺纹钢等与通胀预期直接相关，而通胀预期是债市定价的关键变量。平台看不到。

> 附带说明：平台**已有**商品/汇率相关的**因子**（如 `OIL_PRICE`、`USD_INDEX`、`US_TREASURY_YIELD`、`CN_US_SPREAD`），但那些是从新闻里提取的**概念因子**，**没有对应的实际价格数据**。本模块补的是数据本身。

## 2. 这个模块解决什么

把美债、汇率、商品三类市场数据接进来，**让平台能看到跨资产的价格与联动**。

## 3. 为什么三类合并在一个模块

它们的技术实现**完全相同**，都是同一个套路：

```
调接口 → 解析 → 入新表 → 查询 → 展示
```

**合在一起做，只需写一次取数骨架**，后面每加一类只是加一个数据源配置。拆成三个独立模块反而要重复三次。

## 4. 数据来源（均已实测可达）

| 类型 | 数据源 | 实测结果 |
|---|---|---|
| **美债** | 美国财政部官方 CSV，免密钥 | ✅ 返回 16KB，含 1Mo–30Y 全曲线，数据到 2026-10-20 |
| **汇率** | 新浪行情 `fx_susdcnh` | ✅ 当日 USDCNH |
| **商品** | 新浪行情 `nf_RB0 / nf_SC0 / nf_CU0 / nf_I0` | ✅ 当日螺纹钢、上海原油、铜、铁矿石 |

**美债备用源**：FRED（`fredgraph.csv?id=DGS10`）也可用，作为主源失效时的备份。

**说明**：早前曾依据配置项 `OUTBOUND_PROXY_ENABLED=false` 判断"内网无外网"、建议不做跨资产。**该判断有误**——那个开关只表示"不走代理"，不代表没有外网。实测上述数据源**全部可达**。

## 5. 本期范围

### 做
- 一个取数模块覆盖三类，**共用同一套"下载 → 解析 → 入库 → 记账"骨架**
- **美债**：存 2Y / 10Y / 30Y 关键期限
- **中美利差**：中债 10Y（已有 `yield_data`）− 美债 10Y
- **汇率**：USDCNH 日值
- **商品**：螺纹钢、上海原油、铜、铁矿石（可加黄金）
- 展示：美债曲线、中美利差走势、USDCNH、商品走势、**商品与 10Y 国债收益率的简单相关性**

### 不做
- 海外央行议息日历（需人工维护）
- 多国债券收益率曲线
- 资本流动建模
- 商品-通胀传导建模
- 期货合约展期处理（只取主力连续合约的收盘价）
- 商品持仓量、库存等深度数据

## 6. 数据设计

三类数据各自建表或共表，字段均为：日期、指标标识、数值。

**取数骨架**（三类共用，一次写好）：
```
下载 → 落原始文件 → 解析 → 按唯一键去重入库 → 记录任务日志 → 返回统计
```

**幂等要求**：按 `(日期, 指标)` 唯一键去重，重复执行不产生重复记录。

**任务可观测**：复用现有 `task_runs` / `task_events` 机制，不另建。

## 7. 页面设计

### 7.1 融合位置

**放在新增的 `/cross-asset`（跨资产）页，拆成「海外利率」与「商品」两个子视图。**

```
/cross-asset
├── [信用利差]   ← 信用债曲线与利差
├── [海外利率]   ← 本模块：美债曲线、中美利差、USDCNH
├── [商品]       ← 本模块：原油 / 铜 / 螺纹钢 / 铁矿石
└── [期货持仓]   ← COT
```

**为什么集中在这里**：四者同属"国债之外的新品类/新市场"。**若各占一个顶级标签，市场板块会从 6 个涨到 10 个，标签栏挤爆**。

**为什么不放进 `/factors` 页的"宏观数据"视图**（原方案）：

- 该视图是**月度**指标体系（横轴为 `YYYYMM`），而本模块是**日度**数据，混在一起会让横轴口径打架
- 因子页的主题是"因子"，跨市场行情硬塞进去语义不搭
- 现有 `macro_indicator_data` 表**保持不动**，本模块用独立表

> 详细归位依据见《前端信息架构.md》。

### 7.2 展示内容

**中美利差**（本模块最有业务价值的产出）

```
中美利差（10Y）
┌──────────────────────────────────────┐
│  当前  中债 1.70%  −  美债 5.12%      │
│        利差  −342bp                   │
│  近1年区间  −380 ~ −280bp              │
│                                      │
│   ╲___╱╲    ╱╲___                    │
│         ╲__╱      ╲___               │
│ └──────────────────────────────────┘ │
│  2024-01                  2026-10    │
└──────────────────────────────────────┘
```

**美债曲线**：复用现有宏观数据图表的多指标对比能力，画 2Y/10Y/30Y 三条线。

**商品与 10Y 相关性**：一个简单的相关性表格（皮尔逊相关系数），回答"哪些商品价格与国债收益率同向/反向"。

### 7.3 横轴口径

现有"宏观数据"视图是**月度**指标，本模块是**日度**数据。两者**分开在两处展示，不混用同一视图**——避免横轴口径打架（本模块在 `/cross-asset`，宏观数据仍在 `/factors`）。

本模块内部统一按日度横轴绘制。

## 8. 怎么融合到现有产品

| 集成点 | 做法 | 是否动现有代码 |
|---|---|---|
| 前端入口 | 新增 `/cross-asset` 页的「海外利率」「商品」子视图 | 是（新增页面，不改现有页面） |
| 图表能力 | **复用**现有 ECharts 多指标对比能力 | 否（复用） |
| 后端取数 | 新增三类下载器，**共用一套骨架** | 否（纯新增） |
| 后端接口 | 新增查询路由 | 否（纯新增） |
| 数据表 | 新建独立表 | 否 |
| 现有 `yield_data` | **只读复用**（取中债 10Y 算利差），不改结构 | 否 |
| 现有 `macro_indicator_data` | **不动**（月度为独立体系） | 否 |
| 因子页"宏观数据"视图 | **不动** | 否 |
| 投资组合 | **不涉及**（该板块本期冻结） | 否 |
| Agent / MCP | 新增接口后需**重新导出** `backend/agent/data/openapi.json` | 需重新导出 |

## 9. 验收标准

- [ ] 美债曲线可取，2Y/10Y/30Y 入库正确
- [ ] 中美利差计算正确，且**只在双方都有数据的日期计算（不插值）**
- [ ] USDCNH 可取
- [ ] 商品 4–5 个品种日收盘入库正确
- [ ] 商品与 10Y 相关性可展示
- [ ] 取数失败有明确报错与日志，不静默失败
- [ ] 现有因子页"宏观数据"视图**行为无回归**
- [ ] 重新导出 openapi.json，Agent/MCP 能调用新接口

## 10. 风险与注意

| 风险 | 说明 | 应对 |
|---|---|---|
| **商品取数必须用 `nf_` 前缀** | 实测踩到：`RB0` 不带前缀会返回 **2024-07-17 的旧数据**，看起来"有值"但全是过期数据 | 代码强制 `nf_` 前缀；验收时**检查日期是否为近期**，不只看有无返回 |
| 中美交易日不同 | 利差日期对不齐 | **只在双方都有数据的日期计算，不插值** |
| 新浪接口需要 Referer | 直接请求可能被拒 | 请求头带 `Referer: https://finance.sina.com.cn` |
| 新浪接口非正式 API | 可能变更或限流 | 取数失败明确报错；美债已有 FRED 备用源；商品可先降级为手工导入 |
| 现有图表是月度横轴 | 日度数据展示异常 | 复用组件时需**支持日度横轴**；这是主要的改造点 |
| 商品只取主力连续合约 | 换月时价格跳空 | 本期**不做复权处理**，页面注明"主力连续合约，未复权" |
| 与现有宏观指标混淆 | 用户分不清日度/月度 | 视图内**明确标注数据频率** |
