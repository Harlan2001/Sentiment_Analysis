# PRD：本周开发——Skills 实际接入与项目制完善（基础版）

> 文档状态：Skills 待评审；项目制需求已确认
> 计划周期：2026-09-07 至 2026-09-13
> 需求依据：`docs/后续功能开发顺序.md` 第一阶段、第二阶段
> 本周原则：只完成最简单、最基础、能够真实使用的功能闭环

## 1. 本周目标

本周只开发两部分：

1. **Skills 实际接入**：用户能够管理 Skill，并在真实对话中选择 Skill，使模型按照 Skill 指令和输出要求回答。
2. **项目制完善**：项目成员、管理者/编辑者两类角色和项目内容权限在前后端真实生效，不依赖前端隐藏按钮模拟权限。

本周不追求复杂配置、自动化处理或高级协作。页面上能操作但没有后端数据、真实权限或真实模型调用的功能，不算完成。

## 2. 功能状态标记

文档和后续页面统一使用以下口径：

| 标记 | 含义 |
| --- | --- |
| 已有真实功能 | 已有真实接口、后端数据和实际业务效果 |
| 本周完善 | 已有基础代码，但需要补齐后才能正式使用 |
| 前端 Mock / 演示 | 固定数据、模拟结果或只改变页面状态，不是正式功能 |
| 后续开发 | 不在本周范围 |

对于前端 Mock 或未完成能力，页面必须显示“演示内容”或“即将开放”，不得让用户误认为已经真实可用。

## 3. PRD A：Skills 实际接入

### 3.1 基础使用流程

1. 用户进入 Skills 页面，查看系统 Skill 和“我的 Skill”。
2. 用户可以启用一个只读的系统 Skill，或者创建自己的 Skill。
3. 用户发布自己的 Skill 后，在对话输入区选择本次要使用的 Skill。
4. 用户发送问题，后端校验 Skill 权限和状态。
5. 后端把选中 Skill 的指令和输出格式加入模型上下文。
6. 模型按 Skill 要求生成回答。
7. 会话记录显示本次使用过的 Skill 名称。

完成以上流程，即视为本周 Skills 的核心闭环完成。

### 3.2 当前功能状态

#### 已有真实功能

- 用户 Skill 已有后端创建、编辑、发布、停用和删除接口；
- 用户 Skill 已保存到数据库，并按登录用户隔离；
- Skill 已保存名称、使用场景、分析指令、输出格式、状态和版本号；
- 已发布的个人 Skill 可以在对话中选择；
- 发送消息时，后端会重新校验 Skill 所属用户和发布状态；
- 选中的 Skill 指令已经能够加入模型上下文；
- 消息会保存本次使用的 Skill 名称；
- Skill 附件已有真实上传和文件保存基础。

#### 本周完善

- 系统 Skill 从后端读取，不再把前端写死列表作为正式数据；
- 系统 Skill 保持只读，普通用户不能修改或删除；
- 用户可以把系统 Skill 启用到“我的 Skill”，也可以停用；
- 已启用的系统 Skill 可以在对话中选择和实际调用；
- 输出格式与分析指令一起加入模型上下文，使 Markdown 或纯文本要求真实生效；
- 附件数量在后端限制，删除附件或永久删除 Skill 时同步清理磁盘文件；
- 补齐 Skill 状态、用户隔离和真实调用的基础测试；
- 保存、上传或调用失败时，前端显示真实错误，不显示模拟成功。

#### 当前前端 Mock / 演示

- 当前“系统 Skills”卡片来自前端固定数据，不是后端系统 Skill；
- 当前点击“添加”实际创建的是一条个人 Skill，不是系统 Skill 启用关系；
- 当前附件虽然能够上传保存，但附件内容没有进入模型上下文。

其中前两项本周改为真实功能。附件内容解析和注入模型不在本周开发，页面需要明确说明“附件已保存，本期暂不参与 AI 回答”。

### 3.3 系统 Skill 基础规则

- 系统 Skill 至少包含：ID、名称、使用场景、分析指令、输出格式、发布状态和版本号；
- 系统 Skill 由平台统一维护，普通用户只读；
- 用户点击“启用”后，后端保存当前用户与系统 Skill 的启用关系；
- 用户点击“停用”后，该 Skill 不再出现在其对话可选列表；
- 系统 Skill 本身未发布或已停用时，用户不能继续用于新消息；
- 系统 Skill 的启用状态按用户隔离，不影响其他用户；
- 本周不提供普通用户复制、编辑或自定义系统 Skill 的能力。

### 3.4 用户 Skill 基础规则

用户 Skill 包含以下字段：

| 字段 | 基础规则 |
| --- | --- |
| 名称 | 必填 |
| 使用场景 | 必填 |
| 分析指令 | 必填 |
| 输出格式 | Markdown 或纯文本 |
| 状态 | 草稿、已发布、已停用 |
| 版本号 | 每次修改后递增 |

- 用户只能查看和管理自己的 Skill；
- 草稿和已停用 Skill 不能用于新对话；
- 已发布 Skill 可以在对话中选择；
- 永久删除前需要先停用，并进行确认；
- 本周保留版本信息和版本记录，不开发版本对比及回滚页面。

### 3.5 附件基础规则

- 支持现有页面列出的文档、表格、文本和脚本类附件；
- 单个附件最大 10 MB；
- 单个 Skill 最多 8 个附件，前后端均校验；
- 附件必须真实保存到后端，刷新后仍能查看附件名称；
- 删除附件或永久删除 Skill 时，数据库记录和实际文件同时删除；
- 脚本附件只保存，不在服务器执行；
- 本周不解析附件内容，不把附件加入模型上下文；
- 页面明确标记“附件已保存，本期暂不参与 AI 回答”。

### 3.6 对话调用规则

- 对话中只显示当前用户已启用的系统 Skill 和已发布的个人 Skill；
- 单条消息最多选择 5 个 Skill；
- 后端不信任前端传入结果，每次发送前重新检查用户、Skill 状态和使用权限；
- 后端将 Skill 名称、分析指令和输出格式加入本次模型上下文；
- 草稿、停用、未启用或不属于当前用户的 Skill 调用失败；
- 调用失败时明确提示，不允许悄悄退回普通回答；
- 会话历史保留本次使用的 Skill 名称；
- 本周不处理多个 Skill 之间的复杂冲突，由用户自行选择兼容的 Skill。

### 3.7 Skills 验收标准

- 系统 Skill 列表来自后端，不依赖前端写死数据；
- 用户能够启用和停用系统 Skill，但不能修改或删除系统 Skill；
- 用户 A 的系统 Skill 启用状态不影响用户 B；
- 用户可以创建、编辑、发布、停用和删除自己的 Skill；
- 用户 A 不能查看、修改或调用用户 B 的个人 Skill；
- 草稿和停用 Skill 不出现在对话可选列表；
- 选择 Skill 后发送问题，后端实际把分析指令和输出格式加入模型上下文；
- 会话刷新后仍能看到使用过的 Skill 名称；
- 附件可以真实上传和删除，删除后数据库与磁盘不存在残留；
- 页面明确说明附件内容本周不参与 AI 回答；
- 保存、上传和调用失败均显示真实错误信息。

### 3.8 Skills 后续开发

- 附件解析并作为模型参考资料；
- 用户上传脚本的隔离执行；
- Skill 版本对比和回滚；
- 自动从对话生成 Skill；
- 用户之间共享或共同编辑 Skill；
- 复杂输入表单和多个 Skill 冲突处理。

## 4. PRD B：项目制完善

### 4.1 基础使用流程

1. 用户创建项目，可同时添加系统内已有用户作为成员。
2. 创建者成为项目唯一管理者，其他成员均为编辑者。
3. 编辑者只能查看和管理自己的项目会话；管理者默认查看自己的会话，并可筛选查看全部成员或指定成员的会话。
4. 管理者可以维护项目记忆、项目基本信息和成员；编辑者只能查看项目记忆和成员列表。
5. 成员被移除或账号被停用后，立即不能继续访问项目。

完成以上流程，即视为本周项目制基础闭环完成。

### 4.2 当前功能状态

#### 已有真实功能

- 项目创建、修改、删除和恢复已有后端接口与数据库记录；
- 创建项目时可以添加初始成员和初始项目记忆；
- 项目会话可以真实创建、保存、归档、恢复和删除；
- 项目记忆可以真实创建、编辑、启用、停用和删除；
- 已启用的项目记忆能够加入项目对话的模型上下文；
- 已有项目成员和角色字段；
- 已有成员添加、移除和角色校验基础；
- 多数项目接口已经在后端检查成员关系和角色。

#### 本周完善

- 统一检查项目基本信息、成员、记忆、会话和消息的后端权限；
- 修复账号停用后持有旧 Token 仍可能访问接口的问题；
- 确保成员被移除后立即失去项目访问权限；
- 确保编辑者不能通过直接请求读取他人会话或修改项目记忆、成员和项目设置；
- 将旧的所有者、编辑者、查看者迁移为一名管理者和多名编辑者；
- 项目会话按创建账号隔离，管理者查看他人会话时保持只读；
- 补齐管理者、编辑者和非成员的基础权限测试；
- 统一权限失败、成员不存在和账号停用的页面提示；
- 回归项目创建、成员管理、项目会话和项目记忆的已有功能。

### 4.3 项目角色权限

| 功能 | 管理者 | 编辑者 |
| --- | --- | --- |
| 查看项目基本信息 | 可以 | 可以 |
| 修改项目基本信息 | 可以 | 不可以 |
| 创建和管理自己的项目会话 | 可以 | 可以 |
| 查看其他成员的项目会话 | 可以，只读 | 不可以 |
| 按成员筛选项目会话 | 可以，默认展示自己 | 不提供 |
| 查看项目记忆 | 可以 | 可以 |
| 创建、修改、启停和删除项目记忆 | 可以 | 不可以 |
| 查看成员列表 | 可以 | 可以 |
| 添加和移除成员 | 可以 | 不可以 |
| 删除和恢复项目 | 可以 | 不可以 |

每个项目只有一名管理者，即项目创建者；本期不提供管理权转移或新增管理者。前端根据角色展示按钮，但最终权限必须由后端校验，直接调用接口也不能越权。

### 4.4 成员管理基础规则

- 创建项目时可以添加系统内已有且已启用的用户；
- 创建项目后，管理者可以继续添加成员；
- 新增成员统一为编辑者，不提供查看者角色；
- 管理者不能通过普通成员接口移除自己或修改自己的管理者角色；
- 成员列表显示用户名、显示名称、项目角色和账号状态；
- 不存在或已停用的用户不能被添加为新成员；
- 成员被移除后，下一次项目请求立即失败；
- 本周继续使用用户名添加成员，不开发用户搜索、邀请链接或邮件邀请。

### 4.5 账号停用规则

- 登录保护接口不能只信任旧 Token，需要确认当前账号仍处于启用状态；
- 账号被停用后，其下一次受保护请求立即失败；
- 停用账号不能读取项目，也不能操作项目会话、项目记忆和成员；
- 前端收到账号停用结果后清理登录状态并提示重新登录；
- 账号重新启用后，只恢复原本仍存在的成员关系，不自动恢复已经移除的关系。

### 4.6 项目内容权限

项目基本信息、项目成员、项目记忆和项目会话必须使用同一套成员权限规则：

- 非项目成员不能查看项目及其任何子资源；
- 编辑者只能读取、创建、发送、归档和删除自己账号创建的项目会话，不能读取其他账号的项目会话；
- 管理者默认只展示自己的项目会话，可以切换查看全部成员或指定成员的会话；
- 管理者对其他成员会话只有读取权限，不能代替成员发送、归档或删除；
- 项目记忆只有管理者可以创建、修改、启停和删除，编辑者只读；
- 项目基本信息、成员管理、项目删除和恢复只有管理者可以操作；
- 项目会话读取和发送消息前均再次校验当前成员关系、会话创建账号和写权限；
- 项目记忆只有启用状态的内容进入项目 AI 上下文；
- 项目侧边栏默认显示当前账号最近 5 条真实会话，更多历史在项目详情中查看。

### 4.7 项目制验收标准

- 创建项目时能够添加已有用户，项目和成员真实写入数据库；填写完整但未单独点击添加的当前记忆或成员也会随最终提交加入；
- 创建后管理者能够添加和移除编辑者；
- 成员列表显示用户名、显示名称、角色和账号状态；
- 管理者、编辑者的页面与接口权限符合权限表；
- 编辑者只能查看自己的项目会话，直接请求其他成员会话仍然失败；
- 管理者默认查看自己的会话，可按全部成员或指定成员筛选，且其他成员会话只读；
- 非成员不能读取项目基本信息、成员、记忆、会话或消息；
- 编辑者直接构造项目设置、项目记忆或成员写接口请求仍然失败；
- 成员被移除后，下一次请求立即无法访问项目；
- 账号被停用后，即使持有未过期 Token，也不能继续访问受保护接口；
- 项目会话与项目记忆继续真实保存，刷新和重新登录后数据仍存在；
- 已启用项目记忆真实进入项目对话上下文；
- 多个账号完成管理者、编辑者和非成员的基础流程测试。

### 4.8 项目制后续开发

- 邮件邀请和外部用户邀请；
- 项目管理权转移和多个管理者；
- 自定义角色和细粒度单项权限；
- 项目公开访问；
- 成员搜索和批量导入；
- 完整操作审计页面；
- 自动从对话生成项目记忆；
- 更复杂的删除恢复规则优化。

## 5. 本周测试范围

本周只要求覆盖最基础、最关键的真实使用路径。

### Skills

- 创建个人 Skill → 发布 → 对话选择 → 发送问题 → 模型使用 Skill；
- 系统 Skill 启用 → 对话选择 → 实际调用 → 停用后不可选择；
- 草稿和停用 Skill 不可调用；
- 不同用户之间不能读取或调用对方的个人 Skill；
- 附件上传、数量限制、删除和磁盘清理。

### 项目制

- 创建项目并添加多个编辑者；
- 管理者和编辑者分别验证项目设置、个人会话、他人会话、记忆和成员权限；
- 管理者验证默认自己的会话、全部成员筛选、指定成员筛选以及他人会话只读；
- 非成员直接访问失败；
- 移除成员后立即访问失败；
- 停用账号持旧 Token 访问失败。

## 6. 本周不涉及的其他模块

以下模块继续保持现状，不在本周扩大开发范围：

- 自定义记忆；
- MCP 真实连接；
- 投资组合；
- 工作流其他模块；
- 全站所有演示入口的统一收口。

如果这些页面仍包含固定数据、本地数据或模拟操作，需要保留或增加“演示内容”“本机数据”或“即将开放”标记，但本周不开发其真实后端功能。

## 7. 本周完成定义

本周需求只有在以下条件全部满足时才算完成：

- 用户能够完成“创建或启用 Skill—在对话中选择—模型按 Skill 回答”的真实流程；
- 系统 Skill 保持只读，并按用户保存启用状态；
- 项目成员和管理者/编辑者两类角色的权限在后端真实生效；
- 被移除成员和停用账号不能继续访问；
- 数据刷新和重新登录后仍然存在；
- 核心流程测试通过；
- 尚未真实接入的能力有明确 Mock、演示或后续开发标记。
