# 服务器环境与数据库操作规范

本文档面向本项目开发人员，说明两套线上服务器环境、测试数据库的连接方式，以及日常开发中涉及数据库的操作规范。

---

## 一、环境概览

项目目前部署在**两套线上环境**，各自独立运行，数据库互不相通。

| 环境 | 用途 | 访问方式 |
|------|------|----------|
| **京东云（SaaS）** | SaaS 客户使用 | 必须通过跳板机 |
| **大前台** | 内部大前台展示 | 内网直连 |
| **测试库** | 开发测试 | 内网直连 |

> ⚠️ 京东云和大前台是**完全独立**的两套实例，代码、数据、配置均独立维护。部署或修改时务必确认目标环境，避免误操作。

## 三、开发流程与数据库操作规范

### 3.1 核心原则

1. **先测试，后正式** — 所有 SQL 变更（DDL / DML）必须先在测试库执行验证，确认无误后方可在正式库执行。
2. **变更可回滚** — DDL 变更前评估回滚方案；DML 变更前（特别是 UPDATE / DELETE）先 SELECT 确认影响范围。
3. **谁操作谁负责** — 在正式库执行写操作前，知会相关开发人员。

### 3.2 数据库变更流程

```
┌──────────┐     ┌──────────┐     ┌──────────────┐     ┌──────────────┐
│ 编写 SQL  │ ──▶ │ 测试库   │ ──▶ │ 知会其他开发  │ ──▶ │ 正式库执行    │
│ 变更脚本  │     │ 验证通过  │     │ （重要变更）  │     │ （先京东云    │
│          │     │          │     │              │     │  后大前台）   │
└──────────┘     └──────────┘     └──────────────┘     └──────────────┘
```

**详细步骤：**

1. **编写脚本**：将 DDL / DML 写成 `.sql` 文件，建议放在 `sql/` 目录下，用日期+用途命名（如 `sql/20260727_add_xxx_column.sql`）。
2. **测试库执行**：连接 `Sentiment_analysis_test` 执行脚本，检查结果是否符合预期。
3. **同步代码**：如涉及代码层面的字段/表名变更，先提交代码并确保向后兼容。
4. **京东云执行**：确认测试通过后，在京东云正式库执行脚本。
5. **大前台执行**：京东云确认无问题后，在大前台正式库执行。
6. **验证**：执行后分别在两套环境的业务页面验证功能正常。

### 3.3 SQL 编写规范

#### DDL（表结构变更）

- 新增字段必须带 `DEFAULT` 值或允许 `NULL`，避免影响已有数据。
- 新增字段使用 `ALTER TABLE ... ADD COLUMN`，避免 `DROP` + 重建。
- 修改字段类型前确认数据兼容性（如 `int` → `bigint` 安全，`varchar(50)` → `varchar(20)` 可能截断）。
- 新增索引在低峰期执行，大表加索引可能锁表。
- 所有新表必须添加 `COMMENT`，每个字段建议添加注释。

示例（规范）：
```sql
-- sql/20260727_add_status_column.sql
-- 在 news 表增加处理状态字段
ALTER TABLE `Sentiment_analysis`.`news`
  ADD COLUMN `process_status` varchar(20) DEFAULT 'pending'
  COMMENT '处理状态: pending/processing/done/failed'
  AFTER `indexed`;
```

#### DML（数据变更）

- `UPDATE` 和 `DELETE` 前必须先用**相同的 WHERE 条件**做 `SELECT`，确认影响行数。
- `DELETE` 操作前建议先备份受影响的数据：`CREATE TABLE xxx_backup_20260727 AS SELECT * FROM xxx WHERE ...`。
- 大批量 `UPDATE` / `DELETE` 分批执行（每次 1000~5000 行），避免长事务锁表。
- 禁止在正式库使用 `DELETE FROM table`（无 WHERE 全表删除）。

示例（安全操作）：
```sql
-- 1. 先查看影响范围
SELECT COUNT(*) FROM news WHERE source = 'test_source';
-- 确认数量后可接受

-- 2. 备份
CREATE TABLE news_test_backup_20260727 AS
  SELECT * FROM news WHERE source = 'test_source';

-- 3. 分批删除（每批 2000 行）
DELETE FROM news WHERE source = 'test_source' LIMIT 2000;
-- 循环执行直到影响行数为 0
```

### 3.4 日常开发连接指引

| 场景 | 连接哪个库 | 注意事项 |
|------|-----------|----------|
| 新功能开发 / 调试 | `Sentiment_analysis_test` | 数据可能不完整，仅用于验证逻辑 |
| 查看线上真实数据 | 京东云 / 大前台正式库 | **只读**，禁止修改 |
| 修复线上数据 BUG | 先在测试库复现 → 验证脚本 → 正式库 | 务必先备份 |
| 本地开发启动服务 | 视 `.env` 配置决定 | 建议连测试库，不要连正式库 |

### 3.5 .env 配置注意事项

项目根目录的 `.env` 文件决定后端连接哪个数据库。切换环境时修改以下字段：

```bash
# --- 京东云 ---
MYSQL_HOST=172.18.0.59
MYSQL_PORT=3306
MYSQL_USER=quotation
MYSQL_PASSWORD=Quotation@2022
MYSQL_DATABASE=Sentiment_analysis

# --- 大前台 ---
MYSQL_HOST=10.253.50.134
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=123456
MYSQL_DATABASE=Sentiment_analysis

# --- 测试库 ---

```

## 四、常见问题

### Q: 测试库和大前台库在同一台机器上，如何避免误操作？

打开 Navicat/DBeaver 时，将测试库标记为黄色/橙色，正式库标记为红色。操作前看标题栏确认当前 schema。

SQL 脚本中始终写全 `database.table`（如 `Sentiment_analysis.news`），避免依赖 `USE` 语句后混淆。

### Q: 京东云数据库连接不上？

1. 确认跳板机是否可达：`ssh root@114.67.114.200 -p 2222`
2. 确认 SSH 隧道是否正常：`telnet 127.0.0.1 3307`
3. 确认数据库端口：京东云 MySQL 是 `172.18.0.59:3306`（不是 `172.18.0.23`）

### Q: 表结构变了，需要同步到另一个环境吗？

通常需要。两套正式环境（京东云 + 大前台）应保持表结构一致。按 3.2 的流程在两边依次执行 DDL。
