# 非结构化因子系统对接文档（供策略生成系统使用）

> **文档性质**：面向外部策略生成项目（非本仓库）的对接说明。读者为对方工程团队及其 AI 编程助手。
> **数据基准日**：2026-10-28（文中统计数字均为此日对生产库 `Sentiment_analysis` 的实测值）。
> **配套文件**：[非结构化因子-全量因子目录.md](非结构化因子-全量因子目录.md)（381 个因子全量清单，含事件数与多空分布）。

---

## 0. 给 AI 读者的 TL;DR

1. 本系统的"因子"**不是数值时间序列**，而是从财经新闻中用 LLM 抽取的**事件标签**：一条新闻在某时刻被打上某个因子，并附带对中国国债的方向判断（positive/negative/neutral）与一段作用机制文本。
2. 因子本体在 `factor` 表（字典，381 个）；因子的**事件流**在 `news_factor` 表（64,699 条，覆盖 2021-09 至 2026-10）。策略侧要消费的是后者。
3. 381 个因子中 **308 个是 conceptual（非结构化/概念类）**，73 个是 quantitative（名字对应宏观指标，但**本系统同样不存指标数值**，只存"该指标相关新闻事件 + 方向"）。
4. 方向标签是**中国国债口径**：positive = 利多债券 = 收益率下行。用于其他资产（黄金、股市）时方向不可直接沿用。
5. 事件由三个历史模型分批产出（`doubao`/`deepseek`/`glm`），**跨模型方向口径不完全一致，回测与信号必须固定单一 model**；当前在线模型为 `glm`。
6. 已提供三种现成消费方式：
   - **点信号 API**：`GET /sapi/macro/signal`（presence 0/1 或 directional −1/0/1，带时间衰减）——**最适合策略运行时直接调用**；
   - **历史事件研究结果**：`GET /sapi/factors/backtest-overview` 与 `/sapi/factors/{code}/performance`（因子出现后 T+1/5/20 的 10Y 收益率命中率，已落库）；
   - **事件明细直读**：直接查 `news_factor`（只读账号）或见 §7 拟新增的事件时序接口。
7. 严格防未来函数：信号时间锚点是新闻发布时间 `pub_time`，分析是事后批量跑的，**回测只能按 pub_time 对齐，绝不能按 created_at/分析时间**。

## 1. 系统概述

### 1.1 我们在做什么

对一财（yicai）、华尔街见闻（wallstreetcn）两个来源的宏观/债券财经新闻（`news` 表，约 1.9 万条，2021-08 至今）逐条用大模型分析：

- 判断该新闻对**中国国债**的整体方向（positive/negative/neutral）与影响期限（短期 1 周–1 月 / 中期 1–6 月 / 长期 6 月以上），写入 `analysis` 表；
- 抽取新闻涉及的驱动因子（一条新闻通常 1–N 个），每个因子给出：
  - 因子 code/name/category/type（优先复用因子字典，允许模型发现新因子）；
  - 该因子在本新闻中的方向 `direction`；
  - 作用机制 `driver`（"触发事件 → 中间变量 → 利率方向"三段式中文文本）。
- 因子关联写入 `news_factor`；遇到字典里没有且语义不重复的因子，自动去重后扩充进 `factor` 字典。

### 1.2 因子体系的两个层次（最重要的概念）

| 层次 | 表 | 含义 | 类比 |
|---|---|---|---|
| 因子字典 | `factor` | "有哪些因子"，381 个静态定义 | 字段定义 / 证券主数据 |
| 因子事件流 | `news_factor` | "某因子在某时刻因某条新闻被触发，方向为 X" | 逐笔事件 / 带时间戳的观测值 |

`factor` 表本身**没有数值、没有时间序列**。任何"因子状态/信号"都必须从 `news_factor` 在时间窗口上聚合得到。本系统已经实现了两种聚合（§5），策略侧也可按自己的方法聚合。

### 1.3 数据规模实测（2026-10-28）

| 指标 | 数值 |
|---|---|
| 因子总数 | 381（conceptual 308 / quantitative 73） |
| 因子事件总数 `news_factor` | 64,699 |

### 1.4 六个因子大类

| category | 中文 | 因子数 | conceptual / quantitative | 典型因子 |
|---|---|---|---|---|
| `POLICY` | 政策与监管 | 138 | 125 / 13 | POLICY_SHIFT_EVENT、FED_RATE_EXPECTATION、OMO_RATE、RRR |
| `MACRO` | 宏观经济 | 67 | 32 / 35 | CPI、MANUFACTURING_PMI、GDP_GROWTH_EXPECTATION、OIL_PRICE |
| `LIQUIDITY` | 资金流动性 | 29 | 17 / 12 | TSF_GROWTH、CROSS_BORDER_CAPITAL_FLOW、BANK_ASSET_ALLOCATION_BEHAVIOR |
| `RISK` | 风险/避险 | 33 | 26 / 7 | WAR_CONFLICT、VIX_INDEX、CN_US_SPREAD、SYSTEMIC_FINANCIAL_RISK_PREMIUM |
| `SENTIMENT` | 市场情绪 | 34 | 30 / 4 | RISK_APPETITE、INFLATION_EXPECTATION、UNDERWEIGHT_PRESSURE |
| `INDUSTRY` | 行业/结构性 | 80 | 78 / 2 | SCI_TECH_INDUSTRY_POLICY、PENSION_FINANCE_DEVELOPMENT、INFRASTRUCTURE_INVESTMENT |

### 1.5 conceptual 与 quantitative 的真实差异

`factor_type` 是 LLM 对因子"**理论上是否对应一个可量化指标**"的分类，**不代表本系统存了该指标的数值**：

- `quantitative`（73 个）：如 `CPI`、`OMO_RATE`、`TSF_GROWTH`。在本系统里依然只是事件标签——一条 CPI 相关新闻出现时打一个方向。**CPI 的具体读数不在这里**（月度宏观指标数值另存于 `macro_indicator_data` 表，与因子体系不直接关联，详见 §8.3）。
- `conceptual`（308 个）：如 `风险偏好`、`欠配压力`、`央行政策调整`、`地缘紧张局势升级`，无公开数值序列，传统量化框架无法直接使用，**这正是本系统的核心增量**，也是本次对接的重点。

## 2. 数据模型

数据库：MySQL 8，库名 `Sentiment_analysis`，字符集 utf8mb4。核心表 4 张 + 研究结果表 1 张。

### 2.1 `factor` — 因子字典

```sql
CREATE TABLE `factor` (
  `id`          INT NOT NULL AUTO_INCREMENT,
  `code`        VARCHAR(255) DEFAULT NULL,   -- 大写下划线英文代码，全局唯一
  `name`        TEXT,                        -- 中文名
  `category`    TEXT,                        -- POLICY/MACRO/LIQUIDITY/RISK/SENTIMENT/INDUSTRY
  `factor_type` TEXT,                        -- quantitative | conceptual
  PRIMARY KEY (`id`),
  UNIQUE KEY `code` (`code`)
);
```

- 对接一律使用 **`code`**（稳定字符串），不要用 `id`（自增主键，跨环境可能不同）。
- 已知数据质量问题：存在两个违规占位代码 `NEW_FACTOR`（跨境融资宏观审慎参数调整）、`NEW_FACTOR_1`（监管引导银行零售信贷定价趋稳）；个别 `name` 带尾随换行（如 `OPEN_MARKET_OPERATIONS`）。消费侧请 trim 并建议过滤这两个 code。

### 2.2 `news_factor` — 因子事件流（策略侧主用表）

```sql
CREATE TABLE `news_factor` (
  `news_id`    BIGINT UNSIGNED NOT NULL,
  `factor_id`  INT NOT NULL,
  `direction`  TEXT,          -- positive | negative | neutral（小写存储为主，建议 LOWER() 兜底）
  `driver`     TEXT,          -- 作用机制中文文本（三段式），可作为 LLM 策略推理的解释素材
  `model`      VARCHAR(255) NOT NULL,  -- doubao | deepseek | glm
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,  -- 分析落库时间（勿用于回测对齐！）
  `pub_time`   DATETIME,      -- 新闻发布时间（冗余自 news 表，信号唯一合法时间锚点）
  PRIMARY KEY (`news_id`,`factor_id`,`model`),
  KEY `idx_news_factor_factor_id` (`factor_id`),
  KEY `idx_news_factor_pub_time` (`pub_time`),
  CONSTRAINT ... FOREIGN KEY (`factor_id`) REFERENCES `factor`(`id`),
  CONSTRAINT ... FOREIGN KEY (`news_id`) REFERENCES `news`(`id`)
);
```

要点：

- 主键含 `model`：同一新闻-因子对在不同模型下各有一行。
- 一条新闻 × 一个模型可对应多个因子（1–N）。
- `direction` 是**因子级别**方向（该因子通过此事件对债市的方向），与整条新闻的 `analysis.direction`（新闻总体方向）可能不一致（一条多因子新闻内部允许方向冲突）。
- **无去重/无重大性分级**：同一条因子在一天内可能被多条相似新闻重复触发，聚合策略需自行决定是否按日去重。

### 2.3 `news` — 新闻主表（关键字段）

```sql
CREATE TABLE `news` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `source` VARCHAR(50) NOT NULL,        -- yicai | wallstreetcn
  `title` TEXT NOT NULL,
  `pub_time` DATETIME,                  -- 发布时间（北京时间）
  `url` VARCHAR(1024) NOT NULL,
  `global_uid` CHAR(32) NOT NULL,       -- 跨源去重指纹
  `content` LONGTEXT,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_global_uid` (`global_uid`),
  KEY `idx_pub_time` (`pub_time`)
);
```

### 2.4 `analysis` — 新闻级总体分析

```sql
CREATE TABLE `analysis` (
  `news_id` BIGINT UNSIGNED NOT NULL,
  `direction` TEXT,     -- positive | negative | neutral：整条新闻对国债的总体方向
  `horizon`   TEXT,     -- 短期 | 中期 | 长期
  `reason`    TEXT,     -- 整条新闻的逻辑推导链
  `model`     VARCHAR(255) NOT NULL,
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`news_id`,`model`)
);
```

`analysis` 与 `news_factor` 通过 `(news_id, model)` 对齐。本系统在给策略生成上下文时，只取两者 model 一致的记录，避免混用模型口径（§6 的现成交联即如此）。

### 2.5 `factor_event_study` — 因子事件研究结果（预计算）

```sql
CREATE TABLE `factor_event_study` (
  `factor_code`   VARCHAR(255) NOT NULL,
  `factor_name`   VARCHAR(255),
  `holding_days`  INT NOT NULL,            -- 1 / 5 / 20 个交易日
  `sample_size`   INT,                     -- 有方向且可对齐交易日历的事件样本数
  `hit_count`     INT,
  `hit_rate`      DECIMAL(6,4),            -- 方向命中率（见 §5.2 口径）
  `majority_base` DECIMAL(6,4),            -- 多数类基准（事后无脑猜多/空的命中率）
  `avg_move_bp`   DECIMAL(10,4),           -- 事件后 10Y 收益率平均变动(bp)
  `median_move_bp`DECIMAL(10,4),
  `period_start`  DATE, `period_end` DATE,
  `period_label`  VARCHAR(20) NOT NULL,    -- 'all' 或年度 '2024' 等
  `computed_at`   DATETIME(6),
  UNIQUE KEY `uq_factor_event_study` (`factor_code`,`holding_days`,`period_label`)
);
```

由批处理脚本 `scripts/run_factor_backtest.py` 全量重算（3,333 行 = 381 因子 × 3 持有期 ×（all + 有效年度），最近一次计算 2026-10-27）。策略侧一般通过 API 读，不必直连此表。

### 2.6 ER 关系速览

```
news 1──N news_factor N──1 factor
  │           │
  └──1 analysis (news_id, model)
              └── news_factor.model 须与 analysis.model 一致后再联表
factor 1──N factor_event_study（按 code 软关联，非外键）
```

## 3. 因子是怎么生产出来的（数据生成机制与已知偏差）

理解生成机制对正确使用信号至关重要。

### 3.1 流水线

1. **采集**：定时抓取 yicai / wallstreetcn 新闻入 `news` 表（`global_uid` 跨源去重）。
2. **触发分析**：内部接口 `POST /sapi/internal/pipeline/trigger`（需内部 token + 幂等键），按小时批处理增量新闻；支持补跑历史区间。
3. **LLM 分析**（`backend/analysis/analyzer.py`）：把全量因子字典（`get_factor_prompt_text()`，按大类组织）注入 prompt，要求模型：
   - 优先复用预定义因子，禁止造同义因子；
   - 仅当现有因子无法表达"经济传导机制"且具可复用性时才允许新建（禁止具体政策名/单次事件标签）；
   - 输出 direction、horizon、reason，以及 factors 数组（code/name/category/type/direction/logic_impact/is_new_discovery）。
4. **结果处理**（`backend/analysis/result_processor.py`）：
   - 已存在的 code → 直接写 `news_factor`；
   - 新因子 → 进入发现管理器：用本地 `all-MiniLM-L6-v2` 句向量（70%）+ jieba 关键词 Jaccard（30%）算与现有因子的综合相似度，**< 0.7 才自动入库**；≥0.7 判重丢弃。全过程写 `factor_discovery_history`。
5. 同事务写 `analysis` 与 `news_factor`；向量索引另批处理。
6. 研报来源的因子关联另有 `report_factor` 表（结构类似，目前**无代码写入、无数据**，不要对接）。

### 3.2 三个历史模型与时间覆盖

| model | news_factor 事件数 | analysis 新闻数 | 分析作业时间 | 角色 |
|---|---|---|---|---|
| `doubao` | 33,162 | 13,908 | 2026-05 ~ 2026-07 | 历史回灌主力（2021–2025 旧新闻多由它补跑） |
| `deepseek` | 26,870 | 11,230 | 2026-04-28 ~ 04-29 | 早期一次性回灌 |
| `glm` | 4,667 | 1,780 | 2026-08-28 ~ 至今（每日增量） | **当前在线生产模型** |

注意：

- `pub_time` 是新闻时间，模型作业时间与新闻时间无关——2021 年的新闻可能是 2026 年才被 doubao 分析的。再次强调回测只按 `pub_time`。
- 三个模型的因子命名习惯、方向宽严不同（同一事件不同模型可能选不同因子或给不同方向）。**任何序列构造和回测都要固定 model**；上线交易建议只跟在线模型 `glm`（但 glm 历史只有 2026-08 起，纯 glm 历史样本短）。
- 因子字典本身随时间增长（id 1–381，早期不存在的因子不可能出现在早期新闻上）。用"当前因子全集"回看历史会有**前视存活偏差**：做严谨回测时需要意识到因子集合是 2026 年视角的全集。

### 3.3 方向语义（债市口径，强约束）

- `positive`：该因子此事件**利多中国国债 → 收益率下行**；
- `negative`：利空国债 → 收益率上行；
- `neutral`：无明确方向。事件研究中 neutral 不参与命中率，只进入平均变动样本。
- 这是 LLM 的**判断标签，不是市场真实涨跌**；标签质量在政策/流动性类事件上较高，在长期结构性因子上主观性更强。
- 对**非债券资产**（本系统已接入黄金场景）：方向不可直接翻译成多空，只能作为"背景/风险过滤"。现有 Dream 策略集成对黄金 scope 明确关闭 directional 指引（§6.2）。

### 3.4 更新时效

- 增量新闻按小时级流水线分析，交易日盘中/盘后均可能写入；`news_factor.pub_time` 即新闻发布时刻（北京时间，naive datetime）。
- 因子事件研究表是**离线批量**产物，新闻增量后不会自动刷新，需手动跑脚本（当前数据截至 2026-10-27 计算）。

## 4. 一条真实事件长什么样

新闻 19267（2026-10-28 13:54，一财）《欲放宽甲烷排放监管、松绑对俄能源限制……》经 glm 分析，关联因子之一：

```json
{
  "news_id": 19267,
  "pub_time": "2026-10-28 13:54:00",
  "factor_code": "INFLATION_EXPECTATION",
  "factor_name": "通胀预期",
  "category": "SENTIMENT",
  "factor_type": "conceptual",
  "direction": "positive",
  "model": "glm",
  "driver": "触发事件：全球能源供应预期增加及国际油价下行；中间变量：输入性通胀预期降温、货币政策外部掣肘减轻；利率方向：中国国债收益率下行。",
  "news_horizon": "短期",
  "news_reason": "……国际油价下行通过大宗商品渠道缓解输入性通胀压力……从而压低中国国债收益率（利多债券）。同时对俄制裁放松导致避险情绪降温（利空债券），但短期事件驱动中通胀预期降温逻辑占主导。"
}
```

这类 `driver`/`reason` 文本可直接作为 LLM 策略生成器的推理素材（本系统 Dream 集成已在这么做，见 §6）。

## 5. 现成的因子信号化能力（可直接对接）

### 5.1 点信号：宏观信号 API（推荐策略运行时使用）

把因子事件聚合成**某个时间窗口上的离散信号**，实现见 `backend/macrosignal/macro_signal.py`。

- **presence（事件存在性）**：窗口内该因子是否出现 → `1 / 0`。适合事件类因子（如 POLICY_SHIFT_EVENT、MAJOR_MACRO_DATA_RELEASE、BLACK_SWAN_SHOCK）。
- **directional（方向性）**：窗口内全部事件方向做指数时间衰减加权：

  ```
  score = Σ dir_i · exp(-λ·Δt_i) / Σ exp(-λ·Δt_i)
  dir_i ∈ {+1, 0, -1}，Δt_i 为事件距窗口终点天数，默认 λ=0.1（约 7 天半衰期）
  signal = +1 若 score ≥ 0.3；-1 若 score ≤ -0.3；否则 0
  confidence = min(平均权重, 1.0)   # 事件越多、越近，置信度越高
  ```

  适合趋势/方向类概念因子（如 MONETARY_POLICY_CYCLE、RISK_APPETITE、INFLATION_EXPECTATION）。

接口契约（完整文档见仓库 `docs/宏观信号API接口文档.md`）：

```
GET {BASE}/sapi/macro/signal
    ?factor_code=POLICY_SHIFT_EVENT,RISK_APPETITE   # 逗号分隔多个
    &start_time=2026-10-28T00:00:00                 # 北京时间，ISO
    &end_time=2026-10-28T23:59:59
    &signal_type=presence|directional
    &decay_lambda=0.1                               # 可选，仅 directional
```

单因子返回对象，多因子返回数组；不存在的 code 返回 `{"factor_code": "...", "error": "not found"}`：

```json
{
  "factor_code": "RISK_APPETITE",
  "signal_type": "directional",
  "signal_value": -1,
  "confidence": 0.42,
  "news_count": 5,
  "time_range": {"start": "2026-10-28T00:00:00", "end": "2026-10-28T23:59:59"}
}
```

响应统一包壳 `{"data": ...}`（见 §8.1）。注意：该接口当前**不接受 model 参数，会聚合所有模型的事件**——若严格按在线模型使用，请走 §7 的直连 SQL / 待新增接口（可要求我们加 `model` 参数）。

推荐用法（来自既有文档）：日频策略用当日 00:00–23:59 窗口；周/月频用自然周/月；事件类因子做过滤器/平仓触发（presence），趋势类因子做方向确认（directional）。

### 5.2 历史表现：因子事件研究 API

评估"该因子的方向标签 historically 有没有预测力"，实现见 `backend/evaluation/factor_backtest.py`。

口径：

- 事件日 t 以 **10Y 中债收益率（`yield_data` 表）的交易日序列**对齐，非交易日事件取……实际实现要求事件日恰为交易日（不在日历上的事件被跳过）；
- 收益从 t+1 起算（严格防未来函数），持有 T ∈ {1,5,20} 个交易日，`move_bp = (yield[t+T] − yield[t]) × 100`；
- positive 事件以下跌为命中，negative 事件以上涨为命中；
- **命中率必须与 majority_base（该样本期内多/空哪个方向占优的无脑基准）对比**，0.5 不是正确的基准线；`avg_move_bp` 是含 neutral 事件的无条件平均变动，负号代表收益率下行。

接口：

```
GET /sapi/factors/{factor_code}/performance
    → {factor_code, holding:[T+1/5/20 全样本], yearly:[分年度×持有期], computed_at}

GET /sapi/factors/backtest-overview?holding_days=5&min_samples=20
    → {summary:{factors,total_samples,avg_hit_rate,avg_base,sufficient,above_base}, items:[...每因子...]}
```

实测示例（period=all，n≥30 中较好的记录，供对方建立直觉，**不构成因子推荐**）：

- 5 日持有：`DIRECT_CENTRAL_BANK_DEMAND`（央行直接购债需求，conceptual）n=40，命中率 0.925 vs 基准 0.854，平均 −3.10bp；`OPEN_MARKET_OPERATIONS` n=170，0.618 vs 0.606；`UNDERWEIGHT_PRESSURE`（欠配压力，conceptual）n=88，0.591 vs 0.584。
- 大部分因子命中率围绕多数类基准上下浮动，单因子预测力有限——**更现实的用法是作为方向确认/风险过滤/多因子组合输入，而非单独交易信号**。这与本系统既有策略集成的定位一致（§6.3）。

## 6. 本系统已有的"因子 → 策略生成"集成（DreamStrategy）

本项目已有一条把因子喂给外部策略生成 AI（DreamStrategy，kingstar 量化平台）的链路，对方可直接参考其形态：`backend/strategy/sentiment_context.py` + `backend/strategy/dream_strategy_prompt.py`。

### 6.1 上下文构造

`build_sentiment_strategy_context(lookback_days=7, model_name='glm', scope=...)` 在一个短窗口（1–30 天）内：

- 统计新闻总体方向计数、期限分布；
- 取代表性新闻 3 条（标题/方向/期限/reason）；
- **因子聚合**（关键 SQL 逻辑，对方若自己写聚合可照抄）：

  ```sql
  SELECT f.code, f.name, f.category, f.factor_type,
         COUNT(*) AS event_count,
         SUM(CASE LOWER(nf.direction) WHEN 'positive' THEN 1
                                      WHEN 'negative' THEN -1 ELSE 0 END) AS net_direction,
         MAX(nf.pub_time) AS latest_event_time
    FROM news_factor nf
    JOIN news n     ON n.id = nf.news_id
    JOIN factor f   ON f.id = nf.factor_id
    JOIN analysis a ON a.news_id = nf.news_id AND a.model = nf.model  -- 同模型对齐
   WHERE nf.model = %s AND n.pub_time BETWEEN %s AND %s
     AND LOWER(a.direction)  IN ('positive','negative')   -- 新闻总体须有方向
     AND LOWER(nf.direction) IN ('positive','negative')   -- 因子须有方向
   GROUP BY f.id
  HAVING net_direction <> 0
   ORDER BY ABS(net_direction) DESC, event_count DESC, latest_event_time DESC;
  ```

  取净方向前 3 的正/负向因子，只把**中文名列表**填进 prompt（正向因子：A、B、C；负向因子：…）。

### 6.2 资产范围控制（scope）

- 债券 scope（关键词：国债/债券/收益率/货币政策，标题 LIKE 过滤）：允许方向指引；
- 黄金 scope（关键词：黄金/金价/贵金属/现货金）：`directional_trade_guidance=False`，因子方向仅表述为"正/负向情绪标注"，明确禁止翻译为黄金多空，不带收益率曲线。

### 6.3 给策略 AI 的硬约束（prompt 原文要点）

- 新闻/因子仅用于**方向确认与风险过滤，不单独触发交易**；
- 必须与价格/技术信号确认后才可用（"利多信号占优；仅在价格确认后考虑使用与趋势一致的仓位"）；
- 不提供 OHLCV，禁止策略 AI 伪造技术状态；具体交易代码由量化宿主决定。

**建议对方系统沿用同样的定位**：把非结构化因子作为可选的 alpha 叠加层 / 风险开关，而不是独立交易系统。

### 方案 B：MySQL 只读直连（适合大批量回测）

可为对方开只读账号。建议只授予 `factor / news_factor / news / analysis / yield_data / factor_event_study` 的 SELECT。核心取数 SQL（已按前述纪律写好）：

```sql
-- 单因子事件流（固定模型！）
SELECT nf.pub_time, nf.news_id, nf.factor_id, f.code,
       LOWER(nf.direction) AS direction, nf.driver, n.title, n.url
  FROM news_factor nf
  JOIN factor f ON f.id = nf.factor_id
  JOIN news n   ON n.id = nf.news_id
 WHERE f.code = 'RISK_APPETITE' AND nf.model = 'glm'
   AND nf.pub_time BETWEEN :start AND :end
 ORDER BY nf.pub_time;

-- 日频面板：每个因子每日净方向/事件数（自行决定是否按日去重）
SELECT DATE(nf.pub_time) AS d, f.code,
       COUNT(*) AS n,
       SUM(LOWER(nf.direction)='positive') AS pos,
       SUM(LOWER(nf.direction)='negative') AS neg
  FROM news_factor nf JOIN factor f ON f.id=nf.factor_id
 WHERE nf.model='glm' AND nf.pub_time BETWEEN :s AND :e
 GROUP BY d, f.code;
```

直连方仍须遵守 §9 的全部纪律（尤其固定 model、按 pub_time 对齐、防未来函数）。

### 方案 C：文本上下文（LLM 策略生成器场景）

如果对方策略系统本身是 LLM 驱动（与 Dream 类似），可直接调用我们的上下文构造逻辑（或由我们封装成 HTTP 接口返回现成 prompt 段）：输出"近 N 日正/负向因子名单 + 代表事件 + 使用约束"的中文情报块，见 §6。此方案接入最快，但信号不可机器回测，适合 AI 主观策略生成。

## 9. 对接注意事项清单（务必通读）

1. **固定 model**：任何回测/信号序列只使用一个 model 的行；上线建议 `glm`，长历史回测可用 `doubao`（全历史回灌最多），但两者结论不可拼接混用。当前 `/macro/signal` 不支持 model 过滤，走新增接口或直连。
2. **唯一时间锚点是 `news_factor.pub_time`**（=新闻发布时间，北京时间 naive datetime）。`created_at` 是分析作业时间，严禁用于回测对齐。
3. **防未来函数**：事件在 pub_time 时刻之后方可知情；窗口查询用闭区间时注意同一秒边界；本系统事件研究收益从 t+1 交易日起算。
4. **方向是债市口径**：positive=收益率下行。跨资产使用必须重做方向映射或降级为背景信息。
5. **中性事件占 39%**：聚合时显式决定如何处理 neutral（本系统 directional 信号按 0 分计入但不触发 ±1，事件研究不计入命中率）。
6. **事件不等价于独立观测**：同一事件常被多条新闻、每条多因子重复记录；同日同因子建议按新闻去重或降权。
7. **因子稀疏性**：98 个因子历史事件不足 10 条；上线前用 `/sapi/factors` 的活跃度或附录事件数筛选。建议 minimum：directional 信号窗口内 ≥3 条、历史检验 ≥20 条。
8. **因子字典有脏数据**：`NEW_FACTOR`、`NEW_FACTOR_1` 为模型违规占位 code；name 可能有空白字符，使用前 trim。
9. **因子集合随时间增长**：当前 381 个全集回看 2021 年存在存活/前视偏差；因子方向标签是 LLM 事后判断，非实时市场数据。
10. **无盘中实时性保证**：小时级流水线 + 新闻源延迟，信号适合日频及以上频率，不适合高频/盘中抢跑。
11. **覆盖范围偏宏观利率**：新闻源仅两家（一财、华尔街见闻中文宏观/债券频道），信用债、个股、行业高频信息覆盖弱；INDUSTRY 类因子虽多但单因子事件普遍稀疏。
12. **quantitative 因子无数值**：不要假设 factor_type=quantitative 就能取到指标读数（见 §1.5、§8.3）。
13. 幂等与写入：所有对接接口均为只读；不要尝试写 factor/news_factor（因子入库走内部相似度流程，外部直写会破坏去重体系）。
