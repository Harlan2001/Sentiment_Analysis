Plan: 京东云定时任务与轻事件架构
推荐方案是“定时为主 + 事件触发为辅”的混合架构：
用 Linux Cron 保证三条主任务稳定落地；Spider 每次抓取完成后主动调用 Sentiment 内部触发接口，提升处理及时性；再用每日兜底任务保证最终一致性。
这满足你“同机部署、简单稳定、少组件、Spider 调 Sentiment API”的偏好，不需要先引入 MQ。

关键发现（基于现有代码）

报告脚本支持单日和区间，但默认是 latest 逻辑，9 点生产应改成“明确昨日交易日”，见 generate_report.py。
文档写了 compose 有 scheduler 服务，但当前 compose 实际只有 backend/frontend，见 README.md 与 docker-compose.yml。

Steps

Phase A - 职责与边界

明确单一事实源是 MySQL：Spider 只写 news，Sentiment 只消费并更新 indexed/analyzed、news_vectors、analysis、forecast_report。

明确 Spider 不做向量化/分析，Sentiment 不反向调度 Spider，避免双向耦合。并行 with 2。

Phase B - 三条任务编排

任务1（收益率）：每天 19:00 执行“下载 Excel -> 增量写入 yield_data -> 记录结果”，给 18:00 更新预留缓冲。

任务2（新闻处理，主通道）：Spider 每小时抓取后调用 Sentiment 内部触发 API，Sentiment 执行“indexed=0 向量化 -> -> analyzed=0 分析”。depends on 2。

任务2兜底：每天 23:00 跑一次 model_missing 补偿任务，防止触发丢失。depends on 6,7。

任务3（报告）：每天 09:00 固定生成昨日交易日报告并写 forecast_report(full_report)，不依赖 latest 自动选择。depends on 5,6,7,8。

Phase C - Spider 与 Sentiment 交互（轻事件）

主通道采用“数据库 + 内部触发 API”，不引入 Redis/Kafka。

触发 API 支持幂等键（例如抓取批次号+时间窗），重复调用只受理一次。

触发失败不阻塞 Spider 主流程，靠 23:00 补偿任务保证最终一致性。depends on 7。

Phase D - 可靠性与可观测

新增任务状态记录（task_runs/task_events），记录开始结束、耗时、处理条数、错误原因、重试次数。

告警最小集：任务失败、任务超时、9 点报告缺失、analyzed backlog 超阈值。

提供日期范围回放入口，用于补跑分析与报告。

Phase E - 上线策略

灰度两天：保留原整点批处理，同时开启 API 触发，比较覆盖率与稳定性。

稳定后切主通道为“触发 + 兜底”，整点全量改为只做补偿。

Relevant files

yield_db.py - Excel 导入与期限映射逻辑
vector_store.py - indexed 增量向量化
analyzer_runner.py - analyzed 增量分析与重试模式
generate_report.py - 报告生成与入库
docker-compose.yml - 当前部署编排基线

Verification（这部分不急）

19:00 后检查 yield_data 是否出现当日各期限数据（无新增也要有成功完成日志）。
Spider 抓取后触发 API，5 分钟内 indexed/analyzed 待处理量下降。
同一触发请求重复 3 次，结果不重复（幂等生效）。
人为断开触发 API 一次，23:00 兜底后 backlog 收敛。
09:00 后 forecast_report 存在昨日交易日 full_report，且接口可读。
用日期范围补跑一次，验证回放可恢复缺口。

已实现

- 报告入口已支持 `--trade-date`，默认单日模式会取当前日期之前最近的可用交易日，满足 09:00 显式昨日交易日的调度方式。
- 新增 `/api/internal/analysis/trigger` 批量触发接口，带幂等键和触发日志表，Spider 后续可以直接调用。
- 新增 `task_runs` / `task_events` 任务记录表，报告生成和内部分析触发都会留下开始、结束、明细事件和失败原因。

Spider 调用示例

```bash
python scripts/trigger_analysis_example.py \
	--base-url http://127.0.0.1:8000 \
	--idempotency-key spider-20260519-0900 \
	--mode model_missing \
	--limit 100
```

联调说明

- Spider 抓取结束后先写 news，再调用内部触发接口；触发失败不阻塞抓取主流程。
- 同一个 `idempotency_key` 重复调用时，Sentiment 会按已完成任务直接回放，不重复执行。
- 09:00 报告任务直接传 `--trade-date`，线上建议由 Cron 明确传入昨日交易日。
