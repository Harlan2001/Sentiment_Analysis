# 1.28会议

## 1.23会议总结

23号的会议，我个人总结了一下针对下一步的开展方向。我认为有3个部分。

1. 数据来源
2. 因子整体管理、评价系统
3. 预测

### 数据来源

整体两个方向，商用数据源和爬虫。

Selling的话需要使用商用数据源；

自用的话假设没有办法购买，那就是爬虫。可能的隐患是两者不好做兼容，因为数据格式可能不一样（猜测），数据处理的pipline不一样（肯定），数据库的格式不一样（可能）。目前不确定能复用的内容多不多，所以是有可能两套系统，一套是selling的，一套是爬虫的。

#### 商用数据源API

这一部分，需要对Wind等数据商做相应的API接口处理开发，包括：接数据->清洗数据->建表（服务器）->数据对齐->前端显示->后端适配。

正常来说是客户有什么数据源的需求，我们去做开发，比如说Wind，就是[Wind Client API](https://www.wind.com.cn/portal/zh/ClientApi/index.html),我个人没有Wind账号，也没有使用过Wind，所以没有进一步了解如何获取相应的接口手册，网上没检索到很相关的内容。

这一块的工程量是不小的。

#### 爬虫

假设用爬虫，那就是要做一个自动化多数据源爬虫平台，每一天自动去爬相关的数据。三个问题：

1. 系统需要维护：假设我来维护，那我每一天可能都要检查一下日志，有没有出错？数据源的网站有没有更新前端代码格式？反爬机制有没有更新？

2. 反爬：所有的商业信息网站都会做反爬，每一家都不一样，而且有些网站是直接不给你数据，比如财联社，你查看他的新闻页面，最多只给你展示一个月的新闻，再想看之前的没有“加载更多新闻”的按钮了，这个怎么爬，我不是资深的爬虫工程人，还需要进一步了解。同样的，新浪财经，华尔街见闻有没有这种强制性的反爬虫机制呢？这是不确定的，如果有，是增加了爬虫难度还是说真的就是爬不了？这个也需要考虑。

3. 工程量不小：10个数据源，就是10个自动化爬虫脚本。每一个都要针对页面的前端做对应处理，一天做一个脚本加上测试加上验证是可能需要的工作量。
