# ksquant-train 模型训练与因子能力技术方案

## 1. 系统全景与建设目标

### 1.1 系统定位

ksquant-train 是量化模型训练与预测平台，提供从数据加载、特征工程、因子筛选、因果发现、模型训练到因子产出的完整链路。

系统设计重点不是单点模型效果，而是“可持续生产能力”：
- 能稳定训练与发布。
- 能将结果标准化输出给下游策略。
- 能在生产环境可观测、可治理、可扩展。

### 1.2 技术架构

- 触发层：RocketMQ 接收训练/预测指令。
- 执行层：TrainProcess 与 PredictProcess 子进程隔离执行。
- 模型层：支持 CausalAIRegression、XGBoostTrend 及模板扩展模型。
- 产出层：模型文件 PKL、因子 CSV、结果与日志 MQ 回写。

### 1.3 客户价值

- 交付效率：从模型实验到可部署因子输出形成标准流程。
- 运行稳健：训练、预测、日志、监控形成闭环，便于生产运维。
- 资产沉淀：模型与因子可复用，减少重复研发投入。

## 2. 模型训练链路（技术主干 + 价值映射）

### 2.1 训练启动机制

技术机制：
- 上游通过 model_train_run 下发训练参数。
- 服务模块解析参数并创建训练子进程。
- 训练流程完成后自动保存模型与因子，并回写训练状态。

客户价值：
- 训练任务标准化启动，减少人工干预。
- 支持批量化、流程化训练，提升模型迭代效率。

### 2.2 训练生命周期

1. 任务校验：检查模型配置与文件可用性。
2. 动态加载：按模型名称加载对应训练实现。
3. 模型训练：执行特征处理、训练与验证。
4. 结果持久化：保存 PKL 与因子输出。
5. 状态回写：向 MQ 回写日志、监控与评估结果。

客户价值：
- 各阶段状态可见，便于快速定位问题。
- 训练结果可追溯，满足审计与复盘要求。

### 2.3 训练入参与治理原则

关键入参包括 train_id、model_name、data_freq、model_params。

治理原则：
- train_id 作为全链路唯一标识。
- model_params 保持模型自治，避免统一配置过度耦合。
- 数据频率分层管理，适配不同场景的训练节奏。

客户价值：
- 任务管理标准化，便于规模运行。
- 不同模型可并行演进，避免“一刀切”影响创新速度。

### 2.4 日志与监控回写

技术机制：
- 训练日志、监控指标、评估结果、可视化图分 Topic 输出。
- 过程状态可被调度平台和运维平台实时消费。

客户价值：
- 快速判断任务健康度，缩短故障处理时间。
- 形成可量化运营指标，为管理决策提供依据。

## 3. 核心模型能力说明

### 3.1 CausalAIRegression（因果推断回归）

技术框架：
- 数据层：行情数据 + 宏观因子矩阵。
- 特征层：清洗、平稳化、标准化与派生特征处理。
- 筛选层：过滤式、嵌入式、包裹式特征筛选组合。
- 因果层：基于 PCMCI 的因果发现，降低伪相关干扰。
- 建模层：AutoML 比较与集成，联合输出收益与波动信息。

客户价值：
- 信号质量更高：通过因果约束降低噪声因子影响。
- 解释性更强：可说明“为什么选这些因子”。
- 稳健性更好：多模型比较与集成降低单模型失效风险。

### 3.2 XGBoostTrend（趋势分类）

技术框架：
- 基于时序切分的分类训练，避免未来信息泄漏。
- 用于趋势方向判断与策略演示场景。

客户价值：
- 作为轻量模型可快速验证场景可行性。
- 可作为生产模型前的验证基线，缩短试错周期。

### 3.3 模型扩展机制

技术机制：
- 新模型按统一模板实现 train 与 predict 即可接入调度。
- 与存储、回写、日志能力自动兼容。

客户价值：
- 模型扩展成本可控，支持持续迭代。
- 避免每次上新模型都重做工程底座。

## 4. 因子产出与下游对接

### 4.1 因子存储（CSV）

技术机制：
- 训练完成后将核心预测值与扩展字段写入 CSV。
- 输出结构统一，至少包含时间、因子值、扩展信息三类字段。

客户价值：
- 下游系统可直接消费，减少二次加工工作量。
- 历史结果可对比、可回放，便于策略复盘。

### 4.2 预测结果推送（MQ）

技术机制：
- 预测任务完成后通过 factor_deploy_result 回传结果。
- 保留 deploy_id、factor_id 等关键上下文字段，确保链路追踪。

客户价值：
- 预测结果可直接接入调度与策略系统，缩短上线路径。
- 任务上下文完整，便于跨系统问题定位。

### 4.3 模型持久化（PKL）

技术机制：
- 训练后保存完整推理状态，预测时按 train_id 自动恢复。

客户价值：
- 保证训练与预测口径一致，减少环境差异引入的偏差。
- 支持历史模型回溯，满足审计与复现实验需求。

---

## 5. 工程化能力与边界

### 5.1 容错与降级

技术机制：
- 模型缺失、文件缺失、数据异常、训练异常均有显式失败返回。
- 消息过大自动分片，确保传输稳定。

客户价值：
- 故障行为可预期，减少不可控中断。
- 失败可定位、可恢复，提升生产连续性。

### 5.2 可治理性

技术机制：
- train_id 贯穿训练、存储、推送与日志链路。
- 指标与日志分层输出，支持集中分析。

客户价值：
- 可建立统一 SLA 与质量评估机制。
- 支撑管理层进行效果评估与资源配置。

### 5.3 可扩展性

技术机制：
- 新模型扩展、因子配置扩展、MQ 后端切换、多机部署均可配置化完成。

客户价值：
- 从单策略试点平滑走向规模化生产。
- 技术路线可持续演进，不绑定单一实现。

---

## 6. 价值总结

- 快速形成可验证的训练-预测-因子投产闭环。
- 在低改造成本下接入现有系统，尽快看到业务收益。
- 构建稳定的模型生产流水线，提升策略迭代效率。
- 将经验式研发转化为流程化、可治理的能力体系。
- 形成可复用的模型与因子资产库，持续积累竞争壁垒。
- 支撑跨场景扩展与规模部署，提升组织级量化能力。
