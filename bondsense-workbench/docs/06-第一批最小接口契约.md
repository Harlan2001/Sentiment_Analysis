# BondSense 新版工作台：第一批最小接口契约

> 状态：需求已确认，等待后端实施批准。  
> 功能基线：[`02-前端功能与后端对照.md`](./02-前端功能与后端对照.md)。  
> 对应 PRD：[`03-左侧栏PRD.md`](./03-左侧栏PRD.md)、[`04-会话PRD.md`](./04-会话PRD.md)、[`05-项目PRD.md`](./05-项目PRD.md)。  
> 约束：本文是最小接口契约，不授权编写后端实现；所有未来新增后端代码只能位于 `bondsense-workbench/backend/`。

## 1. 通用约定

- 路径前缀：`/api/workbench`。
- 认证：复用既有登录能力取得 token，新接口统一接受 `Authorization: Bearer <token>`。
- ID：服务端生成的不透明字符串；客户端不得推断格式。
- 时间：ISO 8601 UTC 字符串，例如 `2026-08-06T08:00:00Z`。
- JSON 成功响应统一使用 `{ "data": ... }`。
- 分页使用不透明 `cursor`；默认 `limit=20`，最大 `limit=50`。
- 所有写接口验证 `Content-Type: application/json`，SSE 消息接口除响应类型外仍接收 JSON 请求体。

## 2. 统一错误

```json
{
  "error": {
    "code": "PROJECT_NOT_FOUND",
    "message": "项目不存在或当前用户无权访问",
    "details": {},
    "request_id": "req_xxx"
  }
}
```

首批统一处理：

- `400`：请求格式错误。
- `401`：未认证或 token 无效。
- `403`：已认证但权限不足。
- `404`：资源不存在。
- `409`：幂等键冲突或资源状态冲突。
- `422`：字段校验失败。
- `502`：旧后端调用失败。
- `504`：旧后端调用超时。

## 3. 端点清单

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/sidebar` | 左侧栏聚合 |
| GET | `/projects` | 项目列表 |
| POST | `/projects` | 创建项目 |
| GET | `/projects/{project_id}` | 项目详情 |
| PATCH | `/projects/{project_id}` | 修改项目资料 |
| GET | `/projects/{project_id}/conversations` | 项目会话分页列表 |
| GET | `/conversations` | 普通会话分页列表 |
| POST | `/conversations` | 创建普通或项目会话 |
| GET | `/conversations/{conversation_id}` | 会话及首屏消息 |
| PATCH | `/conversations/{conversation_id}` | 修改标题或归档状态 |
| POST | `/conversations/{conversation_id}/messages` | 保存消息并返回 SSE |

成员、记忆和搜索接口不属于第一批最小契约。

## 4. 左侧栏聚合

```http
GET /api/workbench/sidebar?conversation_limit=5
```

`conversation_limit` 默认值和第一批最大值均为 `5`。

```json
{
  "data": {
    "current_user": {
      "id": "usr_xxx",
      "username": "user",
      "display_name": "User",
      "avatar": null,
      "authenticated": true
    },
    "projects": [
      {
        "id": "prj_xxx",
        "name": "利率债研究",
        "description": "可选",
        "visibility": "private",
        "role": "owner",
        "updated_at": "2026-08-06T08:00:00Z",
        "unread_count": 0,
        "recent_conversations": []
      }
    ],
    "recent_conversations": [],
    "limits": {
      "project_conversations": 5,
      "recent_conversations": 5
    }
  }
}
```

约束：

- `projects[].recent_conversations` 只包含该项目会话。
- 顶层 `recent_conversations` 只包含 `project_id=null` 的普通会话。
- 两处会话集合不得重复。
- 默认排除已归档会话。

## 5. 项目

### 5.1 创建项目

```http
POST /api/workbench/projects
```

```json
{
  "name": "利率债研究",
  "description": "可选"
}
```

第一批忽略客户端提供的共享意图，新项目固定创建为 `private`。返回 `201`：

```json
{
  "data": {
    "id": "prj_xxx",
    "name": "利率债研究",
    "description": "可选",
    "visibility": "private",
    "role": "owner",
    "unread_count": 0,
    "created_at": "2026-08-06T08:00:00Z",
    "updated_at": "2026-08-06T08:00:00Z"
  }
}
```

### 5.2 获取与修改项目

```http
GET /api/workbench/projects/{project_id}
PATCH /api/workbench/projects/{project_id}
```

第一批 PATCH 请求只接受：

```json
{
  "name": "新的项目名称",
  "description": "新的描述"
}
```

不接受通过该接口修改 `visibility`、成员或所有者。

### 5.3 项目列表

```http
GET /api/workbench/projects?limit=20&cursor=...
```

按 `updated_at DESC, id DESC` 排序。

## 6. 会话

### 6.1 会话对象

```json
{
  "id": "cnv_xxx",
  "title": "近期十年国债走势分析",
  "project_id": null,
  "module_type": "chat",
  "source": "sidebar",
  "status": "active",
  "created_at": "2026-08-06T08:00:00Z",
  "updated_at": "2026-08-06T08:02:00Z",
  "last_message_at": "2026-08-06T08:02:00Z"
}
```

`status` 第一批取值为 `active | archived`。

### 6.2 创建会话

```http
POST /api/workbench/conversations
```

普通会话：

```json
{
  "project_id": null,
  "title": null,
  "source": "sidebar"
}
```

项目会话：

```json
{
  "project_id": "prj_xxx",
  "title": null,
  "source": "project"
}
```

每次成功请求返回 `201` 和新的会话 ID。

### 6.3 普通会话列表

```http
GET /api/workbench/conversations?scope=recent&limit=20&cursor=...&archived=false
```

该端点只返回 `project_id=null` 的普通会话。项目会话只能通过项目会话端点获取。

### 6.4 项目会话列表

```http
GET /api/workbench/projects/{project_id}/conversations?limit=20&cursor=...&archived=false
```

只返回路径中指定项目的会话。

### 6.5 获取会话

```http
GET /api/workbench/conversations/{conversation_id}?message_limit=50&message_cursor=...
```

```json
{
  "data": {
    "conversation": {},
    "messages": [],
    "next_message_cursor": null
  }
}
```

### 6.6 修改会话

```http
PATCH /api/workbench/conversations/{conversation_id}
```

```json
{
  "title": "十年国债走势分析",
  "archived": false
}
```

- 两个字段至少提供一个。
- `title` 去除首尾空白后长度为 1 至 120 个 Unicode 字符。
- 不允许修改 `project_id`。

## 7. 消息与 SSE

### 7.1 发送请求

```http
POST /api/workbench/conversations/{conversation_id}/messages
Content-Type: application/json
Accept: text/event-stream
```

```json
{
  "content": "分析一下近期十年国债走势",
  "client_message_id": "客户端为本次发送生成的幂等键"
}
```

- `content` 去除首尾空白后不得为空。
- 同一用户、同一会话和同一 `client_message_id` 只能对应一条用户消息及一次助手生成。
- 相同请求重试返回同一结果或当前流状态，不得重复调用旧聊天接口。
- 同一个 `client_message_id` 携带不同内容时返回 `409`。

### 7.2 消息对象

```json
{
  "id": "msg_xxx",
  "conversation_id": "cnv_xxx",
  "role": "assistant",
  "content": "回答内容",
  "status": "completed",
  "client_message_id": null,
  "created_at": "2026-08-06T08:01:00Z",
  "completed_at": "2026-08-06T08:02:00Z"
}
```

助手消息状态：`streaming | completed | failed | interrupted`。用户消息保存成功后状态固定为 `completed`。

### 7.3 SSE 事件

```text
event: message.accepted
data: {"message": {}}

event: assistant.started
data: {"message_id":"msg_xxx"}

event: assistant.delta
data: {"message_id":"msg_xxx","delta":"增量文本"}

event: assistant.completed
data: {"message": {}}

event: assistant.failed
data: {"message": {},"error":{"code":"LEGACY_CHAT_FAILED","message":"生成失败"}}

event: stream.done
data: {"conversation_id":"cnv_xxx"}
```

`assistant.completed` 或 `assistant.failed` 后必须发送一次 `stream.done`。客户端断连时服务端保存已有内容并把助手消息标记为 `interrupted`；第一批不自动重试。

## 8. 实施前置门槛

只有在用户明确批准进入实现后，才可：

- 创建 `bondsense-workbench/backend/` 中的代码、迁移或配置。

- 编写旧 `/sapi/chat` 适配器。

即使获得批准，也不得修改旧 `frontend/`、旧 `backend/`、旧构建配置、旧接口或旧表结构语义。
