# BondSense 新版工作台：前端功能与后端对照

> 状态：后端开发前的功能基线。  
> 范围：仅覆盖 `bondsense-workbench/frontend` 已实现的页面、交互和已确认需求；不修改旧 `frontend/`、旧 `backend/` 或其接口。  
> 原则：先以本文件确认产品与接口边界，再按模块接入真实数据。

## 1. 当前前端范围与真实度

新版前端是独立 Vite/React 项目，所有展示数据目前为 Mock，普通聊天消息暂存于浏览器 `sessionStorage`。

| 状态 | 含义 |
| --- | --- |
| 已有视觉与交互 | 页面、路由、筛选切换、展开收起、表单输入或局部状态已经存在，但没有真实 API |
| 可复用旧能力 | 旧后端已有对应数据或工作流，新工作台只需适配返回结构 |
| 新增工作台能力 | 旧后端不存在，必须在 `bondsense-workbench/backend` 新建，不侵入旧后端 |
| 后续范围 | 已确认概念但本期不做完整业务闭环 |

不在本期范围：工件模块、完整文件管理、复杂自动推荐规则、复杂权限后台、完整计划调度后台。

## 2. 全局壳与左侧功能栏

### 2.1 已实现前端功能

- BondSense 品牌入口返回首页。
- 新建对话：每次创建独立会话；首页聊天框创建的会话与侧栏新建会话不得复用同一个 ID。
- Computer、自定义、项目的路由入口。
- 项目区：展开/收起项目；项目名称进入项目主页；每个项目可展开其项目内历史会话；项目行加号创建该项目内的新会话；区块加号创建项目。
- 最近会话：默认显示最近 5 条，可展开更多；点击已有会话进入该会话，不创建新会话；区块加号创建普通新会话。
- 账户区：已登录时显示账户菜单、账户信息和登出；未登录时显示登录按钮。
- 顶部全局搜索目前只有视觉入口；会话内搜索也是产品要求，但尚未在页面实现。

### 2.2 所需数据与动作

| 前端动作/显示 | 最小数据字段 | 后端状态 |
| --- | --- | --- |
| 当前用户 | `id, username, display_name, avatar, authenticated` | 旧 `/sapi/auth/status`、`users` 可复用，需统一返回 |
| 项目列表 | `id, name, visibility, updated_at, unread_count` | 新增 |
| 项目内最近会话 | `id, title, project_id, last_message_at, status` | 新增通用会话模型 |
| 全局最近会话 | `id, title, project_id?, last_message_at, module_type` | 新增通用会话模型 |
| 新建项目 | `name, description?, visibility` | 新增 |
| 新建普通/项目会话 | `project_id? , title? , source` | 新增 |
| 登录、登出 | JWT/token 与当前用户 | 登录可复用；登出第一版可只清理前端 token |

### 2.3 推荐接口

```text
GET  /api/workbench/sidebar
POST /api/workbench/projects
POST /api/workbench/conversations
GET  /api/workbench/conversations?scope=recent&limit=5
GET  /api/workbench/projects/{project_id}/conversations?limit=5
```

`/sidebar` 应一次返回当前用户、项目、每个项目的前 N 条会话以及全局最近会话，避免侧栏发起多次串行请求。

## 3. 普通会话

### 3.1 已实现前端功能

- 新会话空态：居中问候语和聊天框。
- 有消息后：消息显示在上方，聊天框固定在下方。
- `Enter` 发送；`Shift + Enter` 换行。
- 首页携带问题进入新会话。
- 第一条用户消息前若干字成为会话主题。
- Mock 历史会话可打开并展示示例内容。
- 当前会话标题显示在工作台顶部。

### 3.2 后端要求

普通聊天不能仅使用旧 `/sapi/chat`：该接口支持流式回答，但不保存通用会话、消息、标题、项目归属或搜索索引。

需要新增：

- 会话创建、读取、列表、归档与搜索。
- 消息持久化：先保存用户消息，再代理旧聊天 SSE；完成后保存助手消息与状态。
- 会话标题：默认由首条用户消息截取；后续可由模型生成摘要标题。
- 项目边界：普通会话默认 `project_id = null`；项目内创建时记录 `project_id`。默认不读取项目记忆或旧会话记忆，只有用户显式选择时才附带。
- 搜索边界：全局会话搜索与当前会话消息搜索分别提供接口。

### 3.3 可复用旧后端

- `POST /sapi/chat`：债券领域 Agent、工具调用、SSE 流式输出。
- `users`：通过既有认证获取用户身份。
- 不能复用旧 AI 策略会话表作为普通聊天表；它属于策略生成专用工作流。

### 3.4 推荐接口

```text
POST /api/workbench/conversations
GET  /api/workbench/conversations/{conversation_id}
POST /api/workbench/conversations/{conversation_id}/messages   # SSE
GET  /api/workbench/conversations/search?q=
GET  /api/workbench/conversations/{conversation_id}/messages/search?q=
PATCH /api/workbench/conversations/{conversation_id}
```

## 4. 首页

### 4.1 已实现前端功能

- 市场、收益、预测、筛选器、关注列表、投资组合、工作流导航切换。
- 10 年国债、30 年国债、国债期货、DR007 行情卡及趋势线。
- 市场摘要和刷新动作。
- 我的关注列表：国债、国债期货、信用利差等。
- 今日信号摘要。
- 首页聊天入口。

### 4.2 可复用旧后端

- `GET /sapi/yields`：收益率时序。
- `GET /sapi/news`、`GET /sapi/news/latest-trading-day`：新闻及交易日。
- `GET /sapi/strategy/snapshot`：策略快照。
- `GET /sapi/ai-strategy-recommendation/latest`：最新 AI 推荐。
- `GET /sapi/forecast`、`GET /sapi/forecast/history`：预测。
- `GET /sapi/dashboard/core`：运营/数据健康大盘，适合部分摘要指标，不等同于投资者首页。

### 4.3 需要新增或确认

- 行情统一聚合：旧接口不足以直接给出 DR007、期货、信用利差、卡片涨跌幅和 sparkline。
- 用户自选：`watchlist` 的保存、排序、增删。
- 市场摘要：先可由规则聚合新闻/策略/收益率；后续才考虑 LLM 摘要。
- 首页导航当前只是前端状态切换；第二阶段再决定每一项是否成为独立视图。

推荐接口：`GET /api/workbench/home/overview`、`GET/POST/DELETE /api/workbench/watchlist`。

## 5. Computer 工作台

### 5.1 总览

前端有全部、研报生成、策略开发、每日新闻总结三个入口；支持模块、状态、未读、日期、归档筛选，并展示“需要处理”和按日聚合的会话/文档表。

需要一个统一只读聚合模型，而不是强制把所有旧数据迁入同一张表：

```text
task_id, task_type, title, source, status, needs_action,
project_id?, conversation_id?, document_count, document_summary,
updated_at, archived_at?, unread_at?
```

策略任务可以映射旧策略会话；研报与新闻总结任务则使用新工作台任务记录。

推荐接口：`GET /api/workbench/computer/tasks`、`PATCH /api/workbench/computer/tasks/{id}`。

### 5.2 策略开发

前端功能：

- 新建策略并输入自然语言需求。
- 列表查看等待确认、运行中、完成、失败的策略工作流。
- 进入提示词确认页。
- 左侧显示原始需求、AI 提取结构化条件和补充信息。
- 右侧可编辑系统提示词；可还原系统草稿、重新生成草稿、确认生成策略。
- 确认后进入代码与回测阶段，显示版本、结果与状态。

可直接复用：

- `POST /sapi/ai-strategy-generation/conversations`
- `GET /sapi/ai-strategy-generation/conversations`
- `GET /sapi/ai-strategy-generation/conversations/{id}`
- `POST /sapi/ai-strategy-generation/conversations/{id}/draft`
- `POST /sapi/ai-strategy-generation/conversations/{id}/drafts/{assistant_message_id}/confirm`
- `PATCH /sapi/ai-strategy-generation/conversations/{id}/archive`
- 旧表：`ai_strategy_conversations`、`ai_strategy_messages`、`ai_strategy_versions`。

缺口：

- 前端“重新生成系统草稿”需要适配接口。旧仓储已有替换草稿能力，但旧路由未公开该操作。
- 项目归属、工作台未读状态与统一任务列表需要新表或适配层映射。
- 前端路由需要使用真实策略会话 ID 和草稿消息 ID，而非固定 Mock 页面。

### 5.3 研报生成

前端功能：新建研报、补充资料、任务状态、文档结果、日期/状态/未读/归档筛选。

可复用：

- `/sapi/research/*`：外部研报上传、解析、AI 分析、列表与详情。
- `/sapi/report/generate-prediction`：基于已有预测数据生成 PDF。

必须新增：

- “根据用户请求生成一份债券研报”的任务模型与执行链路。
- 生成输入、数据来源快照、状态、文档元数据、失败重试。
- 现有 `research_report` 是外部研报解析库，不能直接替代新版生成研报任务。

第一版建议：仅支持文本需求 + 已有数据源生成 Markdown/PDF；文件附件和复杂多模板放到后续。

### 5.4 每日新闻总结

前端功能：手动立即生成、主题补充、列表、失败重试、计划入口、日期/状态/未读/归档筛选。

可复用：`/sapi/news`、新闻来源、新闻详情、新闻分析结果。

必须新增：新闻总结任务、总结文档、生成提示词快照、执行状态。计划调度可先保留设置，第一版只实现手动触发；定时任务在真实需求确认后再接入。

## 6. 自定义：因子库与因子详情

### 6.1 已实现前端功能

- 五类因子分类及总数 400 的产品展示。
- 今日活跃、我的关注、全部因子切换。
- 名称、代码、主题搜索；分类、方向、热度、时间、来源、排序筛选入口。
- 因子表：方向、研究热度、用户关注、7 日趋势、事件数、更新时间。
- 单因子详情：关注切换、7/30/90 日/1 年时间线、利多/利空/中性新闻筛选、新闻联动。

### 6.2 可复用旧后端

- `GET /sapi/factors`
- `GET /sapi/factors/by-category/{category}`
- `GET /sapi/factor/{factor_code}/news`
- 表：`factor`、`news_factor`、`analysis`、`news`。

### 6.3 必须新增/适配

- 分类映射：旧分类为 POLICY/MACRO/LIQUIDITY/RISK/SENTIMENT/INDUSTRY；新版为政策监管、经济增长、货币流动性、债券供需、情绪风险。用独立映射配置或新字段，不修改旧分类语义。
- 热度：由来源权威度、时效性、覆盖度、关注行为共同计算，不能只使用点击量。
- 关注关系：新增 `user_id + factor_code` 记录。
- 因子时间线：按日期统计新闻/事件数量和方向。
- 旧文档记录因子约 398 条；新版目标 400 条，接入前必须实际查库并确认补数来源。

推荐接口：

```text
GET  /api/workbench/factors
GET  /api/workbench/factors/{code}
GET  /api/workbench/factors/{code}/timeline
POST /api/workbench/factors/{code}/follow
DELETE /api/workbench/factors/{code}/follow
```

- 项目主页：项目描述、会话、项目记忆、成员与权限三页签。
- 项目内会话搜索、私有/共享状态、创建项目会话。

### 8.2 后端要求

```text
workbench_projects
workbench_project_members

workbench_memories
```

最小权限：项目默认私有；所有者可管理成员；编辑者可创建/编辑项目内容；查看者只读。第一版不做复杂审计、外链共享或团队空间。

推荐接口：

```text
GET/POST                 /api/workbench/projects
```

## 10. 设置与账户

- 当前只要求登录、登录状态、账户信息、登出。
- 可复用 `/sapi/auth/login`、`/sapi/auth/login/phone`、`/sapi/auth/status` 及 `users`。
- 新前端应将 token 统一注入工作台 API 和旧接口适配器。
- 第一版不新增账户设置表、不做注册、找回密码或完整设置页。

## 11. 推荐后端边界

所有新代码只创建在：

```text
bondsense-workbench/backend/
  routers/        # 新 /api/workbench/*
  adapters/       # 调用旧 /sapi/* 或复用稳定服务
  repositories/   # 新工作台表
  migrations/     # 新表迁移 SQL
  services/       # 聚合、任务、SSE 持久化
```

禁止：修改旧 `backend/app.py`、旧路由、旧表结构语义或旧前端。新服务应通过配置获得旧后端地址，例如 `LEGACY_API_BASE_URL`；避免重复启动旧应用中的 FAISS 和策略后台服务。

## 12. 后端实施优先级

### 第一批：真实工作台基础闭环

1. 新后端脚手架、配置、健康检查、统一错误格式。
2. 认证适配。
3. 普通会话与消息持久化，代理旧 `/sapi/chat` SSE。
4. 项目、项目内会话、侧栏聚合接口。

验收：登录后可创建普通/项目会话；刷新后消息和侧栏历史仍存在；项目内与全局最近会话正确区分。

### 第二批：复用最成熟的策略工作流

1. 接入旧 AI 策略会话列表和详情。
2. 接入草稿创建、编辑、确认、生成、回测结果。
3. 增加工作台任务聚合与项目关联。

### 第三批：数据浏览能力

1. 因子列表、关注、详情时间线和新闻联动。
2. 宏观元数据、单指标与对比模式。
3. 首页基础行情和关注列表。

### 第四批：新增任务工作流

1. 新闻总结任务与文档。
2. 研报生成任务与文档。
3. 统一 Computer 筛选、归档、未读、计划。

## 13. 开发前仍需确认的事项

- 实际数据库中因子、宏观指标、收益率和行情字段是否齐全；目前只完成代码与文档审计，未直接查询生产数据。
- 新工作台后端是否与旧后端同进程部署，还是独立端口部署；推荐独立端口和 HTTP 适配。
- 普通对话的 LLM 成本、超时、取消和失败重试策略。
- 项目记忆何时自动候选、何时必须用户确认；第一版只做用户确认。
- 新闻总结和研报生成是否需要真正的异步队列；第一版应先实现可追踪任务，再评估调度。
